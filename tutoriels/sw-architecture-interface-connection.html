Objectifs du tutoriel

Snowflake offre un maillage technique dense et diversifié : pour interroger, administrer, ingérer ou orchestrer des données via une multitude de points d’entrée.

Que l’on soit data engineer, analyste ou développeur d’applications, il est essentiel de maîtriser l’éventail des interfaces, clients, API, drivers et connecteurs qui permettent d’interagir avec la plateforme. De l’interface web Snowsight aux connexions JDBC/ODBC, en passant par les API RESTful, les bibliothèques Python (Snowpark) ou les connecteurs natifs vers les outils d’ETL et de BI, chaque outil répond à des besoins spécifiques : performance, automatisation, sécurité ou intégration.

Cet article a pour objectif de dresser un panorama complet de ces différentes briques. Nous explorerons comment elles s’articulent, quels sont leurs cas d’usage privilégiés, et comment choisir la bonne approche pour interagir efficacement avec Snowflake, quel que soit le contexte d’utilisation.

Snowsight

1. Qu’est‑ce que Snowsight ?

Snowsight est l’interface Web moderne de Snowflake.

Elle offre une expérience unifiée pour analyser, développer, administrer et collaborer dans Snowflake.

2. Principales fonctionnalités de Snowsight

A. Analyse & développement

  • Écrire et exécuter des requêtes SQL dans des Worksheets.
  • Exécuter du Snowpark Python directement dans l’interface.
  • Créer et exécuter des Notebooks pour des workflows ML de bout en bout.
  • Utiliser Snowflake Copilot pour l’assistance à l’analyse de données.
  • Développer des projets multi‑fichiers (SQL, Python).

B. Visualisation & Applications

  • Visualiser les résultats sous forme de graphiques.
  • Créer des dashboards interactifs.
  • Développer et exécuter des applications Streamlit directement dans Snowflake.
  • Développer et partager des Snowflake Native Apps.

C. Ingestion & Transformation

Snowsight permet de gérer et surveiller :

  • Snowpipe & Snowpipe Streaming
  • Connecteurs
  • Streams & Tasks
  • Pipelines de transformation

D. Monitoring & Administration

  • Suivi de l’historique des requêtes et de leurs performances.
  • Visualisation des graphes de tasks.
  • Monitoring des chargements de données.
  • Gestion des coûts via des vues dédiées.
  • Gestion des utilisateurs, rôles, warehouses, bases, etc.

E. Collaboration & Data Sharing

  • Explorer et partager des données via le Snowflake Marketplace.
  • Créer et gérer des listings.
  • Utiliser Universal Search pour explorer tout le data estate.
  • Accéder au Horizon Catalog pour découvrir et gouverner les données.

3. Navigation et organisation dans Snowsight

Workspaces

  • Organisation des projets SQL/Python/Notebooks.
  • Gestion par dossiers et partage.

Worksheets

  • Éditeur SQL/Python avec exécution, résultats, graphiques et historique.

Dashboards

  • Création de tableaux de bord interactifs basés sur les résultats de requêtes.

Universal Search

  • Recherche globale dans les objets Snowflake (tables, vues, apps, listings…).

4. Opérations critiques réalisables dans Snowsight

  • Gestion des warehouses (start/stop/resize).
  • Gestion des bases, schémas, tables, vues.
  • Gestion des rôles et utilisateurs.
  • Configuration des intégrations (cloud, sécurité, connecteurs).
  • Suivi des coûts et de l’utilisation.

Snowflake CLI

1. Snowflake CLI (nouvelle génération)

Snowflake CLI est l’outil moderne en ligne de commande pour interagir avec Snowflake.

Il est conçu pour les workflows DevOps, CI/CD, déploiement, et gestion d’objets.

Fonctionnalités clés

  • Gestion complète des ressources Snowflake :
    • Bases, schémas, tables
    • Warehouses
    • Intégrations
    • Snowpark Container Services
    • Snowflake Native Apps
  • Exécution de SQL
  • Automatisation des déploiements (IaC-like)
  • Support natif des projets multi-fichiers
  • Intégration avec Git et pipelines CI/CD

Cas d’usage

  • Déploiement d’objets Snowflake
  • Automatisation d’environnements (dev/test/prod)
  • Gestion d’applications Snowflake (Native Apps, Streamlit, containers)
  • Scripts DevOps

Points importants pour SnowPro Core

  • Snowflake CLI est le client recommandé pour les nouveaux projets.
  • Il va remplacer progressivement SnowSQL pour les usages avancés.
  • Il gère des fonctionnalités que SnowSQL ne supporte pas (Native Apps, containers…).
  • Il est orienté infrastructure-as-code.

2. SnowSQL (client historique)

SnowSQL est le client SQL en ligne de commande traditionnel de Snowflake.

Il reste largement utilisé, mais son rôle est plus limité que Snowflake CLI.

Fonctionnalités clés

  • Exécution de requêtes SQL
  • Chargement/déchargement de données (COPY INTO)
  • Gestion basique des objets Snowflake
  • Support des scripts SQL
  • Connexion via profils configurés localement

Cas d’usage

  • Exécution SQL automatisée
  • Scripts simples
  • Chargement de données via COPY
  • Administration légère

Points importants pour SnowPro Core

  • SnowSQL est orienté SQL, pas DevOps.
  • Il ne gère pas :
    • Snowpark Container Services
    • Native Apps
    • Projets multi-fichiers
  • Il reste utile pour les pipelines ETL/ELT simples.

APIs natives

1. Snowflake Python API

La Snowflake Python API permet d’interagir avec Snowflake en Python, en utilisant des objets et méthodes haut niveau plutôt que du SQL brut.

Fonctionnalités clés

  • Créer, gérer et manipuler :
    • Bases, schémas, tables
    • Warehouses
    • Stages
    • Snowpark objects
  • Exécuter des requêtes SQL
  • Gérer les résultats sous forme de DataFrames Python
  • Intégration native avec Snowpark Python
  • Support des opérations administratives (création d’utilisateurs, rôles…)

Cas d’usage

  • Automatisation de workflows data
  • Développement d’applications Python connectées à Snowflake
  • Pipelines ML/ETL
  • Déploiement d’objets Snowflake via code

2. Snowflake REST API

La Snowflake REST API permet d’exécuter des requêtes SQL via des requêtes HTTP.

Elle est idéale pour les environnements où un driver ou un SDK n’est pas disponible.

Fonctionnalités clés

  • Exécuter des requêtes SQL via HTTP POST
  • Récupérer les résultats de manière asynchrone
  • Gérer les sessions et authentifications
  • Compatible avec :
    • OAuth
    • JWT
    • Clés privées
  • Permet d’intégrer Snowflake dans des systèmes externes (microservices, serveurs, outils custom)

Cas d’usage

  • Intégration avec des applications qui ne supportent pas JDBC/ODBC
  • Automatisation via des services serverless (AWS Lambda, Azure Functions…)
  • Exécution SQL depuis des environnements restreints
  • Communication entre Snowflake et des API internes

Drivers

JDBC Driver

Le driver JDBC Snowflake est un driver JDBC Type 4 permettant aux applications Java et aux outils compatibles JDBC d’accéder à Snowflake.

Le JDBC driver Snowflake fournit :

  • un driver Java Type 4 moderne, sécurisé et performant
  • plusieurs modes d'authentification (MFA, OAuth, Key Pair, SSO…)
  • des extensions avancées (asynchronous queries, file streaming)
  • une configuration fine ( paramètres de connexion, options réseau )
  • plusieurs formats de JAR (standard, thin, FIPS)
  • une compatibilité avec tout l’écosystème Java/JDBC

Il constitue la manière la plus complète et performante pour interagir avec Snowflake depuis des applications Java.

ODBC Driver

Le driver ODBC Snowflake permet aux applications ODBC (Power BI, Excel, Tableau, ETL, C/C++ custom, etc.) de se connecter à Snowflake via des DSN ou des connexions ODBC configurées manuellement.

Voici ce que Snowflake attend typiquement dans la certification :

  • Le driver ODBC est un driver natif utilisable via DSN (Windows/macOS/Linux)
  • GET et PUT sont supportés uniquement à partir d’une certaine version selon le cloud
    • AWS ≥ 2.17.5
    • Azure ≥ 2.20.2
    • GCP ≥ 2.21.5
  • Les paramètres requis : server, user (DSN minimal)
  • Le driver ne stocke jamais le mot de passe dans un DSN
  • Multi‑statements nécessitent la déclaration du nombre exact de requêtes
  • Threading : utiliser -pthread (Linux/macOS)
  • ODBC Driver Diagnostic Service est disponible
  • L'authentification supporte : native / SSO / OAuth / key-pair / MFA

Connecteurs natifs

Connecteur Kafka

Le Snowflake Connector for Kafka est un connecteur officiel qui lit en continu des messages depuis Apache Kafka et les charge dans Snowflake. C’est un composant clé du parcours ingestion continue / streaming de Snowflake.

Points cruciaux du connecteur Kafka :

  • Le Kafka Connector est un sink connector exécuté dans Kafka Connect.
  • Il lit des messages Kafka → les charge dans Snowflake (jamais l’inverse).
  • Deux modes : Snowpipe et Snowpipe Streaming.
  • Peut créer automatiquement les tables si non existantes.
  • Nécessite des privilèges :
    • DB/Schema: USAGE
    • Schema: CREATE TABLE, CREATE STAGE, CREATE PIPE
    • Table existante: OWNERSHIP
  • Recommandation Snowflake : user + role dédié.
  • Support Protobuf, JSON, Avro.
  • Fonctionne avec Kafka OSS ou Confluent Kafka.
  • Monitoring possible via JMX.

Connecteur Spark

Le Snowflake Connector for Spark permet d’intégrer Snowflake dans l’écosystème Apache Spark. Il permet à Spark de lire et écrire des données dans Snowflake, en traitant Snowflake comme une source de données Spark classique (comme JDBC, S3 ou HDFS).

Concepts essentiels :

  • Snowflake utilise des stages pour transférer des données.
  • Le connecteur repose sur JDBC + stages internes/externes.
  • Le pushdown optimise les performances en exécutant des opérations dans Snowflake.
  • Snowflake sépare compute (warehouses) et storage.
  • L'intégration Spark/Snowflake n’affecte pas la logique Snowflake (tables, micro-partitions, etc.).

Applications et outils tiers

1. Définition & Rôle de l’Ecosystème Snowflake

Snowflake fonctionne avec un très large ensemble d’outils et technologies, incluant :

  • Connecteurs & drivers (Snowflake et tiers)
  • Outils cloud et on‑premises
  • Langages de programmation
  • Outils d’intégration, BI, ML/AI
  • Partenaires certifiés

Snowflake met à disposition :

  • des clients officiels : CLI Snowflake, SnowSQL, connecteurs Python/Spark, drivers Node.js/JDBC/ODBC, etc. [docs.snowflake.com]

  • une liste d’outils partenaires et validés via Snowflake Partner Connect ou la Technology Validation Program.

Ces solutions sont organisées par catégories.

2. Catégories principales de l’écosystème

Selon la documentation, Snowflake regroupe les outils de l’écosystème en plusieurs familles : [docs.snowflake.com]

1. Data Integration (ETL / ELT)

Inclut tous les outils qui extraient, transforment et chargent dans Snowflake, comme :

  • Airbyte
  • AWS Glue
  • Azure Data Factory
  • Boomi
  • Artie
  • Ascend.io
  • … ainsi que tous les connecteurs supportant Snowflake en destination ou en source.

Ces outils fournissent connectivité native, souvent validée via le Snowflake Ready Technology Validation Program.

2. Business Intelligence (BI)

Outils courants :

  • Tableau
  • Power BI
  • Looker
  • Sigma
  • Mode Analytics (Mentionnés sur les pages de l’écosystème général.)

3. Machine Learning & Data Science

Snowflake s'intègre avec :

  • Python (connecteur natif)
  • Spark (via Snowflake Connector for Spark)
  • Outils ML externes (Databricks, DataRobot, etc.)
  • Connecteurs dédiés dans les outils d'ingestion ou de traitement.

4. Security, Governance & Observability

Outils de gouvernance / monitoring compatibles avec Snowflake.

5. SQL Development & Management

Outils permettant de développer SQL ou d’administrer Snowflake.

6. Native Programmatic Interfaces

Les interfaces Snowflake fournies directement :

  • SnowSQL (CLI)
  • Python Connector
  • Spark Connector
  • JDBC / ODBC drivers
  • Node.js driver [docs.snowflake.com]

3. 🔌 Applications & outils fournis par Snowflake

Les clients Snowflake officiels sont :

  • Snowflake CLI
  • SnowSQL (client en ligne de commande)
  • Connecteurs : Python, Spark
  • Drivers : Node.js, JDBC, ODBC [docs.snowflake.com]

Ces outils servent à automatiser, développer ou administrer Snowflake.

4. 🤝 Partenaires & Technologies certifiées

Snowflake dispose de :

  • Partenaires certifiés proposant des solutions cloud ou on‑premises pour se connecter à Snowflake (ETL, BI, ML, observabilité, etc.).
  • Un réseau étendu via Snowflake Partner Connect pour simplifier l’intégration.
  • Une validation officielle appelée Snowflake Ready Technology Validation Program, garantissant compatibilité et bonnes pratiques. [docs.snowflake.com], [docs.snowflake.com]

Cette certification garantit que les solutions tierces sont fiables pour une intégration Snowflake.
