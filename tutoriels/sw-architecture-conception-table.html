1. Principes généraux de conception des tables

La page "Table Design Considerations" présente les bonnes pratiques et directives essentielles pour structurer efficacement les tables Snowflake. Elle couvre les points suivants :

  • choix des types de données,
  • utilisation des contraintes,
  • implications pour les outils BI,
  • bonnes pratiques de modélisation.

Cette section est centrale pour l'examen SnowPro Core. [docs.snowflake.com]

2. Types de données : recommandations essentielles

Utiliser systématiquement des types DATE / TIMESTAMP

  • Snowflake recommande fortement d'utiliser DATE ou TIMESTAMP plutôt que VARCHAR pour stocker des dates.
  • Pourquoi ?
    • stockage plus efficace,
    • performances de requêtage améliorées. [docs.snowflake.com]

Choisir la granularité adéquate

Exemples :

  • DATE pour des données journalières,
  • TIMESTAMP_NTZ/LTZ/TZ pour des données incluant fuseaux horaires. [docs.snowflake.com]

3. Contraintes (Constraints) dans Snowflake

NOT NULL est la seule contrainte réellement enforcée sur les tables standard

  • Dans les tables standard, les contraintes PK/FK sont informational only → elles ne sont pas appliquées, mais stockées comme métadonnées. [docs.snowflake.com]

Les contraintes sont enforcées uniquement sur les Hybrid Tables

  • Les primary keys, unique keys et foreign keys y sont appliquées strictement. (Info mentionnée dans le contexte des contraintes.) [docs.snowflake.com]

Valeur des contraintes même non-enforcées

Elles restent très utiles car :

  • décrivent le modèle logique,
  • aident les équipes BI à comprendre les relations,
  • certains outils BI importent automatiquement les FKs et créent les jointures automatiquement,
  • certains moteurs BI peuvent exploiter les PK/FK pour optimiser les requêtes (ex : join elimination). [docs.snowflake.com]

Déclaration des contraintes

Utiliser :

CREATE TABLE ... CONSTRAINT ...

ALTER TABLE ... ADD CONSTRAINT ...

4. Bonnes pratiques pour la modélisation

Utiliser les PK/FK pour clarifier la structure

Même si elles ne sont pas enforcées, les déclarer :

  • améliore la qualité du modèle,
  • évite les erreurs dans les outils BI,
  • facilite le maintien des schémas. [docs.snowflake.com]

Utiliser GET_DDL pour documenter les tables

  • Snowflake permet de récupérer un DDL complet, incluant les contraintes existantes.
  • Utile pour documenter et versionner votre modèle. [docs.snowflake.com]
