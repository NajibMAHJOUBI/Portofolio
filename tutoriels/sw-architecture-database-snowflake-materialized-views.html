Snowflake - Materialized Views

Niveau Intermédiaire
Mis à jour: Février 2026 Durée: 15 min Difficulté: Intermédiaire
Snowflake Materialized Views Cloud

1. Définition

Une Materialized View est un ensemble de données pré‑calculé et stocké, dérivé d'une requête SQL définie dans la vue (SELECT). Contrairement aux vues standard, elle conserve physiquement les résultats. [docs.snowflake.com]

Objectif principal :

Accélérer les requêtes répétitives, coûteuses ou complexes grâce à l'utilisation de résultats déjà matérialisés.

2. Fonctionnement et avantages

A. Performances

  • Une materialized view est beaucoup plus rapide à interroger qu'une vue classique, puisque les résultats sont pré‑calculés. [docs.snowflake.com]
  • Idéale pour :
    • agrégations lourdes,
    • analyses de données semi‑structurées,
    • projections complexes,
    • grandes tables ou tables externes (moins performantes). [docs.snowflake.com]

B. Maintenance automatique

  • Snowflake met automatiquement la MV à jour après tout changement dans la table sous‑jacente. [docs.snowflake.com]
  • Si une requête arrive avant la fin de la mise à jour :
    • Snowflake combine les parties à jour et les données de base manquantes. [docs.snowflake.com]

C. Données toujours actuelles

Les données de la MV reflètent toujours les derniers changements, quelle que soit l'intensité du DML sur la table source. [docs.snowflake.com]

D. Caractéristiques spécifiques à Snowflake

  • Maintenance en tâche de fond.
  • Gestion transparente par le moteur Snowflake. [docs.snowflake.com]

3. Limitations et coûts

A. Édition requise

Les vues matérialisées nécessitent l'Enterprise Edition. [docs.snowflake.com]

B. Coûts

  • La matérialisation + la maintenance automatique consomment des crédits. [docs.snowflake.com]
  • Les résultats pré‑calculés nécessitent du stockage. [docs.snowflake.com]

C. Limitations à considérer

  • Peu adaptées si la table sous‑jacente change très fréquemment.
  • Les résultats matérialisés doivent être réutilisés suffisamment souvent pour compenser les coûts. [docs.snowflake.com]

4. Quand créer une Materialized View ?

Pertinente lorsque :

  • le résultat contient beaucoup moins de lignes/colonnes que la table source ;
  • la transformation est coûteuse (semi‑structuré, gros agrégats) ;
  • la table est en externe (S3, GCS) ;
  • la table source ne change pas trop fréquemment. [docs.snowflake.com]

5. Syntaxe – Création d'une Materialized View

Commande CREATE MATERIALIZED VIEW

[docs.snowflake.com] 
CREATE OR REPLACE MATERIALIZED VIEW sales_mv
AS
SELECT customer_id, SUM(amount) AS total_amount
FROM sales
GROUP BY customer_id;

Options importantes :

  • SECURE possible
  • CLUSTER BY pour optimiser l'accès
  • Masquage, policies, tags, row access policy disponibles [docs.snowflake.com]

6. Comparaison avec Views et Dynamic Tables

Source comparative : [docs.snowflake.com]

Objet Avantages Inconvénients
View Simple, pas de stockage Lent, exige du compute
Materialized View Rapide, pré‑calculée, auto‑maintenue Stockage + compute de maintenance
Dynamic Table Très flexible, transformations complexes Coûts de refresh, stockage, tuning nécessaire
