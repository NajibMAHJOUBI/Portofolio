✅ 1. Définition et rôle du Fail‑safe

Source :

Separate and distinct from Time Travel, Fail-safe ensures historical data is protected in the event of a system failure or security breach.
Fail-safe provides a (non-configurable) 7-day period during which historical data may be recoverable by Snowflake.

✔ Points essentiels :

  • Durée fixe : 7 jours, non configurable.
  • Commence immédiatement après la fin du Time Travel.
  • Sert uniquement en cas de défaillance système grave, non pour requêter des données anciennes.
  • Le Fail-safe est géré exclusivement par Snowflake.

✅ 2. Ce que Fail‑safe n'est PAS

Fail-safe is not provided as a means for accessing historical data after the Time Travel retention period has ended.

❌ Vous ne pouvez PAS :

  • Faire des requêtes SQL sur des données en Fail-safe.
  • Restaurer vous‑même une table depuis Fail-safe.
  • Utiliser Fail-safe comme alternative à Time Travel.

Il ne s'agit pas d'une fonctionnalité utilisateur mais d'un service de récupération interne.

✅ 3. Quand Fail‑safe est‑il utilisé ?

Fail-safe is intended only for use when all other recovery options have been attempted.

Cas typiques :

  • Défaillance profonde d'infrastructure.
  • Corruption de micro‑partitions côté Snowflake.
  • Scénarios rares de sécurité / brèche.
Data recovery via Fail-safe peut nécessiter :

several hours to several days.

✅ 4. Interaction Time Travel → Fail‑safe

Le cycle de vie des données est :

Data active → Time Travel (1‑90 jours) → Fail‑safe (7 jours) → purge définitive

Fail-safe period starts when Time Travel retention expires.
Important SnowPro :

A long-running Time Travel query will delay moving data into Fail-safe until the query completes.

✅ 5. Stockage Fail‑safe & visibilité

Snowflake affiche la quantité de données présentes en Fail-safe :

You can view the historical data storage in Fail-safe (ACCOUNTADMIN only).
  • Snowsight › Admin › Cost management › Consumption › Storage.
  • Les types de stockage sont visibles via les barres colorées (Storage Breakdown).

✅ 6. Facturation Fail‑safe

Fail-safe uses Snowflake-managed serverless compute. Standard serverless compute billing applies.

Il ne s'agit pas d'un service gratuit : des crédits sont consommés lors d'opérations de récupération effectuées par Snowflake.

Pour vérifier les coûts :

  • METERING_DAILY_HISTORY
  • METERING_HISTORY
  • Filtrer par : service_type = 'FAILSAFE_RECOVERY'

✅ 7. Limitations (important pour l'examen)

❌ Fail-safe et Snowpipe Streaming Classic

Fail-safe doesn't support tables that contain data ingested by Snowpipe Streaming Classic.

⚠️ Une récupération Fail-safe sur ces tables échouera complètement.

✅ 9. Points clés à mémoriser pour SnowPro Core

✔ Fail-safe = 7 jours → non configurable.

✔ Accessible uniquement par Snowflake (service interne).

✔ Pas un mécanisme de requête, contrairement au Time Travel.

✔ Commence après expiration du Time Travel.

✔ Rétention Fail-safe visible dans Snowsight.

✔ La récupération Fail-safe peut prendre plusieurs heures/jours.

✔ Incompatible avec Snowpipe Streaming Classic.
