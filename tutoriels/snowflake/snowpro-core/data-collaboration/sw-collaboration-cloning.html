Snowflake - Zero-Copy Cloning

Niveau Intermédiaire
Mis à jour: Février 2026 Durée: 20 min Difficulté: Intermédiaire
Snowflake Zero-Copy Cloning Time Travel

1. Qu'est‑ce que le Zero‑Copy Cloning ?

CREATE … CLONE creates a copy of an existing object… primarily used for zero‑copy clones of databases, schemas, and tables.

✔ Points clés :

  • Aucun stockage supplémentaire au moment du clonage.
  • Le clone partage les micro‑partitions avec l'objet source.
  • Le stockage supplémentaire n'est consommé que lorsque l'un des deux objets est modifié (copy-on-write).
  • Le clone est instantané et peut être utilisé pour dev/test, sandbox, analyses, "point‑in‑time copy".

2. Objets clonables

✔ Objets principaux (zero‑copy)

  • Databases
  • Schemas
  • Tables (y compris tables dynamiques, event tables, Iceberg tables)

✔ Autres objets de schéma clonables

You can also clone external stages, file formats, sequences, database roles, alerts, streams, tasks, etc.
  • FILE FORMAT
  • SEQUENCE
  • STAGE
  • STREAM
  • TASK
  • ALERT
  • DATABASE ROLE

3. Syntaxe essentielle (SnowPro Must‑Know)

A) Cloner une base / un schéma

CREATE DATABASE my_clone CLONE my_db;

ou avec Time Travel :

CREATE DATABASE my_clone CLONE my_db
    AT (TIMESTAMP => '2025-01-01 12:00:00');

B) Cloner une table

CREATE TABLE t_clone CLONE my_table;

C) Cloner en "point‑in‑time"

Snowflake supporte :

  • TIMESTAMP => <timestamp>
  • OFFSET => <interval>
  • STATEMENT => <query_id>

D) Paramètres Time Travel utiles

  • IGNORE TABLES WITH INSUFFICIENT DATA RETENTION
  • IGNORE HYBRID TABLES

4. Clonage et Time Travel

CLONE supports an AT | BEFORE clause for cloning using Time Travel for databases, schemas, and non‑temporary tables.
❗ Important :
  • Les tables temporaires ne peuvent pas être clonées avec Time Travel.
  • Les données purgées (ex : transient tables avec 1 jour de rétention) peuvent être ignorées via IGNORE TABLES WITH INSUFFICIENT DATA RETENTION.

5. Comportement des privilèges (point très testé SnowPro)

The clone inherits privileges of child objects, but not the privileges granted on the container itself.

✔ Résumé :

  • Pour bases & schémas :
    • Les objets internes (tables, views…) conservent leurs privilèges d'origine (sur les clones respectifs).
    • Le schéma / la base clonée elle‑même n'hérite PAS des privilèges du conteneur source.
  • Pour les autres objets :
    • Par défaut, les privilèges ne sont pas copiés.
    • Si l'objet supporte la clause COPY GRANTS : les privilèges (sauf OWNERSHIP) peuvent être copiés.

Exemple : CREATE TABLE … CLONE … COPY GRANTS

6. Considérations de clonage (au sens large)

  • DDL/DML et Time Travel : DDL/DML transactions, Time Travel, and retention periods can affect the object clone.
  • Object parameters : Les paramètres explicitement définis sur un objet sont hérités par le clone.
  • Séquences et valeurs par défaut : A cloned table referencing a sequence may reference the cloned sequence or the source sequence depending on scope.
  • Managed access schemas : Le clonage d'un schéma en "managed access" a des exigences de privilèges particulières.

7. Cas particuliers / objets qui ne sont pas clonés identiquement

Bien que non explicitement listé ici, la documentation précise des exceptions :

  • Certains objets comme les pipes donnent OWNERSHIP au rôle créateur lors du clonage.

8. Bénéfices du clonage Snowflake (pour SnowPro)

  • Création instantanée (aucune copie physique initiale).
  • Environnements dev/test isolés sans surcoût majeur.
  • Réduction des coûts de stockage (copy‑on‑write).
  • Reconstruction d'un état antérieur via Time Travel.
  • Possibilité de cloner au niveau base / schéma / table.

9. Exemples pratiques à retenir

Cloner un schéma entier

CREATE SCHEMA analytics_clone CLONE analytics;

Cloner un objet dans un état passé

CREATE TABLE orders_old CLONE orders
    BEFORE (STATEMENT => '01ae3b2b-0602-4ac2');

Cloner une Dynamic Table

CREATE DYNAMIC TABLE dt_clone
    CLONE my_dynamic_table
    TARGET_LAG = '5 minutes'
    WAREHOUSE = my_wh;

10. Questions potentielles à l'examen SnowPro

❓ Le clone consomme‑t‑il du stockage immédiatement ?

→ Non, uniquement lorsque des modifications surviennent (copy‑on‑write).

❓ Les privilèges du schéma source sont‑ils automatiquement transférés ?

→ Non, le schéma clone n'hérite pas des privilèges du schéma source. Les objets internes, oui.

❓ Peut‑on cloner via Time Travel ?

→ Oui, avec AT ou BEFORE.

❓ Peut‑on cloner un stage ou un file format ?

→ Oui.

❓ COPY GRANTS copie‑t‑il OWNERSHIP ?

→ Non.
