Snowflake Time Travel Data Recovery

✅ 1. Time Travel – Définition & objectifs

Snowflake Time Travel permet :

  • De consulter des données historiques (tables, schémas, bases) à un point du passé.
  • De restaurer des tables, schémas ou bases supprimés ou modifiés, dans les limites de la période de rétention.
  • De cloner un objet à un instant historique (Zero-Copy cloning + Time Travel).
Time Travel allows viewing and restoring historical data (tables, schemas, and databases) for a defined retention period.

✅ 2. Période de rétention Time Travel : DATA_RETENTION_TIME_IN_DAYS

La durée durant laquelle Snowflake conserve les versions historiques est contrôlée par le paramètre :

DATA_RETENTION_TIME_IN_DAYS
Data retention is based on the number of days Snowflake retains historical data for Time Travel.

✔ Valeurs :

  • Standard Edition → jusqu'à 1 jour.
  • Enterprise & supérieures → jusqu'à 90 jours.
  • Peut être défini au niveau compte, base, schéma, table.
Impact :
  • Plus la rétention est longue → plus la fonctionnalité Time Travel couvre un historique large.
  • La rétention s'applique aussi aux objets supprimés (possibilité de restauration).

✅ 3. Interroger des données historiques

Snowflake permet d'interroger des données anciennes via les clauses :

✔ AT

Pour une date/heure exacte.

✔ BEFORE

Pour interroger avant un événement (timestamp, statement ID, offset).

The AT | BEFORE clause accepts TIMESTAMP, OFFSET, or STATEMENT to query historical data.

✔ Exemples :

A) Interroger une table comme elle était à un timestamp

SELECT * FROM sales
AT (TIMESTAMP => '2026-03-01 12:00:00');

B) Utiliser un offset (ex : 5 heures dans le passé)

SELECT * FROM sales
BEFORE (OFFSET => -56060);

C) Restaurer une vue d'un statement précédent

SELECT * FROM sales BEFORE (STATEMENT => '01ad…');

✅ 4. Restaurer des objets (UNDELETE)

Time Travel permet de restaurer plusieurs types d'objets pendant la rétention :

  • Tables
  • Schémas
  • Bases
Time Travel supports restoring dropped tables, schemas, and databases during the data retention period.

✔ Commandes typiques :

A) Restaurer une table supprimée

UNDROP TABLE my_table;

B) Restaurer un schéma

UNDROP SCHEMA my_schema;

C) Restaurer une base

UNDROP DATABASE my_db;

D) Restaurer l'état passé d'un objet via un clone Time Travel

CREATE TABLE my_table_restored CLONE my_table
AT (TIMESTAMP => '2026-03-01 12:00:00');

✅ 5. Time Travel + Cloning

Snowflake combine Time Travel et Zero-Copy Cloning pour permettre :

  • Le clonage d'un objet à un instant historique, même s'il est supprimé.
  • Des environnements dev/test sur des états passés.
CREATE … CLONE supports AT | BEFORE to clone using Time Travel for databases, schemas, and tables.

✅ 6. Limitations importantes

  • ❌ Tables TEMPORARY et EXTERNAL ne supportent pas Time Travel. (Confirmé implicitement dans CREATE TABLE / CLONE restrictions.)
  • ❌ Les données purgées du Time Travel sont perdues. Même avec l'UNDROP, si la période DATA_RETENTION_TIME_IN_DAYS est dépassée → impossible de restaurer.
  • ❌ Rétention limitée selon l'édition. Examen SnowPro : très souvent testé.
