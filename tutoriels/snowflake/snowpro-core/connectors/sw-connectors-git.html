✅ 1. Introduction : Git dans Snowflake

Source : Using a Git repository in Snowflake

Snowflake permet d'intégrer un dépôt Git distant (GitHub, GitLab, etc.) et de synchroniser son contenu dans un Git repository clone dans Snowflake.

Ce clone constitue une copie locale complète : branches, tags, commits.

Avec cette intégration, vous pouvez :

  • Consommer des fichiers Git comme du code exécuté dans Snowflake (procédures, UDF handlers…).
  • Naviguer dans les branches, tags, fichiers.
  • Exécuter des fichiers .sql ou .py.
  • Pousser des commits depuis Snowflake (uniquement Workspaces, Streamlit, Notebooks).

✅ 2. Fonctionnement général

✔ Git Repository Clone Snowflake

  • Copie locale complète d'un dépôt Git : branches, tags, commits.
  • Accès aux fichiers comme s'ils étaient dans un stage Snowflake.
  • Snowflake peut fetch les dernières modifications du dépôt externe.

✔ Synchronisation (FETCH)

  • Snowflake met à jour le clone via ALTER GIT REPOSITORY <repo> FETCH.
  • Récupère nouveaux commits et nettoie les éléments supprimés du remote.

✅ 3. Mise en place : Setup Git dans Snowflake

Source : Setting up Snowflake to use Git

✔ Méthodes d'accès pour le dépôt Git

Snowflake supporte plusieurs types d'authentification :

  • Aucune authentification (dépôts publics).
  • Authentification par token (PAT GitHub, token GitLab), via un objet SECRET Snowflake.
  • OAuth2 (notamment avec Workspaces).
  • Accès réseau public ou PrivateLink selon la politique réseau.

✔ Étapes de configuration typiques

  1. Créer un SECRET stockant credentials Git (si nécessaire).
  2. Créer une API INTEGRATION pour autoriser Snowflake à appeler l'API Git (git_https_api).
  3. Créer l'objet GIT REPOSITORY qui clone le dépôt distant.

✅ 4. SQL Commands – Git dans Snowflake

Source : Git operations in Snowflake

🧩 4.1 CREATE GIT REPOSITORY

Crée l'objet Git Repository (clone Snowflake).

Permet de définir :

  • Le remote origin URL
  • L'API Integration à utiliser
  • Le secret pour authentification si nécessaire

🧩 4.2 ALTER GIT REPOSITORY FETCH

Met à jour le clone local depuis le dépôt distant.

ALTER GIT REPOSITORY my_repo FETCH;

🧩 4.3 SHOW GIT BRANCHES

Liste toutes les branches disponibles dans le clone.

SHOW GIT BRANCHES IN my_repo;

🧩 4.4 SHOW GIT TAGS

Affiche tous les tags.

🧩 4.5 DESCRIBE GIT REPOSITORY

Affiche les propriétés du repository clone.

Exemples de colonnes affichées :

  • created_on
  • origin
  • api_integration
  • git_credentials

🧩 4.6 SHOW GIT REPOSITORIES

Liste tous les Git Repositories dans la base.

✅ 5. Fichiers Git utilisables dans Snowflake

Depuis le Git Repository clone, Snowflake permet :

  • De référencer un fichier comme handler d'une procédure ou UDF
  • D'exécuter directement un script .sql ou .py
  • D'utiliser des fichiers provenant d'une branche spécifique

✅ 6. Privilèges et sécurité

  • Les opérations Git requièrent des privilèges spécifiques, par exemple OWNERSHIP pour DESCRIBE GIT REPOSITORY.
  • API_ALLOWED_PREFIXES dans l'API Integration limite les URLs Git accessibles.
  • Les secrets permettent de stocker les tokens Git de façon sécurisée.
