Snowflake Cost Management Budgets

1. Controlling Cost (Contrôle des coûts)

Snowflake propose plusieurs mécanismes pour éviter les dépassements de crédit et contrôler la consommation.

✔ 1.1. Budgets

Les budgets permettent de définir une limite mensuelle de crédit appliquée :

  • à l'ensemble du compte,
  • ou à un groupe d'objets (custom budgets).

Fonctionnalités essentielles :

  • Surveillance du crédit consommé par warehouses et fonctionnalités serverless.
  • Alertes si la consommation risque de dépasser la limite.
  • Notifications configurables : email, SNS, Event Grid, Pub/Sub, webhook (Slack, Teams…).

✔ 1.2. Resource Monitors

Les resource monitors permettent de définir des quotas de crédits pour les warehouses, avec :

  • Notification par email à certains seuils (jusqu'à 5 seuils),
  • Suspension automatique d'un warehouse lorsque le seuil est atteint,
  • Suspension immédiate (abort des requêtes en cours) si configuré.
Ils servent uniquement pour les warehouses gérés par l'utilisateur (pas le serverless).

✔ 1.3. Cost Controls for Warehouses (Best Practices)

Snowflake fournit des bonnes pratiques pour réduire les coûts des warehouses :

  • Utiliser AUTO-SUSPEND et AUTO-RESUME,
  • Dimensionner correctement les warehouses,
  • Éviter les exécutions prolongées ou inutiles.

2. Resource Monitors – Détail (Working with Resource Monitors)

✔ 2.1 Objectif des Resource Monitors

Ils permettent de :

  • suivre la consommation des crédits,
  • agir automatiquement pour éviter les dérives (notifications, suspension).

✔ 2.2 Actions possibles

Lorsqu'un seuil est atteint :

  • Notification par email,
  • Suspendre le warehouse après la fin des requêtes,
  • Suspendre immédiatement + abort des requêtes.

✔ 2.3 Configuration

Paramètres requis :

  • Nom du monitor,
  • Quota de crédits,
  • Type : Account ou Warehouse,
  • Warehouses associés (si mode Warehouse),
  • Schedule (daily / monthly / yearly / never),
  • Actions à exécuter aux seuils.

3. Budgets – Détail (user-guide/budgets & cost)

Les budgets permettent de mesurer et alerter le dépassement potentiel de crédits, mais leur utilisation a elle-même un coût.

✔ 3.1 Coûts liés aux Budgets

Deux types de coûts :

1. Compute Costs

  • Snowflake exécute des tâches serverless comme _MEASUREMENT_TASK et _BACKFILL_TASK,
  • Ces tâches consomment des crédits.

2. Storage Costs

  • Le stockage du metadata des budgets dans plusieurs tables internes (ex. _CONFIGURATION_TABLE, _MEASUREMENT_TABLE…).

4. Cost Controlling Controls (Cost Controls)

Les "cost controls" sont des outils permettant d'éviter des dépenses involontaires.

✔ Resource Monitors

→ Contrôle des warehouses, suspension automatique.

✔ Budgets

→ Définition d'un plafond mensuel, alertes proactives.

✔ Best Practices pour les Warehouses

→ Auto-suspend, tailles adaptées, monitoring des requêtes.

5. Points clés à retenir pour la certification SnowPro Core

⭐ BUDGETS

  • Limites mensuelles, notifications, monitorent warehouses + serverless features.
  • Peuvent envoyer des alertes via email, SNS, Pub/Sub, webhooks.
  • Le système de budgets consomme des crédits et de la storage.

⭐ RESOURCE MONITORS

  • Limitent la consommation des warehouses seulement.
  • Seuils configurables (jusqu'à 5).
  • Peuvent suspendre automatiquement un warehouse.

⭐ COST CONTROLS FOR WAREHOUSES

  • Auto-suspend indispensable.
  • Right-sizing des warehouses.

⭐ CHOIX ENTRE BUDGETS & RESOURCE MONITORS

  • Budgets = global + serverless + objets variés (plus large).
  • Resource monitors = warehouses uniquement.
  • → Les deux sont complémentaires.
