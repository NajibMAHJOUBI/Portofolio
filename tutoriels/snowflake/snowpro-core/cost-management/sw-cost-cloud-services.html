Snowflake Cloud Services Cost Management

1. Qu'est‑ce que le Cloud Services Compute ?

Le Cloud Services layer est une couche de l'architecture Snowflake qui orchestre toutes les opérations nécessaires pour exécuter, optimiser, et sécuriser les requêtes :

  • Authentification & gestion des sessions
  • Metadata management
  • Optimisation & compilation des requêtes
  • Access control
  • Gestion des transactions
  • Coordination avec les warehouses
Snowflake indique que ce sont des compute resources gérées intégralement par Snowflake.

2. Comment Snowflake facture Cloud Services ?

C'est l'un des points clés à connaître pour SnowPro Core.

✔ 2.1. Principe général

Le Cloud Services consomme des Snowflake credits, tout comme un warehouse classique.

MAIS Snowflake applique une règle spécifique :

Les crédits Cloud Services ne sont facturés que si leur consommation quotidienne dépasse 10 % de la consommation quotidienne des warehouses.

Cela signifie :

  • Tant que Cloud Services Usage ≤ 10 % de l'usage warehouse → 0 crédit facturé
  • La partie au‑delà de 10 % → crédits facturés
Points importants :
  • Le calcul est effectué quotidiennement (UTC).
  • Le serverless compute n'entre pas dans le calcul des 10 %.
  • L'ajustement mensuel est la somme des ajustements quotidiens.

4. Que consomme des Cloud Services credits ?

Selon la documentation Snowflake, le Cloud Services layer couvre :

  • authentification des utilisateurs
  • traitement des métadonnées
  • analyse et planification des requêtes
  • accès aux données
  • gestion de l'état global (distributed metadata store)
  • services transverses (caching, coordination des warehouses)

Pour SnowPro Core : l'essentiel est de retenir que Cloud Services = "overhead de gestion et d'orchestration Snowflake".

6. Pourquoi cette règle des 10 % ?

Snowflake explique que :

  • Le Cloud Services sert au fonctionnement global de la plateforme.
  • Il est normalement minoritaire par rapport aux warehouses.
  • Cette règle évite une facturation excessive en offrant un "crédit" quotidien équivalent à 10 % de l'usage warehouses.

Cette politique est un point fondamental à connaître pour l'examen.

7. Cas où des charges Cloud Services apparaissent

On peut s'attendre à voir du Cloud Services facturé si :

  • Très faible usage warehouse mais forte activité metadata
  • Fort usage de requêtes DDL / SHOW / INFORMATION_SCHEMA
  • Nombreux utilisateurs concurrents se connectant / se déconnectant
  • Usage lourd de catalogues / introspection d'objets
  • Organisation complexe avec beaucoup d'opérations administratives
Principe à retenir : Pas de facturation si ces usages ne dépassent pas 10% de la consommation warehouse quotidienne.

8. Points clés SnowPro Core à mémoriser

✔ Cloud Services fait partie du compute

→ donc consommateur de credits.

✔ Règle de facturation

Cloud Services Credits > 10 % des Warehouse Credits (par jour)

✔ Calcul effectué par jour (UTC)

La facturation Cloud Services réinitialise chaque jour.

✔ Serverless non inclus

Le serverless compute ne compte pas dans le calcul des 10 %.

✔ Cloud Services inclut

authentification, metadata, optimisation de requêtes, orchestration interne

✔ Géré par Snowflake

Le Cloud Services layer est entièrement géré par Snowflake → l'utilisateur ne peut pas le dimensionner.

📌 Résumé express (1 minute)

  • Snowflake facture le compute selon Warehouses + Serverless + Cloud Services.
  • Cloud Services = compute administratif de Snowflake.
  • Chaque jour, Snowflake compare : crédits Cloud Services et 10 % des crédits Warehouse.
  • Pas de facturation si Cloud Services ≤ 10 % des Warehouse.
  • Facturation seulement pour la partie excédant ces 10 %.
