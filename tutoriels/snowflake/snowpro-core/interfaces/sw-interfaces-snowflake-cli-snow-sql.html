🧊 Présentation de la commande snow sql

Snowflake CLI fournit une commande puissante — snow sql — permettant d'exécuter des requêtes SQL, des fichiers SQL, des blocs Snowflake Scripting et des templates SQL avec variables.

Cette fonctionnalité est essentielle pour automatiser, tester, développer et intégrer Snowflake dans des pipelines CI/CD.

1. Exécuter une requête SQL ad‑hoc

Utiliser l'option -q (ou --query) :

snow sql -q "SELECT * FROM FOO;"

→ Exécute la requête immédiatement et affiche les résultats. [docs.snowflake.com]

2. Exécuter un fichier SQL

Utiliser l'option -f :

snow sql -f my_query.sql

→ Exécute tout le contenu du fichier. [docs.snowflake.com]

3. Exécuter plusieurs statements

snow sql supporte plusieurs instructions dans un même appel : 

snow sql -q "select 'a','b'; select 'c','d';"

→ Renvoie plusieurs jeux de résultats. [docs.snowflake.com]

4. Exécuter des blocs Snowflake Scripting

Snowflake CLI supporte Snowflake Scripting, mais attention au délimiteur $.

Exemple :

EXECUTE IMMEDIATE $
DECLARE radius_of_circle FLOAT;
area_of_circle FLOAT;
BEGIN
    radius_of_circle := 3;
    area_of_circle := pi() * radius_of_circle * radius_of_circle;
    RETURN area_of_circle;
END;
$;
⚠️ Attention : Certains systèmes interprètent $ comme PID → Solutions :
  • échapper les délimiteurs : \$\$
  • ou placer le bloc dans un fichier et utiliser -f [docs.snowflake.com]

5. Variables et templates SQL (Substitution côté client)

-D permet d'injecter des variables dans un template SQL :

Variables dans la requête :

SELECT * FROM <% database %>.logs

Commande d'exécution :

snow sql -q "select * from <% database %>.logs" -D "database=dev"

Résultat envoyé à Snowflake :

select * from dev.logs

✔ Snowflake recommande d'utiliser la syntaxe : <% variable_name %> plutôt que l'ancienne syntaxe SnowSQL &variable_name. [docs.snowflake.com]

6. Exécution via STDIN

--stdin permet d'exécuter une requête passée en pipe :

cat my.sql | snow sql -i

7. Options importantes de snow sql (à connaître pour l'examen)

Option Description
-q / --queryExécuter une requête ad-hoc
-f / --filenameExécuter un fichier SQL
-i / --stdinLire depuis STDIN
-D / --variableSubstitution de variables
--single-transactionEncapsule BEGIN/COMMIT autour des statements
--retain-commentsConserve les commentaires
--enable-templatingChoix du moteur de templating (LEGACY/STANDARD/JINJA/ALL/NONE)

8. Authentification & connexion (rappel CLI)

Toute commande snow sql accepte les paramètres :

--account,
--user,
--password,
--authenticator,
--private-key-file,
--role,
--warehouse, etc.

Cela permet d'exécuter des requêtes dans des environnements ou projets distincts.
