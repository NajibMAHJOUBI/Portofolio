🧊 Snowsight Notebooks & Warehouse Behavior

Les Snowsight Notebooks sont un environnement intégré dans Snowflake permettant de combiner SQL, Python et Markdown au sein d'un même document interactif. Ils sont de plus en plus utilisés dans les workflows analytiques et data science, et certaines questions de certification SnowPro Core portent sur leur fonctionnement, surtout leur relation aux virtual warehouses.

✅ 1. Snowsight Notebooks — Vue d'ensemble

Les notebooks permettent de :

  • développer des analyses SQL, Python ou hybrides dans une interface interactive ;
  • exécuter du code directement dans Snowflake sans outil externe ;
  • utiliser des environnements contrôlés par Snowflake ;
  • intégrer du texte explicatif (Markdown), du SQL et du Python dans un même espace.

✔ Fonctionnalités essentielles

  • exécution cellulaire ;
  • support Snowflake Python runtimes ;
  • interaction directe avec les tables Snowflake ;
  • visualisation intégrée des résultats.

✅ 2. Getting Started with Snowsight Notebooks

La documentation explique comment débuter avec les notebooks dans Snowsight :

✔ Pour créer un notebook :

  • ouvrir Snowsight ;
  • naviguer vers Projects & Notebooks ;
  • créer un nouveau notebook dans un projet.

✔ Exécution :

  • une cellule SQL s'exécute via un warehouse Snowflake ;
  • une cellule Python utilise Snowflake Python runtimes ;
  • les notebooks gèrent automatiquement les contextes nécessaires (role, warehouse, database, schema).

✔ Environnements supportés :

Les notebooks permettent :

  • l'utilisation de Snowflake Native Python ;
  • l'accès sécurisé aux données Snowflake ;
  • l'exécution orchestrée, interactive et reproductible.

✅ 3. Default Warehouse for Notebooks

Snowflake précise comment les notebooks utilisent un warehouse par défaut.

✔ Comportement clé :

  • Si un warehouse est déjà sélectionné dans la session Snowsight, il devient le default warehouse utilisé par le notebook.
  • Si aucun warehouse n'est sélectionné, Snowflake demande d'en choisir un au lancement du code SQL.
  • Le warehouse détermine la capacité de calcul pour toutes les cellules SQL du notebook.
Points importants pour SnowPro Core :
  • Le warehouse utilisé par un notebook peut être changé manuellement dans les paramètres du notebook.
  • Les cellules Python n'utilisent pas le warehouse, mais un runtime Python serverless géré par Snowflake.
  • Les warehouses doivent être en état running pour exécuter les cellules SQL.
  • Le coût est facturé en crédits Snowflake selon la taille du warehouse (comme pour toute autre requête).

🎯 4. Points clés pour la certification SnowPro Core

✔ Snowsight Notebooks :

  • Sont un environnement natif Snowflake mixant SQL / Python / Markdown.
  • Permettent une exécution interactive directement dans Snowflake.
  • Nécessitent des permissions identiques à celles de l'utilisateur (roles, database, schema, warehouse).

✔ Exécution SQL :

  • Requiert un virtual warehouse.
  • Le warehouse par défaut est le warehouse actuellement utilisé dans Snowsight.

✔ Exécution Python :

  • Se fait via un runtime Python Snowflake, pas via un warehouse compute.

✔ Coûts :

  • SQL = crédits warehouse
  • Python = compute serverless (selon configuration)

✔ Contexte :

  • Notebooks héritent : rôle actif, warehouse actif, DB/Schema actifs
  • Le contexte peut être modifié dans le notebook.

🧠 Résumé final (Ultra‑synthèse)

  • Les Snowsight Notebooks permettent d'exécuter SQL, Python et Markdown dans Snowflake.
  • Leur exécution SQL dépend d'un warehouse, choisi automatiquement selon celui actif dans Snowsight.
  • Ils sont utiles pour l'analyse, la data science et le prototypage.
  • Python s'exécute via un runtime Snowflake distinct du warehouse.
  • Les notebooks héritent du rôle, warehouse, DB et schema actifs.
