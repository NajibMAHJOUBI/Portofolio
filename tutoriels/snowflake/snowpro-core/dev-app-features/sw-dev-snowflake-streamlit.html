🧊 Streamlit in Snowflake

Les questions SnowPro Core peuvent porter sur :

  • ce qu'est Streamlit dans Snowflake,
  • son fonctionnement (compute, stockage, sécurité),
  • comment créer/déployer une app Streamlit,
  • les permissions nécessaires,
  • l'architecture d'exécution (warehouse vs container runtime).

✅ 1. Streamlit in Snowflake — Concepts clés

Selon Snowflake :

Streamlit est une librairie Python open‑source permettant de créer facilement des web apps data/ML.

✔ Objectif (dans Snowflake)

Streamlit in Snowflake permet de développer, déployer et partager des applications interactives directement dans le Data Cloud, sans déplacer les données ni le code vers une infrastructure externe.

✔ Avantages principaux

  • Snowflake gère le compute et le stockage des apps Streamlit.
  • Le code est stocké dans un objet Streamlit gouverné par RBAC.
  • Intégration native : Snowpark, UDFs, Stored Procedures, Native Apps.
  • Développement facile dans Snowsight (éditeur + preview côte‑à‑côte).

✔ Modes d'exécution

Deux runtimes disponibles :

  • Warehouse Runtime : exécute Python + SQL via un warehouse Snowflake.
  • Container Runtime (Preview) : exécute l'app dans un compute pool.

✅ 2. Architecture & Billing (Très important SnowPro Core)

✔ Compute utilisé

Selon la documentation :

  • Un warehouse Snowflake est requis pour exécuter l'application Streamlit et les requêtes SQL.
  • Le même warehouse exécute Streamlit + SQL queries.
  • La session reste active tant que la connexion WebSocket reste ouverte (~15 min après la dernière activité).

✔ Consommation de crédits

  • Tant qu'un utilisateur a l'onglet ouvert → warehouse actif → crédits consommés.
  • Fermer la page ou suspendre le warehouse → arrêt de consommation.

✅ 3. Prérequis & Permissions

Avant de créer une app, il faut que l'admin Snowflake configure les autorisations.

Privilèges nécessaires :

  • USAGE sur la database
  • USAGE, CREATE STREAMLIT sur le schema
  • USAGE sur le warehouse
  • USAGE sur le compute pool (uniquement pour container runtime)

✅ 4. Créer une application Streamlit (Snowsight UI)

Étapes décrites dans la documentation :

✔ Étape 1 – Créer une nouvelle app

Dans Snowsight :

  • Projects → Streamlit
  • + Streamlit App
  • Nommer l'app
  • Choisir database + schema
  • Sélectionner le runtime :
    • Run on warehouse → choisir un warehouse
    • Run on container (Preview) → choisir un compute pool
  • Créer l'application

Snowflake fournit automatiquement un template / code de démarrage.

✅ 5. Modifier & Exécuter des apps Streamlit

Via Snowsight :

  • Ouvrir l'app → Edit
  • L'éditeur comprend 3 panneaux :
    • Files (source Python)
    • Code Editor
    • Preview de l'app

✔ Exécution :

Cliquer sur Run pour rafraîchir l'application.

✔ Upload de fichiers (assets)

  • Taille max = 250 MB par fichier
  • Upload dans l'internal stage de l'app

🎯 6. Points clés SnowPro Core (à mémoriser absolument)

✔ Concept / Architecture

  • Streamlit in Snowflake = app Python hébergée comme un objet Snowflake.
  • Appelle Snowpark & SQL sans sortir du Data Cloud.

✔ Compute

  • Streamlit Runtime = 1 seul Warehouse sélectionné pour toute l'app.
  • (Compute pool uniquement en Container Runtime – Preview)
  • WebSocket → Warehouse actif tant que l'app est ouverte.

✔ Sécurité

  • Accès via RBAC → permissions sur DB/Schema/Warehouse.

✔ Déploiement

  • Création via Snowsight UI, SQL ou Snowflake CLI.
  • Template généré automatiquement si aucun fichier n'est fourni.

✔ Fichiers / stockage

  • Code et assets stockés dans l'internal stage du Streamlit object.

✔ Limitations

  • Multi‑file editing non supporté si l'app utilise ROOT_LOCATION.

🧠 Résumé express (10 secondes)

  • Streamlit in Snowflake = web apps Python hébergées nativement dans Snowflake.
  • Nécessite permissions sur DB/Schema/Warehouse.
  • App tourne sur un Warehouse unique, restant actif tant que la session Streamlit est ouverte.
  • Création simple via Snowsight, avec éditeur + preview intégrés.
  • Stockage du code + fichiers dans l'internal stage de l'app.
