1. Snowflake ML – Overview

Snowflake ML est la suite d'outils permettant :

✔ Construire ses propres modèles ML dans Snowflake

Snowflake ML inclut :

  • des classes de développement de modèles (basées sur des frameworks ML populaires),
  • un Feature Store,
  • un Model Registry pour suivre versions et artefacts,
  • des connecteurs vers frameworks,
  • des snapshots immuables pour la traçabilité ML.

✔ Exécuter du ML sans écrire de code (ML Functions)

Les ML Functions permettent de :

  • entraîner rapidement des modèles sur données structurées,
  • réaliser : forecasting, anomaly detection, classification, top insights.
Garanties Snowflake
  • Sécurité : les modèles tournent dans le périmètre Snowflake.
  • Data privacy : les données clients ne sont jamais utilisées pour entraîner les modèles d'autres utilisateurs.
  • Contrôle via RBAC.

2. ML Functions – Overview

Les ML Functions sont des fonctions SQL "clé en main" pour les non‑experts ML.

✔ Catégories principales

(A) Time-Series Functions

  • Forecasting : prédiction d'une métrique sur la base de séries temporelles.
  • Anomaly Detection : détection des valeurs atypiques.

(B) Autres fonctions analytiques

  • Classification : prédiction d'une classe.
  • Top Insights : identification automatique des dimensions ayant un impact significatif sur la métrique.

✔ Coûts et stockage

  • Chaque modèle entraîne un stockage de l'instance du modèle (visible dans ACCOUNT_USAGE.TABLES / STAGES mais sans DB/schema).
  • Les coûts dépendent : quantité de données, complexité, durée d'entraînement.
  • Pour réduire coûts : supprimer les modèles obsolètes.
Limitations importantes
  • AUTOCOMMIT doit être actif.
  • Incompatibilité : Snowpark session.call ne peut pas invoquer directement des modèles ML Functions → utiliser session.sql("CALL model!FORECAST(...)").

3. SQL DDL pour les modèles ML (CREATE MODEL, ALTER MODEL, DROP MODEL)

✔ CREATE MODEL

Permet d'entraîner un modèle ML à partir d'une source de données structurée :

CREATE MODEL my_model
    PREDICT (target_col)
    USING (
        SELECT * FROM my_table
    );

Effet : crée une instance de modèle ML stockée par Snowflake, accessible ensuite via model_name!METHOD(...) (ex: !FORECAST).

✔ ALTER MODEL

Utilisé pour :

  • ajouter un tag,
  • ajouter un commentaire,
  • gérer la rétention,
  • rafraîchir ou cloner une version.

✔ DROP MODEL

Supprime le modèle et libère les ressources associées (artefacts, stockage d'instance).

✔ Méthodes du modèle

Les modèles ML functions exposent des méthodes comme :

  • !FORECAST
  • !DETECT_ANOMALIES
  • !CLASSIFY

Appel direct :

CALL my_model!FORECAST(
    INPUT_DATA => (SELECT date, metric FROM ts_table)
);

4. Snowflake ML – Model Registry (Overview)

Le Model Registry est le composant dédié au cycle de vie des modèles.

✔ Objectifs du Model Registry

  • Gestion centralisée des versions de modèles
  • Stockage des artefacts (model objects, metadata)
  • Gouvernance & traçabilité (RBAC, lineage)
  • Support multi‑frameworks (Snowpark ML, modèles personnalisés)
  • Intégration MLOps : déploiement, suivi, audit

✔ Briques offertes par le Model Registry

Snowpark ML Overview décrit les composants inclus :

  • Model registry pour conserver version, état, artefacts.
  • Compatibilité avec les pipelines ML Snowflake.
  • Support pour le développement + déploiement dans Snowflake même.

✔ Flux type ML avec Model Registry

  • Entraîner un modèle avec Snowpark ML ou ML Functions
  • Enregistrer le modèle dans le Model Registry
  • Versionner et annoter
  • Déployer (UDF/UDTF/Stored Proc ou service)
  • Surveiller et réentraîner

Le Model Registry sert aussi d'ancrage pour la production ML dans Snowflake, en s'intégrant avec feature store, stages, UDFs, tasks et Snowpark.

🧊 5. Résumé final pour SnowPro Core

✔ Snowflake ML =

ML Functions (no‑code) + Snowpark ML (full ML) + Model Registry + MLOps.

✔ ML Functions =

  • Forecasting / Anomalies / Classification / Top Insights
  • Stockage → des objets d'instance dans account usage
  • Méthodes appelées via model!method

✔ DDL du modèle =

  • CREATE MODEL, ALTER MODEL, DROP MODEL
  • Appels via CALL model_name!METHOD(...)

✔ Model Registry =

Versioning, gouvernance, déploiement, traçabilité
