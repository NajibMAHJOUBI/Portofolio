🧊 Snowpark (Overview & Developer Guides)

Snowpark est un thème clé pour SnowPro Core, particulièrement dans les sections portant sur :

  • architecture du traitement de données dans Snowflake,
  • API Snowpark pour manipuler les DataFrames,
  • différences entre Snowpark et Spark Connector,
  • possibilités de développer pipelines / UDFs / UDTFs / Stored Procedures dans Snowflake.

Cette synthèse reprend les points essentiels à retenir.

✅ 1. Qu'est‑ce que Snowpark ? (Snowpark Overview)

Selon la documentation Snowflake :

Le Snowpark API fournit une librairie intuitive pour interroger et transformer des données à grande échelle dans Snowflake, sans déplacer les données hors de Snowflake.

✔ Objectif principal

Snowpark permet de développer du code (Python / Java / Scala) qui s'exécute à l'intérieur du moteur Snowflake, en profitant :

  • du compute Snowflake,
  • du pushdown automatique,
  • du modèle serverless / scalable.

L'application ne récupère pas les données localement : toutes les opérations sont poussées dans Snowflake.

✅ 2. Langages supportés et Developer Guides

La documentation liste trois Snowpark Developer Guides, selon les langages supportés :

Chaque guide couvre :

  • la configuration du développement,
  • la création d'une session Snowpark,
  • l'utilisation des DataFrames,
  • la création de UDF/UDTF/Stored Procedures,
  • les meilleures pratiques de performance.

✅ 3. Fonctionnalités clés de Snowpark

La documentation met en avant plusieurs points différenciants :

✔ a) Pushdown intégral vers Snowflake

Snowpark pousse toutes les opérations vers Snowflake, y compris les UDFs. Cela garantit performance et scalabilité, sans cluster externe.

✔ b) Aucun cluster externe requis

Toutes les opérations sont exécutées dans Snowflake. Aucun cluster Spark ou compute externe n'est nécessaire.

✔ c) API DataFrame unifiée

Snowpark fournit une API permettant :

  • de manipuler les données via DataFrame et Column objects ;
  • de générer du SQL via des constructeurs natifs du langage ;
  • tout en bénéficiant du type checking et de l'auto‑complétion.

✔ d) Intégration complète Snowflake

Snowpark permet de créer :

  • UDF,
  • UDTF,
  • Stored Procedures,
  • Data Pipelines orchestrés via Tasks,
  • ML models (notamment Snowpark Python).

✅ 4. Snowpark vs Spark Connector (bénéfices)

Selon la documentation :

Par rapport au Spark Connector, Snowpark offre :

  • un support natif pour manipuler les données dans Snowflake,
  • un pushdown systématique,
  • l'absence d'infrastructure Spark externe,
  • une simplification du code (pas de SQL string, utilisation d'API natives),
  • gestion automatique du scale & compute par Snowflake.

✅ 5. Principes de développement Snowpark (général)

D'après la documentation Snowpark Developer Guides :

✔ Créer une session

Tout code Snowpark commence par une session dans laquelle on configure :

  • le compte Snowflake,
  • l'utilisateur,
  • le rôle,
  • le warehouse,
  • la database + schema.

✔ Manipuler les données via DataFrames

Snowpark permet :

  • de charger des tables (session.table(...))
  • de créer des DataFrames (session.create_dataframe(...))
  • d'utiliser transformations : filter, select, groupBy, join, etc.
  • toutes les opérations sont compilées en SQL et exécutées dans Snowflake.

✔ UDF / UDTF / Stored Procedures

Snowpark permet de créer et déployer :

  • UDFs (User‑Defined Functions)
  • UDTFs (User‑Defined Table Functions)
  • Stored Procedures

pour encapsuler de la logique métier au sein du moteur Snowflake.

✅ 6. Possibilités Snowpark par langage

✔ Snowpark Python

  • Data engineering ETL/ELT
  • Snowpark pandas
  • Machine learning (training + inference avec UDFs)

✔ Snowpark Java / Scala

  • Pipelines backend
  • Transformations industrielles
  • Intégration avec applications JVM

🧠 Résumé final (point de révision rapide)

  • Snowpark est l'API Snowflake permettant d'exécuter du code (Python/Java/Scala) directement dans Snowflake.
  • Il utilise un pushdown complet, sans déplacer les données.
  • Les Developer Guides existent pour Java, Python, Scala.
  • Snowpark permet : DataFrames, UDF/UDTF, Stored Procedures, pipelines ML, automatisations.
  • Il remplace avantageusement Spark Connector dans la plupart des cas (pas de cluster, meilleures performances).
