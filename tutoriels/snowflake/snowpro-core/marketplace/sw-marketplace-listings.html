✅ 1. Que sont les Listings dans Snowflake ?

A listing is an enhanced method of Secure Data Sharing… providers can publish data or apps privately or on the Snowflake Marketplace.

Les listings permettent au provider :

  • De publier des données publiquement (Marketplace) ou privatement.
  • D'ajouter metadata enrichis : titre, description, queries exemples, informations provider.
  • De monétiser leur data product (Marketplace).
  • De suivre l'usage et l'intérêt (usage metrics).

Les consumers peuvent :

  • Accéder aux données via Marketplace ou via un partage privé.
  • Créer une database depuis le listing.

✅ 2. Les deux types principaux de listings

✔ 1. Marketplace Listings (public or private)

Permettent de partager avec tout compte Snowflake, dans toute région cloud.

Fonctionnalités clés :

  • Visibles sur le Snowflake Marketplace.
  • Possibilité de rendre le listing public.
  • Possibilité de facturer l'accès.
    Offer a share publicly… charge consumers… monitor usage.
  • Auto-fulfillment disponible (voir section 4).

✔ 2. Organizational Listings (Internal Marketplace)

Allow you to share data products securely within your organization.

Il s'agit d'un Marketplace interne qui centralise les data products uniquement pour les comptes d'une organisation Snowflake.

Différences clés :

  • Accessible uniquement dans l'organisation (Internal Marketplace).
  • Contrôlé via RBAC et account targeting.
  • Pas de visibilité publique.
  • Objectif : catalogue interne de données fiables.

Avantages :

  • Découverte plus simple des datasets internes.
  • Cohérence & gouvernance renforcée.
  • Multiples équipes peuvent publier / consommer.
Notes : Les providers créent/gèrent les listings via Snowsight (Provider Studio) ou API. Fonctionne dans les régions commerciales ; certaines options disponibles en régimes gouvernementaux (preview).

✅ 3. Structure d'un Listing : Data Product

Dans un listing, le data product représente soit :

  • un share Snowflake,
  • un Snowflake Native App.
A data product is the share or the app attached to a listing.

✅ 4. Cross-Cloud Auto-Fulfillment (Auto-réplication des listings)

Auto-fulfillment automatically replicates your data product to other Snowflake regions as needed.

✔ Pourquoi c'est important ?

  • Sans auto-fulfillment, un provider doit manuellement répliquer ses données dans les régions où se trouvent ses consumers → fastidieux, lent.
  • Avec auto-fulfillment :
    • Snowflake réplique automatiquement les données vers les régions cibles.
    • Le consumer accède au listing dans sa propre région, ce qui réduit la latence.
    • Fonctionne pour shares et application packages.

✔ Contraintes :

  • Pas disponible sur les comptes trial.
  • Le provider doit avoir activé le Global Data Sharing :
    SELECT SYSTEM$ENABLE_GLOBAL_DATA_SHARING_FOR_ACCOUNT('<account>');

✔ Cas d'utilisation :

  • Paid listings → auto-fulfillment obligatoire.
  • Private listings cross-region → auto-fulfillment activé automatiquement.
    Snowsight automatically detects whether the consumer is in another region and enables auto-fulfillment.

✔ Fonctionnement technique :

Snowflake crée et gère une Secure Share Area (SSA) pour stocker les données répliquées.
When auto-fulfillment is set up, Snowflake provisions a Secure Share Area and fulfills data to remote regions.

Impact sur les coûts : Les providers sont facturés selon l'utilisation réelle.
When you make a data product available in other regions, you incur additional costs.

✅ 6. Points clés à maîtriser pour SnowPro Core

✔ Un listing = version enrichie de Secure Data Sharing.

✔ Un data product = un share ou une application Snowflake Native.

✔ Marketplace listings : publics, privés, monétisables.

✔ Organizational listings : Internal Marketplace, sécurisation interne, RBAC.

✔ Auto-fulfillment : Snowflake réplique automatiquement les données dans d'autres régions.

✔ Auto-fulfillment obligatoire pour les paid listings.

✔ Non disponible pour trial accounts.

✔ Activé par ORGADMIN via SYSTEM$ENABLE_GLOBAL_DATA_SHARING_FOR_ACCOUNT.
