Snowflake Marketplace Listings

✅ 1. Snowflake Marketplace — Définition & objectifs

The Snowflake Marketplace is where you can explore, access, and provide listings to consumers… and discover third‑party data and services.

✔ Pour les consumers :

  • Accéder à des datasets tiers (internes ou externes).
  • Utiliser des données historiques, du streaming, des données d'identité, etc.
    Consumers can explore historical data, streaming data, identity data, and more.
  • Tester, intégrer ou enrichir leurs propres données Snowflake.

✔ Pour les providers :

  • Publier leurs data products à grande échelle.
    Publish curated offerings to many consumers simultaneously.
  • Éviter d'avoir à créer des pipelines/API de distribution de données.
    Eliminate costs of building and maintaining APIs and pipelines.
  • Proposer des paid listings (monétisation).
    With paid listings, you can also charge for your data products.
✔ Disponibilité
Disponible pour tous les comptes non‑VPS sur AWS, GCP, Azure (hors Azure Government).
Available globally to all non‑VPS accounts… except Azure Government.

✅ 2. Qu'est-ce qu'un Listing ?

A listing is an enhanced method of Secure Data Sharing… you can publish a Snowflake Native App or data.

Contenus possibles :

  • Shares (secure share)
  • Snowflake Native Apps

Chaque listing contient en plus :

  • métadonnées enrichies : titre, description, SQL sample…
    Provide metadata such as title, description, sample SQL, and provider info.
  • usage metrics (consultation, usage du data product)
  • modalité publique ou privée

✅ 3. Types de listings & modalités

✔ Private listing (listing ciblé)

Disponible uniquement pour des comptes spécifiques, dans n'importe quelle région Snowflake.

Private listings… available to specific consumers in any Snowflake region.

✔ Public listing (Marketplace)

Disponible sur le Marketplace et visible par l'ensemble des comptes.

✔ Free / Sample / Paid access

Consumers can access data products free, sample-based, or paid.

✅ 4. Provider Listings Workflows — Vue générale

4.1. Workflow global du provider

Le workflow standard d'un provider inclut :

  1. Créer un listing
  2. Définir le data product (share ou application package)
  3. Configurer la disponibilité régionale
  4. Configurer l'accès (private/public)
  5. Configurer auto‑fulfillment si nécessaire
  6. Publier le listing
  7. Gérer et mettre à jour le listing
  8. Unpublish / delete si besoin

Le Marketplace permet maintenant la gestion complète via Snowsight Provider Studio ou via API.

4.2. Publication d'un listing (Provider)

✔ Configuration initiale

Au moment de la création du listing, le provider doit compléter :

  • Titre
  • Description
  • Catégorie Marketplace
  • Conditions d'utilisation (Terms of Service)
You must complete additional fields before making your listing available… listing terms required.

✔ Choix de la disponibilité

  • All regions ou Custom regions
  • Les paid listings utilisent généralement Custom regions
    Paid listings are only available in supported regions.

4.3. Attacher un data product au listing

Un listing doit référencer un data product :

A data product is any share or application package attached to your listing.
⚠ Note :
  • Un share ne peut être attaché qu'à un seul listing.
  • Une application peut être attachée à plusieurs listings.

4.4. Auto‑Fulfillment (Cross‑Cloud Auto‑Fulfillment)

Automatically replicates your data product to other regions as needed.

✔ Pour quels listings ?

✔ Conditions

  • Non disponible sur comptes trial
    Auto-fulfillment isn't available on trial accounts.
  • Activation via ORGADMIN : SELECT SYSTEM$ENABLE_GLOBAL_DATA_SHARING_FOR_ACCOUNT('<account>');

✔ Fonctionnement technique

Snowflake provisionne automatiquement un Secure Share Area (SSA) et réplique les données.

Snowflake manages provisioning for a secure share area (SSA) and auto‑fulfillment to remote regions.

✔ Coûts

Le provider paie uniquement lorsqu'il existe une demande réelle.

You incur costs only when there is consumer demand in that region.

4.5. Gestion des listings (mise à jour, retrait, suppression)

Le provider peut :

  • Modifier les métadonnées (titre, description…)
  • Modifier les régions disponibles
  • Modifier les comptes cibles pour un private listing
  • Unpublish un listing (le retire du Marketplace)
  • Supprimer définitivement un listing

✅ 6. Points à retenir pour SnowPro Core

✔ Un listing est une version enrichie de Secure Data Sharing.

✔ Marketplace = pour toutes les régions cloud, y compris paid listings.

✔ Les organizational listings permettent un Internal Marketplace.

✔ Auto‑fulfillment = réplication automatique cross‑cloud → essentiel pour les paid listings.

✔ Le provider doit :

  • attacher un data product
  • configurer TOC (Terms of Service)
  • respecter les régions supportées
  • configurer la réplication automatique si nécessaire

✔ Les consumers créent des databases depuis les listings, comme avec le sharing classique.
