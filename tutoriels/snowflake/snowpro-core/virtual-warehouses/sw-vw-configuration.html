🧊 Synthèse SnowPro Core — Warehouse Tasks, CREATE/ALTER WAREHOUSE, Monitoring

Cette fiche couvre les éléments essentiels pour maîtriser les opérations sur les virtual warehouses, un thème fortement évalué en certification SnowPro Core.

✅ 1. Warehouse Tasks (Working with Warehouses)

La documentation décrit les opérations principales :

✔ Créer un warehouse

  • via Snowsight, SQL ou Python
  • peut être créé en Started ou Suspended
  • Si créé en "Started", il consomme des crédits dès que les ressources sont provisionnées

✔ Démarrer / reprendre un warehouse

ALTER WAREHOUSE <name> RESUME;
  • démarrage généralement en quelques secondes (mais peut prendre plus longtemps en cas de reprovisionnement)

✔ Suspension automatique et consommation

  • Warehouse consomme des crédits uniquement lorsqu'il est en cours d'exécution
  • Facturation = par seconde, avec un minimum de 60 secondes à chaque démarrage
  • Si des ressources échouent à se provisionner, Snowflake facture seulement les ressources provisionnées

✔ Exécution des requêtes

Snowflake n'exécute pas les requêtes tant que toutes les ressources ne sont pas provisionnées, sauf si certaines ressources échouent → démarrage partiel à ≥50%

✅ 2. CREATE WAREHOUSE — Syntaxe et options clés

Snowflake permet la création d'un warehouse via :

CREATE [ OR REPLACE ] WAREHOUSE [ IF NOT EXISTS ] <name>
    WITH
        WAREHOUSE_TYPE = STANDARD | 'SNOWPARK-OPTIMIZED'
        WAREHOUSE_SIZE = XSMALL | SMALL | MEDIUM | LARGE | ...
        GENERATION = '1' | '2'
        RESOURCE_CONSTRAINT = <constraint>
        MAX_CLUSTER_COUNT = <num>
        MIN_CLUSTER_COUNT = <num>
        SCALING_POLICY = STANDARD | ECONOMY
        AUTO_SUSPEND = <seconds> | NULL
        AUTO_RESUME = TRUE | FALSE
        INITIALLY_SUSPENDED = TRUE | FALSE
        RESOURCE_MONITOR = <monitor>
        ENABLE_QUERY_ACCELERATION = TRUE | FALSE
        QUERY_ACCELERATION_MAX_SCALE_FACTOR = <num>;

Points essentiels pour l'examen :
  • WAREHOUSE_TYPE : Standard ou Snowpark-Optimized
  • GENERATION : contrôle Gen1 / Gen2 pour les Standard warehouses
  • (MIN|MAX)_CLUSTER_COUNT : indispensable pour Multi‑Cluster Warehouse
  • SCALING_POLICY : Standard = performance, Economy = réduction coûts
  • AUTO_SUSPEND / AUTO_RESUME : très important pour la gestion des crédits
  • INITIALLY_SUSPENDED : permet de créer le warehouse sans coût initial

✅ 3. ALTER WAREHOUSE — Gestion & modification

Syntaxe principale :

✔ Suspendre ou reprendre

ALTER WAREHOUSE <name> SUSPEND;
ALTER WAREHOUSE <name> RESUME;

✔ Abandonner toutes les requêtes

ALTER WAREHOUSE <name> ABORT ALL QUERIES;

✔ Renommer

ALTER WAREHOUSE <name> RENAME TO new_name;

✔ Modifier les propriétés

Toutes les propriétés modifiables apparaissent dans la section SET :

  • WAREHOUSE_SIZE
  • MAX_CLUSTER_COUNT / MIN_CLUSTER_COUNT
  • SCALING_POLICY
  • AUTO_SUSPEND, AUTO_RESUME
  • RESOURCE_MONITOR
  • COMMENT
  • RESOURCE_CONSTRAINT, GENERATION, etc.

✔ Réinitialiser des propriétés (UNSET)

ALTER WAREHOUSE <name> UNSET AUTO_SUSPEND;

✔ Ajouter / retirer des tables dans un contexte de per‑table warehouses (fonctionnalité avancée)

ALTER WAREHOUSE <name> ADD TABLES (...);
ALTER WAREHOUSE <name> DROP TABLES (...);

✅ 4. Monitoring Warehouse Load

La documentation décrit comment Snowflake mesure et visualise la charge d'un warehouse.

✔ Accès au monitoring

  • Nécessite le privilège MONITOR sur le warehouse.
  • Dans Snowsight : Compute → Warehouses → <warehouse_name>

✔ Load Monitoring Chart

Affiche :

  • les requêtes Running
  • les requêtes Queued (Provisioning)
  • les requêtes Blocked
  • les requêtes Queued (Overload)

Fenêtres d'analyse : de 1 heure à 2 semaines, granularité automatique (1 minute à 1 jour)

✔ Calcul du query load

Snowflake calcule la charge : somme des temps d'exécution / durée totale de l'intervalle

Exemple donné (5 minutes = 300 sec) :

  • Load Running = 0.92
  • Load Queued = 0.08
  • Total load = 1.00

✔ Pour analyses plus avancées :

Utiliser ACCOUNT_USAGE.QUERY_HISTORY

🎯 5. Points clés SnowPro Core

Warehouse Tasks

  • Création possible en état Started → attention aux coûts
  • Warehouse exécute des requêtes seulement après provisionnement complet des ressources
  • Billing par seconde après un minimum de 60 secondes

CREATE WAREHOUSE

  • Paramètres cruciaux : type, taille, génération, multi-cluster, scaling policy
  • AUTO_SUSPEND & AUTO_RESUME = optimisation des crédits
  • standard vs snowpark-optimized : selon workload

ALTER WAREHOUSE

  • Peut suspendre, reprendre, renommer, changer taille/cluster
  • MAX/MIN_CLUSTER_COUNT = fonction multi-cluster
  • SCALING_POLICY = STANDARD ou ECONOMY

Monitoring Load

  • Connaître les 4 statuts : Running / Queued (Provisioning) / Queued (Overload) / Blocked
  • Interpréter le "Warehouse Load" (proche de 1 = limite de capacité)
  • Outil essentiel pour identifier la nécessité de Scaling Up vs Scaling Out
