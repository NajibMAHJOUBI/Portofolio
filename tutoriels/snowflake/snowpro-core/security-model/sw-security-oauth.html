✅ 1. Introduction à OAuth (OAuth Intro)

Source : [docs.snowflake.com]

Snowflake supporte OAuth 2.0 comme mécanisme d'authentification/autorisation via des security integrations.

✔ 1.1. Deux types d'OAuth supportés

  • Snowflake OAuth (OAuth interne Snowflake)
  • External OAuth (IdP / OAuth server externe) [docs.snowflake.com]
32 32 划

✔ 1.2. Fonctionnement général

  • Le client redirige vers une page d'autorisation.
  • Snowflake génère un access token (et optionnellement un refresh token). [docs.snowflake.com]

✔ 1.3. Audit OAuth

Lorsqu'un utilisateur s'authentifie en OAuth, la colonne FIRST_AUTHENTICATION_FACTOR = 'OAUTH_ACCESS_TOKEN' apparaît dans :

  • LOGIN_HISTORY
  • LOGIN_HISTORY_BY_USER [docs.snowflake.com]

✅ 2. Snowflake OAuth Overview

Source : [docs.snowflake.com]

Snowflake OAuth utilise le service OAuth natif de Snowflake comme authorization server et resource server.

✔ 2.1. Clients supportés

  • Tableau Desktop & Tableau Cloud
  • Looker
  • ThoughtSpot
  • Alation
  • Clients personnalisés [docs.snowflake.com]

✔ 2.2. OAuth Authorization Code Flow (Flow principal)

  1. L'utilisateur démarre la connexion OAuth.
  2. Snowflake affiche une page d'authentification + page de consentement pour choisir un rôle.
  3. Le client reçoit un authorization code.
  4. Le client échange ce code contre un access token (+ refresh token si activé).
  5. Le client envoie le token au Snowflake Resource Server.
  6. Snowflake ouvre une session avec le rôle lié au token. [docs.snowflake.com]

✔ 2.3. Rôles privilégiés bloqués par défaut

Les rôles suivants ne peuvent pas être utilisés avec OAuth sauf configuration explicite :

  • ACCOUNTADMIN
  • SECURITYADMIN
  • ORGADMIN
  • GLOBALORGADMIN [docs.snowflake.com]

Paramètre pour lever le blocage :

ALTER ACCOUNT SET OAUTH_ADD_PRIVILEGED_ROLES_TO_BLOCKED_LIST = FALSE;

✔ 2.4. Tokens

  • Access tokens : durée courte (~10 minutes).
  • Refresh tokens : permettent d'obtenir de nouveaux access tokens.
  • Single‑use refresh tokens disponibles pour réduire les risques de vol. [docs.snowflake.com]

✅ 3. Key‑pair Authentication & Rotation

Source : [docs.snowflake.com]

L'authentification par paire de clés est une alternative plus sécurisée que le mot de passe.

✔ 3.1. Principe général

  • L'utilisateur génère une paire RSA ≥ 2048 bits ou ECDSA (ES256/ES384/ES512).
  • Le public key est enregistré dans Snowflake via ALTER USER.
  • Le client signe un JWT avec la private key et Snowflake l'utilise pour l'authentifier. [docs.snowflake.com]

✔ 3.2. Avantages

  • Aucun mot de passe stocké.
  • Authentification forte.
  • Rotation des clés supportée nativement. [docs.snowflake.com]

✔ 3.3. Clients supportés pour key‑pair authentication

Tous les principaux drivers Snowflake supportent cette méthode :

  • SnowSQL, Snowflake CLI
  • Python, Spark, Kafka
  • JDBC, ODBC
  • Node.js, .NET, PHP, Go [docs.snowflake.com]

✔ 3.4. Bonnes pratiques

  • Générer des clés chiffrées (recommandation Snowflake).
  • Protéger la private key avec une passphrase.
  • Effectuer la rotation régulièrement. [docs.snowflake.com]

✅ 5. Points clés pour SnowPro Core

🔐 Snowflake OAuth

  • Authorization server intégré, adapté aux clients interactifs. [docs.snowflake.com]
  • Bloque les rôles privilégiés par défaut. [docs.snowflake.com]

🔐 External OAuth

  • Délégation complète à un serveur OAuth externe, idéal pour les systèmes distribués.

🔐 Key‑pair Auth

  • Méthode recommandée pour sécurité maximale dans les automations. [docs.snowflake.com]

🔐 Audit

  • Les audit logs OAuth apparaissent dans LOGIN_HISTORY. [docs.snowflake.com]
