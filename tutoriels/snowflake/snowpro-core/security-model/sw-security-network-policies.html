✅ 1. Network Policies

Source : [docs.snowflake.com]

Les Network Policies servent à restreindre l'accès réseau à votre compte Snowflake en contrôlant quelles adresses IP peuvent se connecter.

✔ Fonctionnement

Une Network Policy définit :

  • une liste allowed_ip_list (IP autorisées)
  • une liste blocked_ip_list (IP explicitement bloquées)

Une priorité : le blocage > l'autorisation

✔ Types d'application

  • Au niveau du compte → affecte tous les utilisateurs
  • Au niveau utilisateur → peut surcharger la règle du compte

Se configure via :

CREATE NETWORK POLICY my_policy
    ALLOWED_IP_LIST = ('x.x.x.x', 'y.y.y.y')
    BLOCKED_IP_LIST = ('z.z.z.z');
Bonnes pratiques (selon Snowflake Secure Guides) :
  • Restreindre l'accès via politiques réseau est un pilier de la sécurité Snowflake.
  • S'intègre avec RBAC, MFA et autres contrôles. [docs.snowflake.com]

✅ 2. Network Rules

Source : [docs.snowflake.com]

Les Network Rules sont utilisées dans les External Access Integrations, notamment pour autoriser Snowflake à contacter des endpoints externes (API externes, services cloud, etc.).

✔ Types de Network Rules

Elles définissent quelles adresses/IP/domaines Snowflake peut contacter pour :

  • External Functions
  • Remote Services
  • Outbound accesses maîtrisés

✔ Structure

Une Network Rule peut définir :

  • hostnames
  • port ranges
  • Protocols

✔ Exemple d'utilisation

Associer une network rule à une external access integration :

CREATE NETWORK RULE allow_ext_api
    TYPE = HOST_PORT
    VALUE_LIST = ('api.example.com:443');

CREATE EXTERNAL ACCESS INTEGRATION my_int
    NETWORK_RULES = (allow_ext_api)
    ENABLED = TRUE;
Objectif SnowPro Core : Comprendre que Network Rules = contrôle des connexions sortantes, alors que Network Policies = contrôle des connexions entrantes.

✅ 3. Secure Snowflake – Guides Overview

Source : [docs.snowflake.com]

Les guides "Secure" décrivent les fondamentaux de sécurité de Snowflake :

✔ Principes de sécurité Snowflake

  • Sécurité complète : opérations IA/ML et données protégées dans le périmètre Snowflake.
  • Gouvernance centralisée avec :
    • RBAC
    • Network Policies
    • Data Masking
    • Row Access Policies
    • Secure Views
    • External Tokenization
  • Confidentialité : aucune donnée client n'est utilisée pour entraîner des modèles partagés. [docs.snowflake.com]

✔ Composants clés à connaître pour l'examen

  • RBAC (database → schema → object privileges)
  • Encryption (always-on)
  • Time Travel & Fail-safe (protection et récupération)
  • Access control (policies, MFA, SSO)
  • Data protection (masking, secure objects)

✅ 4. LOGIN_HISTORY (ACCOUNT_USAGE)

Source : [docs.snowflake.com]

La vue ACCOUNT_USAGE.LOGIN_HISTORY permet d'auditer :

  • les connexions au compte
  • les succès / échecs
  • l'IP source
  • l'utilisateur
  • les timestamps
  • la méthode d'authentification (MFA, OAuth, SSO, etc.)

✔ Types d'informations exportées

Elle contient, entre autres :

  • EVENT_TIMESTAMP
  • USER_NAME
  • CLIENT_IP
  • REPORTED_CLIENT_TYPE
  • IS_SUCCESS
  • ERROR_MESSAGE

✔ Intérêt pour SnowPro Core

Requêtes d'audit :

SELECT *
FROM SNOWFLAKE.ACCOUNT_USAGE.LOGIN_HISTORY
ORDER BY EVENT_TIMESTAMP DESC;

Utilisée pour :

  • auditing de sécurité
  • détection de connexions suspicieuses
  • investigations d'incidents
  • vérification de policies réseau

✅ 6. Points clés SnowPro Core à retenir

🔐 Network Policies

  • Filtrent l'accès au compte → IP clients autorisées.
  • Peuvent être appliquées par‑utilisateur.

🌐 Network Rules

  • Filtrent les connexions sortantes → endpoints externes.
  • Nécessaires pour External Functions & API calls.

🛡️ Secure Snowflake

  • Basé sur RBAC + policies + encryption.
  • Approche "zero-trust" + gouvernance fine.

📊 LOGIN_HISTORY

  • Audit complet des tentatives de connexion.
  • Analyse des IP, erreurs, authentifications.
