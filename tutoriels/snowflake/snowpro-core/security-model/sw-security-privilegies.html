Snowflake - Configuration du contrôle d'accès

Niveau Intermédiaire
Mis à jour: Février 2026 Durée: 25 min Difficulté: Intermédiaire
Snowflake RBAC User Management

1. Configuration du contrôle d'accès

Snowflake utilise un modèle d'accès hybride RBAC + DAC + UBAC, mais RBAC est le modèle recommandé pour toutes les implémentations.

✔ Principes essentiels

  • Les privilèges sont accordés à des rôles, non directement aux utilisateurs (sauf exceptions).
  • Les utilisateurs activent un primary role, et peuvent activer d'autres privilèges via les secondary roles.
  • Les owners (privilège OWNERSHIP) gèrent la sécurité de leurs objets (DAC).

✔ Étapes de configuration générale

  1. Créer les utilisateurs (USERADMIN).
  2. Créer des rôles personnalisés (USERADMIN).
  3. Créer la hiérarchie des rôles (USERADMIN/SECURITYADMIN).
  4. Attribuer les privilèges aux rôles (SECURITYADMIN).
  5. Attribuer les rôles aux utilisateurs (USERADMIN/SECURITYADMIN).
  6. Activer le rôle approprié dans la session (USE ROLE ...).

2. User Management (Admin — User Management)

✔ Rôles impliqués dans la gestion utilisateur

  • USERADMIN : création gestion des USERS et ROLES.
  • SECURITYADMIN : gestion des privilèges et GRANTS.

✔ Gestion des USERS

  • Création via SnowSight, SQL (CREATE USER) ou SCIM (provisionnement IdP).
  • Les utilisateurs ont un primary role défini dans DEFAULT_ROLE.
  • Ils peuvent avoir plusieurs rôles attribués.
  • Par défaut, tous les utilisateurs héritent aussi du rôle PUBLIC.

3. CREATE ROLE

Créer un rôle personnalisé :

CREATE ROLE analyst;
  • Nécessite un rôle ayant privilège CREATE ROLE (souvent USERADMIN).
  • Les rôles peuvent être assignés à d'autres rôles, créant une hiérarchie.

4. GRANT ROLE

Attribuer un rôle à un utilisateur ou un autre rôle :

GRANT ROLE analyst TO USER alice;
GRANT ROLE analyst TO ROLE finance_team;

✔ Points essentiels

  • L'héritage s'applique : un rôle "parent" hérite des privilèges des rôles enfants.
  • Le rôle ACTIVÉ par l'utilisateur détermine les privilèges disponibles dans la session.

5. GRANT PRIVILEGE

Attribuer des privilèges à un rôle :

GRANT SELECT ON TABLE sales TO ROLE analyst;
GRANT USAGE ON WAREHOUSE wh_xs TO ROLE analyst;

✔ Privilèges clés

  • Les privilèges dépendent du type d'objet (warehouse/table/schema/etc.)
  • Exemples :
    • USAGE (db, schema, warehouse)
    • SELECT, INSERT, UPDATE, DELETE (tables)
    • CREATE TABLE, CREATE VIEW (schema)
    • OWNERSHIP (objet complet) — non héritable.
✔ Règle d'accès fondamentale

Pour accéder à un objet :

  • USAGE on DATABASE
  • + USAGE on SCHEMA
  • + privilege on OBJECT

6. SHOW GRANTS

Permet d'auditer les privilèges.

✔ Exemples

-- Lister les privilèges d'un utilisateur
SHOW GRANTS TO USER alice;

-- Lister les privilèges attribués à un rôle
SHOW GRANTS TO ROLE analyst;

-- Lister les roles attribués à un user
SHOW GRANTS OF ROLE analyst;

-- Lister les privilèges sur un objet
SHOW GRANTS ON TABLE sales;

7. REVOKE ROLE

Révoquer un rôle d'un user ou d'un autre rôle :

REVOKE ROLE analyst FROM USER alice;
REVOKE ROLE analyst FROM ROLE finance_team;
  • Le rôle doit avoir été préalablement accordé.
  • La révocation coupe immédiatement l'accès via ce rôle.

8. REVOKE PRIVILEGE

Retirer un privilège d'un rôle :

REVOKE SELECT ON TABLE sales FROM ROLE analyst;

✔ Détails importants

  • Snowflake interdit la suppression du privilège OWNERSHIP sans transfert d'ownership.
  • Les privilèges hérités via un "role parent" doivent être révoqués au niveau du rôle parent.

9. USE SECONDARY ROLES

Contrôle l'utilisation des privilèges attribués directement aux users (UBAC).

✔ Activation

USE SECONDARY ROLES ALL;

✔ Active tous les rôles secondaires et les privilèges directs. ✔ Utile pour un accès UBAC temporaire (ex. dépannage).

✔ Désactivation

USE SECONDARY ROLES NONE;
✔ Rappel important

Sans USE SECONDARY ROLES ALL, les privilèges accordés directement à un user ne sont pas considérés.

10. Synthèse

Concept Essentiel SnowPro Core
RBAC Modèle principal : privilèges → rôle → user
DAC L'OWNERSHIP contrôle l'objet (non héritable)
CREATE ROLE Permet de structurer l'organisation
GRANT ROLE Assignation des rôles aux users/rôles
GRANT PRIVILEGE Droit d'accéder ou modifier un objet
Accès minimal USAGE(DB) + USAGE(SCHEMA) + SELECT/…
SHOW GRANTS Audit central des accès
REVOKE Suppression du rôle ou privilège
Secondary roles Activation explicite pour UBAC
