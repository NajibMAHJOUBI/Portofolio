Niveau Intermédiaire

Snowflake MFA Sécurité

✅ 1. Multi‑Factor Authentication (MFA)

Source principale : [docs.snowflake.com]

La MFA est un pilier de la sécurité Snowflake. Elle réduit fortement les risques liés aux connexions par mot de passe en exigeant un second facteur d'authentification.

✅ 1.1. Principe général

Lorsqu'un utilisateur "password user" est enrolled en MFA, il doit fournir :

  • son mot de passe,
  • son second facteur (ex. Duo Mobile). [docs.snowflake.com]
MFA est destinée uniquement aux utilisateurs humains.
→ Les "service users" doivent utiliser d'autres méthodes d'authentification. [docs.snowflake.com]

✅ 1.2. Règles d'obligation MFA – selon la date de création du compte

Snowflake rend progressivement la MFA obligatoire pour tous les utilisateurs humains :

  • Si le compte existait avant le bundle 2024_08 → l'admin doit configurer le compte pour imposer la MFA. [docs.snowflake.com]
  • Si le compte a été créé après 2024_08 → MFA obligatoire par défaut pour tous les human users qui utilisent un mot de passe. [docs.snowflake.com]

Exception

L'exigence MFA ne s'applique pas aux service users. [docs.snowflake.com]

Option temporaire

Il est possible de rendre la MFA OPTIONAL via une Authentication Policy, mais ce sera temporaire, car Snowflake planifie la dépréciation totale du mot de passe single‑factor. [docs.snowflake.com]

✅ 1.3. MFA avec SSO (Single Sign-On)

  • Par défaut : Snowflake ne requiert pas de MFA additionnelle pour les utilisateurs SSO.
  • La MFA doit être gérée par l'IdP (Okta, Azure AD…). [docs.snowflake.com]

👉 Si nécessaire, une Authentication Policy peut imposer une MFA Snowflake après authentification SSO.

✅ 1.4. Dépréciation du password single‑factor

Snowflake a annoncé que :

  • Tous les human users devront obligatoirement utiliser la MFA (s'ils utilisent un mot de passe).
  • Les service users ne pourront plus utiliser un mot de passe. [docs.snowflake.com]

✅ 2. Authentication Policies

Source principale : [docs.snowflake.com]

Les Authentication Policies sont des objets Snowflake permettant de définir finement comment les utilisateurs/clients s'authentifient.

Elles peuvent être appliquées :

  • au niveau du compte,
  • au niveau de l'utilisateur (ce niveau prévaut). [docs.snowflake.com]

✅ 2.1. Ce qu'une Authentication Policy peut contrôler

🔐 1. Exigences MFA

  • Imposer que tous les utilisateurs s'inscrivent en MFA.
  • Spécifier quels mécanismes d'authentification nécessitent la MFA. [docs.snowflake.com]

🔐 2. Méthodes d'authentification autorisées

  • Password
  • OAuth
  • Key‑pair authentication
  • SAML
  • Programmatic access token [docs.snowflake.com]

🔐 3. Contrôle des IdP (SAML2 security integrations)

  • Spécifier quels IdP sont disponibles lors du login.
  • Restreindre par domaines ou patterns email (ALLOWED_USER_DOMAINS, ALLOWED_EMAIL_PATTERNS). [docs.snowflake.com]

🔐 4. Contrôle des clients

  • Restreindre quels clients/clients types peuvent se connecter (Snowsight, SnowSQL, CLI, drivers).
  • Définir des versions minimales de clients. [docs.snowflake.com]
Limitations : Le filtrage via CLIENT_TYPES est un best‑effort → ne bloque pas l'accès via l'API REST Snowflake.

🔐 5. Programmatic Access Tokens (PAT)

  • Définir expiration min/max
  • Définir la nécessité d'une network policy [docs.snowflake.com]

✅ 2.2. Application et hiérarchie

Une Authentication Policy définie au niveau de l'utilisateur override la policy définie au niveau du compte. [docs.snowflake.com]

✅ 2.3. Cas d'usage typiques

Selon la documentation :

  • Exiger MFA pour toutes les méthodes d'authentification ou seulement pour certaines.
  • Imposer un IdP particulier et masquer les autres.
  • Restreindre les accès clients (ex. empêcher Snowsight pour certains utilisateurs).
  • Exiger un niveau de sécurité plus fort pour certains groupes. [docs.snowflake.com]

✅ 2.4. Syntaxe SQL (aperçu)

Exemple simplifié basé sur la doc CREATE AUTHENTICATION POLICY :

CREATE AUTHENTICATION POLICY my_policy
    AUTHENTICATION_METHODS = ('PASSWORD', 'OAUTH')
    CLIENT_TYPES = ('SNOWSQL', 'JDBC')
    MFA_ENROLLMENT = 'REQUIRED'
    COMMENT = 'Policy enforcing MFA and limiting auth methods';

[docs.snowflake.com]

✅ 3. Synthèse SnowPro Core – Points clés à retenir

🔐 MFA

  • Réservée aux utilisateurs humains.
  • Deviendra obligatoire pour tous les password users.
  • Les comptes créés après 2024_08 ont MFA obligatoire par défaut. [docs.snowflake.com]

🔐 Authentication Policies

  • Définissent les règles d'authentification (MFA, méthodes, IdP, clients).
  • Peuvent s'appliquer au niveau compte ou utilisateur (user > account). [docs.snowflake.com]

🔐 SSO + MFA

  • Pas obligatoire par défaut → IdP censé gérer la MFA.
  • Snowflake peut la forcer via une Authentication Policy. [docs.snowflake.com]

🔐 Service Users

  • Ne doivent pas utiliser MFA → utiliser clés, tokens, OAuth… [docs.snowflake.com]
