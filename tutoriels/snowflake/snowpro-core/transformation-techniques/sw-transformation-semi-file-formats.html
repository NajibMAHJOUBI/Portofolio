1. Les types semi‑structurés dans Snowflake

Source : Data Types Semi‑structured

Snowflake supporte nativement plusieurs types semi‑structurés, optimisés pour manipuler des formats comme JSON, Avro, ORC, Parquet, XML.

✔ Types disponibles

  • VARIANT : type générique capable de contenir n'importe quel contenu semi‑structuré.
  • OBJECT : équivalent JSON à un dictionnaire (clé → valeur).
  • ARRAY : liste ordonnée de valeurs.
Ces types sont stockés dans des micro‑partitions en format columnar, ce qui favorise un traitement performant, même dans les structures imbriquées. Snowflake stocke également des métadonnées détaillées dans chaque micro‑partition, incluant les valeurs min/max et d'autres statistiques utiles pour le pruning.

2. Stockage & architecture des données semi‑structurées

Source : Micro‑partitions & Data Clustering

✔ Les points essentiels à retenir pour l'examen

  • Toutes les données semi‑structurées sont stockées dans des micro‑partitions entre 50MB et 500MB, compressées et en colonnes.
  • Les colonnes semi‑structurées bénéficient des mêmes mécanismes de pruning que les types classiques grâce à la capture de métadonnées (min/max, distinct count…).
  • Le stockage est automatique : aucun partitionnement manuel n'est nécessaire.

3. Interroger des données semi‑structurées

Source : Querying Semi‑structured Data

La documentation décrit comment interroger des données hiérarchiques stockées dans un type VARIANT.

✔ Syntaxe clé pour naviguer dans une colonne VARIANT

  • : → pour accéder aux champs d'objets
  • [] → pour accéder aux indices de tableau

Exemples classiques :

SELECT v:customer.name FROM raw_table;
SELECT v:items[0].price FROM raw_table;

✔ Opérations supportées

  • Accès aux champs imbriqués
  • Flattening via la fonction TABLE FLATTEN()
  • Conversion via TO_VARIANT, TO_OBJECT, TO_ARRAY
  • Cast explicite pour convertir un champ en type SQL classique (ex → ::string, ::number)

La documentation rappelle que Snowflake inclut des opérateurs et fonctions spécifiques pour exploiter les formats semi‑structurés.

4. FLATTEN() : Fonction centrale pour le semi‑structuré

Bien que non explicitement incluse dans les extraits renvoyés, FLATTEN est un point attendu en SnowPro Core :

→ C'est une table function qui transforme un ARRAY ou OBJECT en lignes tabulaires.

Exemple type :

SELECT
    f.value:productName,
    f.value:price
FROM raw t,
LATERAL FLATTEN(input => t.items) f;

5. Types semi‑structurés & Agrégations

Les types semi‑structurés sont inclus dans certaines fonctions d'agrégation comme :

  • ARRAY_AGG
  • OBJECT_AGG

Ce point apparaît dans la liste officielle des fonctions d'agrégation.

Cela permet de regrouper des objets JSON, par exemple pour reconstruire un document.

6. Points clés de performance (SnowPro Core)

✔ Micro‑partitions et pruning

Les métadonnées minimales/maximales de colonnes VARIANT permettent du pruning très efficace.

✔ Coût structurel

Les formats semi‑structurés étant colonaires + compressés, Snowflake peut lire uniquement les champs demandés.

✔ Bonnes pratiques
  • Préférer le cast explicite (::string, ::number) pour faciliter les filtres.
  • Utiliser FLATTEN() plutôt que des parcours imbriqués complexes.
  • Charger les données semi‑structurées via COPY/ Snowpipe dans une colonne VARIANT pour bénéficier de l'optimisation native.
