1. FLATTEN : rôle, fonctionnement, usage

Source : Snowflake Community

Snowflake utilise FLATTEN pour transformer un ARRAY ou OBJECT contenu dans un champ VARIANT en un jeu de lignes relationnel.

FLATTEN permet d'exploser un ARRAY JSON ou une structure imbriquée pour extraire dynamiquement des données semi‑structurées.

✔ Principe

FLATTEN retourne une table virtuelle contenant pour chaque élément :

  • VALUE — la valeur extraite
  • INDEX — position dans un tableau
  • KEY — nom de clé si OBJECT
  • PATH — chemin JSON
  • SEQUENCE — ordre interne de traitement

Ces colonnes sont essentielles aux transformations.

2. Syntaxe FLATTEN (générale) 

SELECT ...
FROM TABLE(FLATTEN(
    INPUT => <expression_variant>,
    PATH => '<json_path_optional>',
    MODE => 'ARRAY|OBJECT|BOTH',
    OUTER => TRUE|FALSE,
    RECURSIVE => TRUE|FALSE
));

✔ Paramètres (références indirectes)

  • INPUT : l'expression VARIANT à traiter (obligatoire)
  • PATH : chemin JSON optionnel pour cibler un sous-élément
  • MODE : 'ARRAY', 'OBJECT', ou 'BOTH'
  • OUTER : TRUE pour conserver les lignes même si INPUT est NULL
  • RECURSIVE : TRUE pour explorer récursivement les structures imbriquées
Snowflake permet d'extraire dynamiquement des objets JSON à l'aide de FLATTEN combiné à LATERAL.

3. FLATTEN + LATERAL : extraction dynamique

La ressource Snowflake Community décrit spécifiquement l'usage réel pour "dynamically extracting JSON using LATERAL FLATTEN".

✔ L'accès aux champs imbriqués

La combinaison de LATERAL et FLATTEN permet d'accéder dynamiquement aux valeurs d'objets JSON, y compris lorsqu'on ne connaît pas les clés en avance.

✔ Approche 1 : extraction simple

SELECT
    f.value
FROM my_table t,
LATERAL FLATTEN(input => t.json_column) f;

✔ Approche 2 : extraction profonde (hiérarchie)

FLATTEN peut être utilisé plusieurs fois (multi‑FLATTEN) pour naviguer dans des structures JSON hiérarchiques complexes. 

SELECT
    child.value
FROM my_table t,
LATERAL FLATTEN(input => t.json_column:parent_array) parent,
LATERAL FLATTEN(input => parent.value:child_array) child;

✔ Approche 3 : extraction dynamique des clés

FLATTEN retourne KEY, VALUE, PATH, ce qui permet d'extraire dynamiquement des colonnes sans connaître les noms des clés JSON à l'avance. 

SELECT
    f.key,
    f.value
FROM my_table t,
LATERAL FLATTEN(input => t.json_column) f;

4. FLATTEN et performance (SnowPro Core)

  • ✔ FLATTEN = opération coûteuse si utilisé massivement (car traverse potentiellement un tableau très large).
  • ✔ FLATTEN + LATERAL permet un accès structuré → meilleur que :path en cas de structure variable.
  • ✔ Toujours éviter RECURSIVE => TRUE sauf nécessité → Peut provoquer une explosion combinatoire.

5. JSON parsing + FLATTEN

Dans la communauté, l'article rappelle que du JSON peut être chargé via PARSE_JSON() et ensuite "flattened" :

La fonction PARSE_JSON peut être utilisée pour transformer des chaînes JSON avant de les traiter avec FLATTEN. 
SELECT f.value
FROM (SELECT PARSE_JSON(raw_json) AS v FROM src),
LATERAL FLATTEN(input => v.items) f;

6. Cas pratiques (à connaître pour SnowPro Core)

✔ 1. Exploser un tableau JSON

SELECT
    f.index,
    f.value
FROM events,
LATERAL FLATTEN(input => events.payload:items) f;

✔ 2. Extraire toutes les clé/valeurs

SELECT
    f.key,
    f.value
FROM logs,
LATERAL FLATTEN(input => logs.json_event) f;

✔ 3. Extraction dynamique (schémas inconnus)

Important pour les API NoSQL / telemetry.

✔ 4. Multi‑FLATTEN (hiérarchie profonde)

Pour logs complexes ou événements IoT.
