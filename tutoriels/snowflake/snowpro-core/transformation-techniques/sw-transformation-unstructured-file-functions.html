Snowflake Unstructured Data FILE Type

1. Contexte : travailler avec des fichiers non structurés

Unstructured data includes text-heavy content (documents), images, video, audio, and specialized industry file types.

Les fichiers doivent être dans un stage interne ou externe, puis manipulés en SQL via :

  • URL de fichier (Scoped / Stage File URL)
  • FILE objects (via TO_FILE / TRY_TO_FILE)

2. Le type SQL FILE (central pour les fonctions unstructured)

A FILE value represents a file stored in an internal or external stage… It stores metadata such as size, type, etag, last modified timestamp.

Le FILE contient notamment :

  • STAGE
  • RELATIVE_PATH
  • STAGE_FILE_URL
  • SCOPED_FILE_URL
  • CONTENT_TYPE (MIME)
  • SIZE
  • ETAG
  • LAST_MODIFIED

3. Fonctions SQL associées au FILE type

Source : FILE functions

✔ A. Fonctions Constructeurs

Permettent de créer un objet FILE :

  • TO_FILE — Crée un FILE à partir d'une URL, d'un stage + chemin, ou d'un objet metadata
  • TRY_TO_FILE — Même logique mais renvoie NULL en cas de problème
You can create a file by passing a scoped file URL, a stage and path, or a metadata object.

5. Intégration avec UDF/Procedures pour lire un fichier

Use a scoped URL when passing a file's location to a UDF.

Très souvent testé en SnowPro : toujours utiliser Scoped URL dans un UDF pour éviter les attaques de type file-injection.

6. Bonnes pratiques SnowPro Core

✔ Toujours utiliser un Scoped URL

→ sécurité + limite temporelle

✔ Utiliser TO_FILE/TRY_TO_FILE pour manipuler un fichier dans SQL

→ transformation du fichier en FILE object

✔ Utiliser les fonctions FL_* pour inspecter les métadonnées

→ utile pour ETL ingestion, cataloging d'images/vidéos/documents

✔ FILE n'est qu'un descripteur, pas le contenu

FILE values do not store the file data itself.

✔ Les FILE values ne se mettent pas à jour automatiquement si le fichier change

FILE values may become inconsistent with the underlying staged files.
