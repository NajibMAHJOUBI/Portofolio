Types d'URL pour accéder aux fichiers non structurés dans Snowflake

Source officielle : Introduction to unstructured data

Snowflake propose trois types d'URL pour accéder à des fichiers stockés sur un stage interne ou externe. Elles sont utilisées dans les requêtes SQL, les UDF/procedures, les applications externes, et les workflows de data loading/processing.

La documentation souligne que ces URL offrent des niveaux différents de sécurité, de portée et d'usage.

1. Scoped URL

✔ Définition

Encoded URL that permits temporary access to a staged file without granting privileges to the stage.

Une Scoped URL donne un accès temporaire aux fichiers, sans transmettre les privilèges du stage sous-jacent. Elle est cryptée et limitée à un contexte de sécurité spécifique.

✔ Expiration

The URL expires when the persisted query result period ends (24 hours).

Durée : 24 heures, liée au résultat persistant de Snowflake.

✔ Cas d'usage recommandé

  • Accorder un accès contrôlé à un fichier au sein du même compte Snowflake, par des rôles spécifiques.
  • Construire des vues sécurisées qui exposent des URLs aux consommateurs internes.
  • Sécuriser les UDF/UDTF (Snowflake recommande explicitement de passer uniquement des Scoped URLs aux UDF pour éviter l'injection de fichiers).

✔ Particularités

Snowflake journalise dans l'history qui accède au fichier via une scoped URL.

2. File URL (Stage File URL)

✔ Définition

URL that identifies the database, schema, stage, and file path.

Il s'agit de l'URL native et permanente d'un fichier situé sur un stage Snowflake.

✔ Cas d'usage recommandé

Pour usage interne Snowflake, dans :

  • des pipelines SQL
  • des requêtes techniques
  • des opérations de partage via des vues
  • Document AI ou d'autres processing SQL
Ideal for custom applications… or for downloading/analyzing unstructured data in Snowsight.

✔ Conditions d'accès

L'utilisateur doit avoir les privilèges sur le stage (USAGE + READ).

3. Pre-signed URL

✔ Définition

A simple HTTPS URL used to access a file via a web browser… using a pre-signed access token.

C'est une URL HTTP(S) visant à exposer un fichier Snowflake à un utilisateur ou une application hors de Snowflake, via un token d'accès temporaire.

✔ Expiration

L'expiration du token est configurable.

✔ Cas d'usage recommandé

Scénarios externes :

  • Applications web ou mobiles
  • Téléchargements de fichiers pour analyse offline
  • Partenaires ou clients externes ne disposant pas d'accès Snowflake

✔ Utilisation typique

  • Transmission à des systèmes externes via HTTPS
  • Automatisation avec API REST Snowflake (GET sur la pre-signed URL)

5. Points clés à mémoriser pour SnowPro Core

1. Le type le plus sécurisé pour les UDF

= Scoped URL
→ Empêche l'accès non autorisé au stage.

2. Les File URLs nécessitent des privilèges sur le stage

→ Pas d'accès sinon.

3. Les Pre‑signed URLs sont destinées aux applications externes

→ Via navigateur ou API HTTP.

4. Scoped URLs sont limitées à 24h et sont journalisées

→ Important pour audit & compliance.

5. Les pré-signed URLs ont une expiration configurable

→ Permettent de gérer les besoins de sécurité.

6. Mini‑QCM d'entraînement (3 questions)

1️⃣ Quel type d'URL est recommandé pour passer un fichier à une UDF ?

➡️ Scoped URL (sécurisée & limitée)

2️⃣ Quel type d'URL permet un accès depuis un navigateur web ?

➡️ Pre-signed URL

3️⃣ Quel type d'URL identifie directement <db>.<schema>.<stage>/<path> ?

➡️ File URL
