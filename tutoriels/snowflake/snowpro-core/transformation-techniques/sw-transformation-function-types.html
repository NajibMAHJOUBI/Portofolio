Snowflake Functions Performance

✅ 1. Operators & Functions – Vue d'ensemble

La documentation Snowflake organise toutes les fonctions en grandes familles, dont :

  • Fonctions système (SYSTEM$…),
  • Fonctions de table (TABLE(…)),
  • Fonctions SQL standards,
  • Fonctions externes,
  • UDFs (User-Defined Functions).
Point clé performance : Certaines fonctions empêchent l'utilisation du cache : CURRENT_TIMESTAMP, RANDOM, UUID_STRING, etc.

Cela signifie que TOUTES les fonctions ne sont pas équivalentes en termes de performance, ce qui est un point important pour SnowPro.

✅ 2. System Functions (Fonctions système)

Les fonctions système Snowflake (préfixe SYSTEM$) sont utilisées pour :

  • Vérifier l'état d'objets,
  • Diagnostiquer la performance,
  • Interroger le clustering (ex. SYSTEM$CLUSTERING_INFORMATION),
  • Accéder aux résultats d'une requête.
Impact cache : Les fonctions évaluées à l'exécution (ex. CURRENT_TIMESTAMP) empêchent la réutilisation du Persisted Result Cache

✅ 3. Table Functions (Fonctions de table)

Les table functions retournent un result set et doivent être appelées via :

SELECT … FROM TABLE(function_name(…));

✔ RESULT_SCAN() – Fonction clé

Permet de récupérer explicitement les résultats d'une requête précédente :

  • Permet d'utiliser un jeu de résultats sans réexécuter la requête
  • Fonction utile même lorsque les conditions du persisted result cache ne sont plus remplies

Exemple :

SELECT * FROM TABLE(RESULT_SCAN(last_query_id()));
Cette fonction est importante pour SnowPro Core car elle montre comment manipuler les jeux de résultats et contourner le système de cache standard.

✅ 4. External Functions

Une external function appelle un service externe via API.

✔ Point clé : Le recours à une external function empêche la réutilisation du cache des résultats

C'est un point très testé dans SnowPro Core :

  • Les résultats persistés ne sont pas réutilisés si la requête contient une external function.
  • Cela implique :
    • Un coût plus élevé (requête entièrement réévaluée),
    • Une latence potentiellement plus importante,
    • Une nécessité de surveiller les performances si l'on utilise des extensions API.

✅ 5. UDFs (User‑Defined Functions)

✔ Impact cache : Un UDF empêche le persisted result cache. Snowflake considère les UDFs comme du code évalué à l'exécution → pas de réutilisation du cache

Les UDFs Snowflake peuvent être écrites en :

  • SQL
  • JavaScript
  • Python (via Snowpark)
  • Java (Snowpark container services)

✔ Rôle des UDFs

Les UDFs permettent :

  • D'encapsuler la logique métier,
  • De créer des transformations réutilisables,
  • D'étendre SQL sans recourir aux external functions.
✔ Contraintes importantes SnowPro Core
  • Les UDFs tournent dans l'environnement Snowflake → stateless
  • Ils peuvent avoir un impact performance important
  • Ils cassent le cache des résultats persistés

✅ 7. Synthèse pour SnowPro Core

✔ À connaître absolument

  • Les opérateurs & fonctions Snowflake sont organisés par catégories (système, table, external, UDF).
  • Certaines fonctions empêchent la réutilisation des résultats persistés → impact majeur sur la performance.
  • RESULT_SCAN() est une fonction de table clé.
  • Les external functions servent à appeler des API → cassent le cache.
  • Les UDFs permettent d'étendre SQL → cassent aussi le cache.

✔ Rôle dans la performance (thématique SnowPro majeure)

Comprendre :

  • quelles fonctions se réévaluent,
  • lesquelles sont compatibles avec le cache,
  • comment analyser les plans d'exécution.
