🧊 Snowflake Stages et Chargement de Données

Les stages dans Snowflake représentent des emplacements intermédiaires servant à stocker des fichiers avant le chargement ou après l'export.

Il existe trois familles :

  • Internal Stages (hébergés dans Snowflake)
  • External Stages (hébergés dans des services externes : S3, GCS, Azure Blob)
  • Local File Upload (chargement direct via Snowsight)

✅ 1. Internal Stages (Stages internes)

Les internal stages sont des zones de stockage gérées par Snowflake et hébergées dans le compte Snowflake. Ils sont utilisés pour charger des données dans les tables ou pour stocker temporairement des fichiers.

Selon la documentation : Snowflake permet de charger des données depuis plusieurs types de sources, incluant internal (Snowflake) locations. [docs.snowflake.com]

🔹 Types d'Internal Stages

✔ 1. User Stage (@~)

  • Chaque utilisateur possède un stage interne dédié.
  • Utilisation simple pour tester des chargements.

✔ 2. Table Stage

  • Chaque table possède un stage interne associé.
  • Accessible via @%table_name.

✔ 3. Named Internal Stage

  • Créé explicitement :
CREATE STAGE my_internal_stage;
  • Peut contenir des options : file format, encryption, directory tables.
Avantages
  • Pas besoin de configurer de credentials cloud.
  • Sécurisé et complètement géré par Snowflake.
  • Architecture simple pour les petits workflows ETL/ELT.

✅ 2. External Stages (Stages externes)

Les external stages permettent de charger / décharger des données depuis un service de stockage cloud :

  • Amazon S3
  • Google Cloud Storage (GCS)
  • Microsoft Azure Blob Storage

Documentation : Snowflake supporte le chargement depuis external cloud locations. [docs.snowflake.com]

🔹 Définition

Un external stage référencie un emplacement externe :

CREATE STAGE my_ext_stage
    URL='s3://my-bucket/path/'
    CREDENTIALS=(AWS_KEY_ID='...' AWS_SECRET_KEY='...');

🔹 Caractéristiques clés

  • Doit inclure des informations d'authentification (IAM role, token, clés).
  • Peut utiliser des file formats et directory tables.
  • Souvent utilisé pour des pipelines automatisés ou ingestion continue (Snowpipe).
Points importants pour SnowPro Core
  • Snowflake automatically detects compression for Avro/ORC/Parquet files situés dans un external stage. [docs.snowflake.com]
  • External stages sont indispensables pour Snowpipe en mode auto-ingest.
  • Permet de traiter de très gros volumes et s'intègre dans des architectures data lake.

✅ 3. Local File System Upload (via Snowsight)

En plus des internal/external stages, Snowflake permet d'importer des fichiers directement depuis son ordinateur. La fonctionnalité d'upload est mentionnée dans la documentation :

→ Snowsight permet d'upload des fichiers directement vers des tables via l'UI et de gérer l'ingestion à partir du local. [dataengine.academy.com]

🔹 Fonctionnement général

  • Dans Snowsight : Add Data ou Load Data
  • L'utilisateur sélectionne un fichier local (CSV, JSON, Parquet, etc.)
  • L'interface :
    • crée un temporary stage interne
    • copie le fichier dedans
    • lance un COPY INTO <table> automatiquement

🔹 Avantages

  • Très simple pour petits fichiers et tests rapides.
  • Pas besoin de configurer de stage ni de credentials.
  • Idéal pour environnement dev ou QA.
Limitations
  • Pas adapté aux gros volumes (préférer internal/external stages).
  • Pas automatisable hors UI.

🎯 4. Synthèse organisationnelle SnowPro Core

Type de stage Localisation Usage typique Notes certification
Internal Stage Dans Snowflake Chargement facile, staging interne Pas de credentials externes
External Stage S3 / Azure / GCS Pipelines, ingestion massive, Snowpipe Credentials obligatoires
Local File Upload Poste utilisateur Tests, POC, chargement manuel Snowsight uniquement

🎯 5. Points clés à mémoriser pour l'examen SnowPro Core

  • ✔ Snowflake supporte le chargement depuis : internal stages, external stages, local filesystem via UI.
  • ✔ Internal stages n'ont pas besoin d'authentification externe.
  • ✔ External stages nécessitent des credentials cloud.
  • ✔ Snowflake détecte automatiquement la compression des fichiers semi‑structurés. [docs.snowflake.com]
  • ✔ Snowsight upload = copie automatique du fichier vers un stage temporaire puis COPY INTO. [dataengine.academy.com]
  • ✔ Les external stages sont utilisés pour Snowpipe et ingestion d'événements.
  • ✔ Internal stages : user stage, table stage, named stage.
