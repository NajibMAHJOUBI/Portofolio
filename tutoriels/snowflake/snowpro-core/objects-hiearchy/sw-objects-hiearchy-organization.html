Snowflake Organizations Governance

Introduction

Snowflake introduit le concept d'Organization pour regrouper tous les comptes appartenant à une même entreprise. Cela permet une gouvernance centralisée, une administration simplifiée et un suivi global des usages.

1. Organizations : concepts fondamentaux

Une Organization Snowflake est une entité logique regroupant l'ensemble des comptes Snowflake appartenant à une entreprise.

Elle permet :

  • de lister tous les comptes de l'entreprise,
  • de gérer des objets organisationnels,
  • de voir des données d'usage cross‑accounts,
  • de gérer l'accès à des fonctionnalités globales (ex. Marketplace Terms),
  • de faciliter le multi‑account strategy (Prod / Dev / QA / BU / Régions).

2. Organization Account (compte d'organisation)

Il existe un seul organization account par organisation.

C'est un type spécial de compte réservé aux administrateurs organisationnels.

✔ Rôles clés du compte d'organisation

Les administrateurs peuvent :

  • gérer le cycle de vie des comptes (création / suppression),
  • voir les données d'usage organisationnelles (query history, consommation),
  • créer et gérer organization users et organization groups,
  • activer les Marketplace Terms pour toute l'organisation,
  • activer la réplication cross‑region pour les comptes,
  • utiliser les premium views dans ORGANIZATION_USAGE.

✔ Organisation hybride (compliance)

Une organisation peut contenir des comptes dans des régions régulées et non régulées.

Certaines fonctionnalités (premium views, objets organisationnels) peuvent amener Snowflake à déplacer des métadonnées entre régions, ce qui a un impact compliance.

3. Rôles d'administration : GLOBALORGADMIN vs ORGADMIN

Snowflake fournit deux rôles d'administration organisationnelle :

✔ GLOBALORGADMIN (modèle modernisé)

  • Rôle recommandé pour les organisations multi‑comptes.
  • S'utilise uniquement dans l'organization account.
  • Permet toutes les tâches organisationnelles : gestion comptes, organisation users, premium views.

✔ ORGADMIN (ancien modèle)

  • Rôle activable dans plusieurs comptes (limité par défaut à 8).
  • En cours de dépréciation pour les organisations multi‑comptes.
  • Snowflake préviendra 3 mois avant son retrait.

→ Pour SnowPro Core : retenir que le rôle moderne et recommandé est GLOBALORGADMIN.

4. Managing Accounts in an Organization

L'organisation permet une gestion complète des comptes Snowflake :

✔ Création / suppression de comptes

Les administrateurs peuvent :

  • créer un compte via l'organization account,
  • définir son édition Snowflake, région, rôle de démarrage, compute, etc.

✔ Gestion globale

L'interface permet :

  • lister les comptes
  • modifier des paramètres d'édition
  • activer des services (réplication, failover, marketplace terms)

5. Organization Users et Organization Groups

Nouveauté importante des organisations modernes.

✔ Organization Users

  • Un organization user peut accéder à plusieurs comptes Snowflake avec une seule identité.
  • Permet une administration centralisée et réduit la duplication des utilisateurs.

✔ Organization Groups

  • Groupes d'utilisateurs organisationnels pour assigner des rôles dans plusieurs comptes.
  • Facilite onboarding / offboarding.

6. Premium Views (dans ORGANIZATION_USAGE)

Disponible uniquement dans l'organization account.

Exemples :

  • vues sur tags, masking policies, objects, usage croisé multi‑comptes.

→ Ces vues offrent une visibilité centralisée non accessible via un compte standard.

7. Account Identifiers

Pour se connecter à un compte, on utilise un account identifier.

Format général :

  • orgname-account_name (Format 1 recommandé)
  • Peut être utilisé dans Snowsight, drivers, SnowSQL, Snowflake CLI.

L'account identifier :

  • identifie le compte au sein de l'organisation,
  • dépend du cloud provider et de la région.

Formats existants (selon doc complète) :

  • Account name in organization
  • Account locator
  • URL-based identifier

→ Snowflake recommande Account name in organization pour cohérence multi‑comptes.
