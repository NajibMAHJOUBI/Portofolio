Snowflake File Formats

Les file formats sont des objets Snowflake utilisés pour décrire la structure, le type et les propriétés des fichiers stockés dans des stages (internes ou externes). Ils sont essentiels pour les commandes COPY INTO <table> et COPY INTO <location>.

1. CREATE FILE FORMAT — Le DDL officiel

La commande sert à créer un objet FILE FORMAT nommé, qui pourra ensuite être utilisé dans :

  • COPY INTO <table>
  • COPY INTO <location>
  • CREATE STAGE (association directe à un stage)
  • D'autres objets manipulant des fichiers

➜ Syntaxe complète (simplifiée) :

CREATE [ OR REPLACE ]
    [ { TEMP | TEMPORARY | VOLATILE } ]
    FILE FORMAT [ IF NOT EXISTS ] <name>
    [ TYPE = { CSV | JSON | AVRO | ORC | PARQUET | XML | CUSTOM } [ formatTypeOptions ] ]
    [ COMMENT = '<string>' ];

2. File formats supportés par Snowflake

Snowflake supporte les formats suivants pour le chargement (COPY INTO <table>) :

✔ Structured

  • CSV / TSV / autres délimités
    → Snowflake supporte toute valeur single-byte comme délimiteur.

✔ Semi-structured

  • JSON
  • Avro
  • ORC
  • Parquet
  • XML
Points importants :
  • Snowflake détecte automatiquement les fichiers Avro/ORC/Parquet compressés.
  • Parquet supporté uniquement en format writer v1 (v2 non supporté).
  • JSON est chargé en mode NDJSON lors de l'unload.
  • Semi-structured → chaque top-level object = une ligne distincte dans la table VARIANT.

3. Options disponibles selon le type de fichier

Snowflake propose un large ensemble d'options paramétrables dans CREATE FILE FORMAT.

✔ A. CSV — options principales

  • COMPRESSION = AUTO | GZIP | BZ2 | ZSTD | …
  • RECORD_DELIMITER = '<string>'
  • FIELD_DELIMITER = '<string>'
  • PARSE_HEADER = TRUE/FALSE
  • SKIP_HEADER = <int>
  • SKIP_BLANK_LINES = TRUE/FALSE
  • ESCAPE, ESCAPE_UNENCLOSED_FIELD
  • NULL_IF = (‘<string>’, …)
  • ERROR_ON_COLUMN_COUNT_MISMATCH = TRUE/FALSE
  • FIELD_OPTIONALLY_ENCLOSED_BY = '<char>'
  • ENCODING = 'UTF8' (par défaut)
  • TRIM_SPACE = TRUE/FALSE

✔ B. JSON — options principales

  • STRIP_OUTER_ARRAY = TRUE/FALSE
  • IGNORE_UTF8_ERRORS
  • ALLOW_DUPLICATE
  • ENABLE_OCTAL
  • MULTI_LINE
  • DATE_FORMAT / TIME_FORMAT / TIMESTAMP_FORMAT
  • REPLACE_INVALID_CHARACTERS

JSON est nativement interprété → chargé généralement dans VARIANT.

✔ C. AVRO, ORC, PARQUET

  • AVRO : COMPRESSION, NULL_IF
  • ORC : TRIM_SPACE, NULL_IF
  • PARQUET : COMPRESSION = AUTO | SNAPPY | LZO, BINARY_AS_TEXT, USE_LOGICAL_TYPE, USE_VECTORIZED_SCANNER

✔ D. XML

  • Supporté pour chargement semi-structuré
  • Chaque top-level element devient une ligne

4. Où peut‑on définir un file format ?

Selon la doc data-load-prepare :

  • ✔ Dans un named file format (via CREATE FILE FORMAT)
  • ✔ Dans un stage (via CREATE STAGE … FILE_FORMAT = …)
  • ✔ Directement dans la commande COPY INTO <table> :
COPY INTO my_table
FROM @my_stage/file.csv
FILE_FORMAT = (TYPE='CSV' FIELD_DELIMITER='|' SKIP_HEADER=1);

5. File Formats et Named File Formats

Snowflake recommande l'usage de named file formats lorsque :

  • le chargement est récurrent,
  • plusieurs tables partagent un même format,
  • il faut standardiser les options.

Exemple officiel :

CREATE OR REPLACE FILE FORMAT my_csv
    TYPE = 'CSV'
    FIELD_DELIMITER = '|';

6. Compression — points clés

Selon la documentation Preparing to load data :

  • Snowflake recommande de compresser les fichiers pour les gros volumes.
  • Snowflake détecte automatiquement : codec de compression et file type compression.
  • La gestion du paramètre COMPRESSION peut se faire : dans COPY INTO, dans un FILE FORMAT, ou dans un STAGE.

7. Résumé

Thème À retenir
CREATE FILE FORMAT Crée un objet décrivant les options de parsing des fichiers
Formats supportés CSV, TSV, JSON, Avro, ORC, Parquet, XML
Compression Auto‑détection + options paramétrables
Usage COPY INTO, STAGE, unloading
Semi‑structured JSON, Avro, ORC, Parquet, XML chargés dans VARIANT
Inline vs Named File Format Named recommandé pour réutilisation
