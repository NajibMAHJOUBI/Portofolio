DDL Database — CREATE / ALTER / DROP / UNDROP DATABASE

Les commandes DDL liées aux bases de données dans Snowflake permettent de créer, modifier, cloner, répliquer, restaurer, supprimer et récupérer des bases.

Snowflake fournit un ensemble riche d'options destinées à la gouvernance, la récupération, la réplication, les catalogues et le support Iceberg.

1. CREATE DATABASE – Fonctionnalités générales

CREATE DATABASE permet de :

  • créer une base standard,
  • créer une base transiente,
  • cloner une base existante, incl. Time Travel,
  • créer une base depuis un backup set,
  • créer une base depuis un listing (Snowflake Marketplace),
  • créer une base à partir d'un share,
  • créer une base en tant que réplica d'une base primaire (Database Replication).

C'est l'une des commandes DDL les plus puissantes de Snowflake.

2. Syntaxe générale (formule standard) 

CREATE [ OR REPLACE ] [ TRANSIENT ] DATABASE [ IF NOT EXISTS ] <name>
    [ CLONE <source_db>
        [ { AT | BEFORE } ( { TIMESTAMP => <timestamp>
                            | OFFSET => <time_difference>
                            | STATEMENT => <query_id> } ) ]
        [ IGNORE TABLES WITH INSUFFICIENT DATA RETENTION ]
        [ IGNORE HYBRID TABLES ]
    ]
    [ DATA_RETENTION_TIME_IN_DAYS = <integer> ]
    [ MAX_DATA_EXTENSION_TIME_IN_DAYS = <integer> ]
    [ EXTERNAL_VOLUME = <external_volume_name> ]
    [ CATALOG = <catalog_integration_name> ]
    [ ICEBERG_VERSION_DEFAULT = <integer> ]
    [ ENABLE_ICEBERG_MERGE_ON_READ = TRUE | FALSE ]
    [ REPLACE_INVALID_CHARACTERS = TRUE | FALSE ]
    [ DEFAULT_DDL_COLLATION = '<collation>' ]
    [ STORAGE_SERIALIZATION_POLICY = COMPATIBLE | OPTIMIZED ]
    [ COMMENT = '<string>' ]
    [ WITH TAG ( <tag_name> = '<value>', ... ) ]
    [ WITH CONTACT ( purpose=name, ... ) ]
    [ OBJECT_VISIBILITY = <value> | PRIVILEGED ]
    [ ENABLE_DATA_COMPACTION = TRUE | FALSE ];

3. Variantes de CREATE DATABASE

✔ A. Créer une base standard

CREATE DATABASE my_db;

✔ B. Transient Database

CREATE TRANSIENT DATABASE my_transient_db;

→ Pas de Fail-safe → coûts plus faibles.

✔ C. Cloner une base existante

Le clone Snowflake est zéro‑copy (metadata seulement).

CREATE DATABASE my_clone CLONE my_db;

Prend en charge Time Travel :

CREATE DATABASE my_clone
    CLONE my_db AT (TIMESTAMP => '2026-03-01 12:00:00');

Options supplémentaires :

  • IGNORE TABLES WITH INSUFFICIENT DATA RETENTION
  • IGNORE HYBRID TABLES

✔ D. Restaurer depuis un backup

CREATE DATABASE restored_db
    FROM BACKUP SET my_backup IDENTIFIER 'backup_id';

✔ E. Base à partir d'un Listing (Marketplace)

CREATE DATABASE db_from_listing
    FROM LISTING 'provider/listing_name';

✔ F. Base créée à partir d'un Share (Secure Data Sharing)

CREATE DATABASE shared_db
    FROM SHARE provider_account.share_name;

✔ G. Base répliquée (replica)

CREATE DATABASE my_replica
    AS REPLICA OF acct.primary_db;

4. ALTER DATABASE

Permet de :

  • modifier les paramètres (retention, policies, tags),
  • renommer la base,
  • changer les collations,
  • changer les options Iceberg/synchronisation, etc.

Référencé dans les commandes associées : ALTER DATABASE, DESCRIBE DATABASE, SHOW DATABASES

5. DROP DATABASE & UNDROP DATABASE

✔ DROP DATABASE

Supprime une base et tous ses objets :

DROP DATABASE my_db;

✔ UNDROP DATABASE

Grâce à Time Travel, Snowflake permet de restaurer une base supprimée :

UNDROP DATABASE my_db;
