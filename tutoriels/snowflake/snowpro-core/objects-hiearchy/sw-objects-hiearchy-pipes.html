🧊 Snowpipe (Introduction)

Snowpipe est le service Snowflake de chargement continu (continuous loading) permettant d'ingérer des fichiers dès qu'ils arrivent dans un stage, en micro‑lots, avec une latence de quelques minutes.

Il remplace les pipelines batch basés sur COPY programmés et s'appuie sur un modèle serverless.

✅ 1. Qu'est-ce que Snowpipe ?

Selon la documentation :

Snowpipe permet de charger les données dès qu'elles sont disponibles dans un stage, en micro‑batches, avec disponibilité quasi‑immédiate pour les utilisateurs. [docs.snowflake.com]

Ses caractéristiques essentielles :

  • Chargement automatisé et continu
  • Basé sur un pipe, objet Snowflake contenant un COPY INTO <table>
  • Fonctionne via compute serverless fourni par Snowflake
  • Supporte tous les types de données, incluant JSON, Avro, Parquet etc. [docs.snowflake.com]

✅ 2. Architecture Snowpipe

Snowpipe charge les données :

  • Dès que les fichiers sont détectés dans un stage (interne ou externe).
  • En utilisant une instruction COPY définie dans un PIPE.
  • Par des ressources compute Snowflake, sans warehouse à gérer. [docs.snowflake.com]

Les fichiers sont chargés par Snowflake immédiatement via :

  • Notifications Cloud (Snowpipe automatisé)
  • Snowpipe REST API (injection contrôlée par API)

✅ 3. Le rôle du PIPE (objet Snowflake)

Un PIPE est un objet de première classe contenant une instruction COPY :

COPY INTO target_table
FROM @stage/path/
FILE_FORMAT = ...

Le pipe définit :

  • la source (un stage)
  • la cible (table Snowflake)
  • les options de chargement [docs.snowflake.com]

Snowpipe se base sur ce pipe et exécute automatiquement la logique COPY.

✅ 4. Mécanismes de détection des fichiers

Snowpipe supporte deux mécanismes :

🔹 A. Automated Snowpipe with Cloud Messaging

Snowflake est prévenu automatiquement de l'arrivée de nouveaux fichiers via :

  • AWS S3 Event Notifications
  • Azure Event Grid
  • GCP Pub/Sub [docs.snowflake.com]

Snowpipe poll ensuite les notifications déposées dans une file (queue) et charge les fichiers correspondants.

C'est la méthode la plus utilisée pour le near real-time.

🔹 B. Snowpipe REST API

Votre application appelle un endpoint Snowflake en fournissant :

  • un nom de pipe
  • une liste de fichiers

Snowflake vérifie les fichiers dans le stage puis les ajoute à la file d'ingestion. [docs.snowflake.com]

→ Utile pour les systèmes ne supportant pas les notifications cloud.

✅ 5. Plateformes Cloud supportées

Snowpipe (auto & REST API) supporte les stockages suivants :

  • Amazon S3
  • Google Cloud Storage
  • Azure Blob Storage
  • Azure Data Lake Gen2 [docs.snowflake.com]

Chaque cloud provider supporte tous les modes quand le compte Snowflake est hébergé sur AWS, Azure ou GCP.

✅ 7. Recommandations & limitations importantes

  • ✔ Snowflake recommande d'activer le cloud event filtering pour réduire les coûts, améliorer la latence et éviter le bruit dans les notifications. [docs.snowflake.com]
  • ✔ Utiliser un format cohérent dans les stages — Snowpipe prend en charge semi-structuré & compressé.
  • ✔ Snowpipe ne gère pas lui‑même les transformations complexes → Utiliser COPY transformations limitées ou un pipeline ELT.
  • ✔ Snowpipe ne garantit pas un chargement strictement en temps réel → Latence habituelle : quelques minutes.

🎯 8. Points à mémoriser pour la certification SnowPro Core

  • Snowpipe = chargement continu, serverless et déclenché automatiquement.
  • Un PIPE contient l'instruction COPY responsable du chargement.
  • Deux mécanismes : cloud notifications et REST API.
  • Pas besoin de warehouse : compute Snowflake inclus.
  • Fonctionne sur S3, GCS, Azure Blob, ADLS Gen2.
  • Snowpipe traite des micro‑batches.
  • Préférer COPY pour larges batchs planifiés.
  • Recommandation : activer le cloud event filtering. [docs.snowflake.com]
