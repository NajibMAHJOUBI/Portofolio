Account Management & Parameters

Cette synthèse regroupe les points essentiels pour comprendre l'administration de compte dans Snowflake et la gestion hiérarchique des paramètres — deux sujets fréquemment évalués à la certification SnowPro Core.

1. Account Management – Concepts clés

La page officielle Managing Your Snowflake Account regroupe les opérations d'administration essentielles du compte. [docs.snowflake.com]

Ces tâches concernent principalement les rôles :

  • ACCOUNTADMIN
  • SYSADMIN
  • SECURITYADMIN

🔹 Les composants clés de la gestion de compte

Selon la documentation : [docs.snowflake.com]

ComposantDescription
Account identifiersIdentifiants uniques du compte, utilisés pour les connexions multi‑comptes.
Trial accountsActivation, ajout de carte bancaire, annulation.
Parameter managementGestion des paramètres au niveau account/session/object.
User managementCréation utilisateurs, gestion des mots de passe, MFA, etc.
Behavior change managementActiver/désactiver les nouvelles releases de comportements Snowflake.
Securing Snowflake (via SECURITYADMIN)Contrôle des accès, network policies, MFA, etc.

🔹 Rôles d'administration (implicites dans la doc)

  • ACCOUNTADMIN → Super‑administrateur du compte
  • SECURITYADMIN → Gestion sécurité, grants, policies
  • USERADMIN → Gestion utilisateurs & rôles (documenté dans les sections liées)

2. Parameter Hierarchy & Types

Snowflake documente trois types de paramètres : [docs.snowflake.com]

✔ 1. Account parameters

  • Définis via : ALTER ACCOUNT.
  • Affectent tout le compte.
  • Seuls les rôles autorisés (ACCOUNTADMIN) peuvent les modifier.
  • Exemples fournis dans la documentation :
    • ALLOW_BIND_VALUES_ACCESS
    • ENABLE_INTERNAL_STAGES_PRIVATELINK
    • DISABLE_USER_PRIVILEGE_GRANTS

✔ 2. Session parameters

  • Peuvent être définis au niveau : session, user, account
  • Définition via : ALTER SESSION, ALTER USER, ou ALTER ACCOUNT.
  • Affectent uniquement la session active (si définis dans celle-ci). [docs.snowflake.com]

✔ 3. Object parameters

  • Définis pour les objets Snowflake : warehouses, databases, schemas, tasks, tables/views
  • Définis via leur commande ALTER propre : ALTER WAREHOUSE, ALTER SCHEMA, etc. [docs.snowflake.com]

3. Hiérarchie des paramètres (ordre de priorité)

La documentation précise que les paramètres suivent une hiérarchie de surcharge : [docs.snowflake.com]

Ordre général de résolution
  1. Session level (le plus prioritaire si explicitement défini)
  2. Object level (pour les objets concernés)
  3. User level (défauts appliqués à chaque login)
  4. Account level (valeur par défaut si rien n'est explicitement défini)

Cela signifie :

  • Une valeur définie dans une session écrase toutes les autres.
  • Une valeur account agit comme default global.

4. SHOW PARAMETERS — Navigation et diagnostic

La commande SHOW PARAMETERS permet de visualiser les paramètres :

SHOW PARAMETERS;
SHOW PARAMETERS IN ACCOUNT;
SHOW PARAMETERS FOR USER myuser;
SHOW PARAMETERS FOR WAREHOUSE mywh;

Selon la documentation :

  • Elle affiche la valeur courante et la valeur par défaut.
  • Elle précise où le paramètre a été défini (session, user, object ou account).
  • Elle ne nécessite pas de warehouse actif. [docs.snowflake.com]

5. Points essentiels à mémoriser pour SnowPro Core

✔ Account Management

  • L'administration du compte couvre : users, roles, paramètres, comportement, sécurité. [docs.snowflake.com]
  • ACCOUNTADMIN est le rôle maître.
  • Les identifiants de compte sont essentiels dans les environnements multi‑comptes.

✔ Parameters

  • Trois types : account, session, object.
  • Les paramètres ont des valeurs par défaut mais peuvent être surchargés.
  • La hiérarchie détermine la priorité → session > object > user > account. [docs.snowflake.com]
  • Objet SHOW PARAMETERS indispensable pour troubleshooting. [docs.snowflake.com]

✔ Modifications

  • ALTER ACCOUNT → paramètres globaux
  • ALTER SESSION → spécifiques session
  • ALTER USER → defaults session utilisateur
  • ALTER <object> → paramétrage objet (warehouse, database, schema, table, task)

6. Résumé

Snowflake offre une architecture d'administration robuste, basée sur :

  • une hiérarchie claire de paramètres, permettant un contrôle précis du comportement du système ;
  • un modèle RBAC puissant, centré sur ACCOUNTADMIN / SECURITYADMIN / USERADMIN ;
  • des commandes simples mais structurantes pour gérer account, sessions et objets.

La maîtrise de ces concepts est indispensable pour réussir la SnowPro Core Certification.
