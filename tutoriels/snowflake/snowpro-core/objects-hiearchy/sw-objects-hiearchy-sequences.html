Querying Sequences

Les sequences dans Snowflake sont des objets générant des valeurs numériques uniques. Elles servent typiquement à produire des clés techniques (surrogate keys), des identifiants d'audit ou tout champ nécessitant un numéro généré automatiquement.

1. Rôle et caractéristiques principales des sequences

Selon la documentation :

✔ Génération de valeurs uniques globalement

Les valeurs générées par une séquence sont garanties uniques tant que le signe de l'intervalle ne change pas.

✔ Non‑contiguïté

Snowflake ne garantit pas que les valeurs soient contiguës ni sans trous. Les gaps sont normaux.

✔ Non-ordre garanti (NOORDER)

Sans l'option ORDER, Snowflake peut générer les valeurs hors ordre strict, surtout en cas de parallélisme. Avec NOORDER : les valeurs générées peuvent être 1, 3, 101, 5, 103, etc.

✔ Exécution parallèle

Snowflake réserve des plages de valeurs pour optimiser l'exécution concurrente.

Exemples :

  • Step = 2 → réservera 100 et 101
  • Step = 10 → réservera 100 à 109

Cela participe aussi aux gaps.

2. Semantics détaillées des sequences

La documentation insiste sur les points suivants :

✔ Réservation de valeurs (value reservation)

Chaque valeur générée entraîne la réservation d'un ensemble de valeurs dépendant du step. Ces valeurs ne seront jamais réutilisées tant que le step ne change pas.

✔ Recalcul anticipé

Snowflake peut pré‑calculer la valeur suivante dès qu'une valeur a été utilisée, sans attendre la prochaine demande.

→ Impact : un ALTER SEQUENCE … SET INCREMENT peut ne pas affecter la valeur suivante, car une plage était déjà réservée.

✔ Modification du signe de l'INCREMENT

Si vous changez le step de +1 à -1 (ou inversement), Snowflake peut émettre des valeurs déjà émises.

Exemple : valeurs générées 1, 2, 3 → si INCREMENT passe de 1 à -1 : prochaines valeurs possibles : 2, 1.

3. Comment obtenir des valeurs de sequence ?

On utilise les pseudo‑colonnes :

  • my_seq.NEXTVAL → génère la prochaine valeur
  • my_seq.CURRVAL → retourne la dernière valeur utilisée dans la session

Exemples classiques :

SELECT my_seq.NEXTVAL;

INSERT INTO t VALUES (my_seq.NEXTVAL, ...);

4. Propriétés ORDER vs NOORDER

Par défaut, les séquences optimisent la performance :

  • ORDER : garantit que les valeurs augmentent (ou diminuent) selon l'intervalle.
  • NOORDER : performance supérieure, mais aucune garantie d'ordre, surtout en cas d'inserts concurrentiels.

Documentation : NOORDER permet d'améliorer la performance lorsque plusieurs INSERT sont exécutés simultanément.

5. Garanties Snowflake

  • ✔ Unicité (tant que le signe ne change pas)
  • ✔ Pas de contiguïté
  • ✔ Pas d'ordre garanti sans ORDER
  • ✔ Valeurs possiblement non séquentielles
  • ✔ Pas de réutilisation des valeurs réservées

6. Limites / pièges importants pour SnowPro Core

  • Snowflake ne garantit JAMAIS des séquences sans trous → Exam piège très fréquent.
  • Changer l'INCREMENT peut produire des valeurs déjà générées → en inversant le signe (+ → -).
  • L'ordre d'arrivée n'est pas garanti en cas de parallélisme ou en NOORDER
  • Pas d'assurance que NEXTVAL = valeur précédente + step → en raison de la réservation interne de plages.

7. Exemples testables SnowPro Core

✔ Générer plusieurs valeurs

SELECT myseq.NEXTVAL FROM TABLE(GENERATOR(ROWCOUNT => 5));

✔ Utiliser dans INSERT

INSERT INTO sales VALUES (myseq.NEXTVAL, ...);

✔ Vérifier la structure

SHOW SEQUENCES;
DESC SEQUENCE myseq;
