Synthèse SnowPro Core – Databases dans Snowflake

Les bases de données (databases) constituent le niveau logique supérieur pour organiser les données dans un compte Snowflake. Elles contiennent des schémas, eux‑mêmes contenant des objets tels que des tables, des vues, des fonctions, des file formats, etc.

1. Définition et rôle d'une Database

Toutes les données Snowflake sont stockées dans des databases.

Une database contient un ou plusieurs schemas, qui regroupent les objets de données (tables, vues, UDFs…).

Il n'existe aucune limite concernant le nombre de bases, de schémas ou d'objets qu'un utilisateur peut créer. [docs.snowflake.com]

Importance pour SnowPro Core :

La database est la racine de l'organisation logique des données d'un compte Snowflake. Elle détermine la structure de tous les objets enfants.

2. Types de bases dans Snowflake

Même si la page principale traite surtout du concept général de database, Snowflake inclut également :

✔ Databases utilisateur

  • Bases créées par les utilisateurs ou applications.
  • Peuvent contenir n'importe quels objets Snowflake.

✔ SNOWFLAKE database (system‑defined)

  • Base fournie par Snowflake contenant des métadonnées et vues système comme ACCOUNT_USAGE, ORGANIZATION_USAGE, etc. [docs.snowflake.com]

✔ Bases clonées

  • Grâce au zero‑copy cloning, une database peut être clonée instantanément sans duplication physique de données.

3. Objets contenus dans une Database

Dans Snowflake, une database peut contenir :

  • Schemas
  • Tables (permanent, transient, temporary)
  • External tables
  • Hybrid tables
  • Iceberg tables
  • Views (standard, secure, materialized)
  • File formats
  • Sequences
  • Stages
  • Functions, UDFs, UDTFs [docs.snowflake.com]

→ Les databases servent donc de "conteneur parent" pour toute la structure d'objets Snowflake.

4. Opérations principales sur les databases

Les opérations typiques incluent :

✔ CREATE DATABASE

Créer une nouvelle base :

CREATE DATABASE my_db;

✔ USE DATABASE

Sélectionner la base active :

USE DATABASE my_db;

✔ CLONE

Créer un clone zéro‑copie :

CREATE DATABASE my_db_clone CLONE my_db;

→ Le clonage fait partie des bonnes pratiques Snowflake. [docs.snowflake.com]

✔ DROP DATABASE

Supprimer une base et tout son contenu.

5. Information Schema dans chaque Database

Chaque database contient automatiquement un schema INFORMATION_SCHEMA, contenant :

  • des vues sur les objets de la base,
  • des vues sur certains objets du compte,
  • des table functions autour de l'historique et de l'usage.

→ Très utile pour l'audit, l'observabilité et la gouvernance. [docs.snowflake.com]

6. Points clés sur les databases Snowflake

✔ Pas de limite sur le nombre de bases, schémas ou objets

[docs.snowflake.com]

✔ Stockage indépendant du compute

Les databases bénéficient de l'architecture Snowflake (compute & storage séparés).

✔ Database = unité de réplication

Les bases peuvent être répliquées entre régions / plateformes cloud.

✔ Database = unité de partage (Secure Data Sharing)

On peut partager une database ou un de ses schémas via shares.
