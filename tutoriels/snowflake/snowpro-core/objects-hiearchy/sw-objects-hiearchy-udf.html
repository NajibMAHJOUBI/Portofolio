Snowflake - User-Defined Functions (UDF)

Niveau Intermédiaire
Mis à jour: Février 2026 Durée: 20 min Difficulté: Intermédiaire
Snowflake UDF Python

Introduction

Les User‑Defined Functions (UDF) permettent d'étendre Snowflake en écrivant vos propres fonctions, dans des langages variés, pour exécuter des opérations non couvertes par les fonctions système.

1. Définition et objectif des UDFs

Une UDF :

  • est une fonction personnalisée que vous créez dans Snowflake via SQL, Java, Python, or Scala
  • retourne toujours une valeur (un scalaire ou un ensemble de lignes dans le cas des UDTFs) ;
  • permet d'implémenter des calculs ou transformations non disponibles via les fonctions intégrées ;
  • est réutilisable dans toutes vos requêtes comme une fonction native.

Les UDF sont idéales pour :
  • encapsuler des calculs complexes ;
  • appliquer des règles métier propres à l'organisation ;
  • enrichir la bibliothèque de fonctions Snowflake.

2. Variantes de User-Defined Functions

Snowflake supporte plusieurs types d'UDFs :

1. Scalar UDFs

  • aussi appelées UDF tout court ;
  • retournent une valeur unique pour chaque ligne d'entrée.

2. UDAF — User-Defined Aggregate Functions

  • opèrent sur plusieurs lignes et retournent un seul résultat : SUM, AVG, MIN, MAX personnalisés ;
  • peuvent implémenter des calculs statistiques avancés.

3. UDTF — User-Defined Table Functions

  • retournent un tableau (plusieurs lignes) pour chaque ligne d'entrée ;
  • idéal pour exploser, transformer ou enrichir des données.

4. Vectorized UDFs / Vectorized UDTFs

  • fonctionnent sur des batches de données sous forme de Pandas DataFrames ;
  • accélèrent les opérations à haute volumétrie.

3. Langages supportés pour les UDFs

Snowflake permet d'écrire la logique (handler) dans plusieurs langages :

Langage Types de fonctions
JavaUDF, UDTF
JavaScriptUDF, UDTF
PythonUDF, UDAF, UDTF, Vectorized UDF/UDTF
ScalaUDF
SQLUDF, UDTF
Tous les UDFs (quel que soit le langage) sont déclarés via SQL, même si leur logique est écrite en Python/Java/etc.

4. UDF vs Stored Procedure — Différences importantes

Snowflake indique explicitement qu'une UDF ressemble à une procédure mais diffère sur plusieurs aspects clés :

✔ UDF

  • retourne une valeur directement ;
  • utilisée dans des expressions SQL ;
  • stateless, adaptée aux calculs.

✔ Stored Procedure

  • retourne 0 ou 1 valeur générique (souvent un VARIANT) ;
  • peut exécuter des opérations DDL / DML complexes ;
  • peut gérer des transactions, des erreurs, du branching.

5. Comment les UDFs s'exécutent

  • L'utilisateur appelle la fonction dans une requête SQL.
  • Snowflake appelle le handler (code Python/Java/etc.) avec les arguments.
  • Le résultat est retourné à Snowflake puis au client.
  • Les UDFs s'exécutent dans un environnement sécurisé et isolé.

6. Outils pour créer et gérer des UDFs

  • SQL (CREATE FUNCTION)
  • Snowpark API (Java, Python, Scala)
  • Snowsight
  • Snowflake CLI
  • VS Code Extension

8. Cas d'usage recommandés

Les UDFs sont un bon choix pour :

  • étendre les fonctions intégrées,
  • encapsuler des calculs organisationnels réutilisables,
  • normaliser des transformations,
  • réaliser masquage/logique métier personnalisée,
  • traiter semi‑structuré via Python.

9. Résumé

  • UDF = retourne toujours une valeur (scalaire ou table pour UDTF).
  • Les handlers peuvent être écrits en Python, Java, JavaScript, SQL, Scala.
  • Les UDAF opèrent sur plusieurs lignes.
  • Les vectorized UDFs utilisent Pandas DataFrames.
  • Les UDF sont créées avec CREATE FUNCTION.
  • Différence majeure : UDF ≠ Stored Procedure.
  • Les UDFs sont exécutées dans un runtime géré, sécurisé, isolé.
  • Les UDFs peuvent être appelées comme n'importe quelle fonction SQL intégrée.
