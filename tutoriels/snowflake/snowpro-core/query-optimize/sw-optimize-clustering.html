1. Micro-partitions & Data Clustering

Source : Micro-partitions & Data Clustering

✔ Qu'est‑ce qu'une micro-partition ?

  • Unité de stockage fondamentale dans Snowflake : 50 à 500 MB non compressés.
  • Organisée en format columnar, immuable, et générée automatiquement lors du chargement des données.

✔ Quel lien avec le clustering ?

  • Lors de l'ingestion, les données sont naturellement ordonnées selon l'ordre d'insertion → natural clustering.
  • Snowflake stocke pour chaque micro-partition des métadonnées : min/max, distinct count, informations de filtrage.
  • Ces métadonnées permettent le pruning : ignorer les micro-partitions non pertinentes.
✔ Enjeux du data clustering

Le clustering permet :

  • de conserver une organisation logique des valeurs,
  • de maximiser l'efficacité du pruning,
  • d'optimiser les performances sur tables volumineuses.

Lorsque le clustering naturel se dégrade (notamment via DML sur de grandes tables), les requêtes deviennent plus lentes → nécessité d'un clustering key.

2. Clustering Keys (Cluster By)

Source : Clustering Keys & Clustered Tables

✔ Définition

Un clustering key est un ensemble de colonnes ou expressions utilisées pour co‑localiser les données dans les micro-partitions.

✔ Quand en définir un ?

Indicateurs :

  • Les requêtes sur la table deviennent plus lentes.
  • Le clustering depth du tableau est élevé.

✔ Bénéfices

Pour les très grandes tables (>1 To ou plusieurs milliards de lignes) :

  • Meilleur pruning, donc scans plus courts.
  • Meilleure compression des colonnes.

✔ Définition / modification

À la création :

CREATE TABLE t (...) CLUSTER BY (col1, col2);

Après création :

ALTER TABLE t CLUSTER BY (col1, col2);

✔ Attention (SnowPro piège classique)

Snowflake insiste : les clustering keys ne sont pas toujours recommandés. Ils sont adaptés uniquement si :

  • la table est très volumineuse,
  • les requêtes filtrent souvent sur les mêmes colonnes,
  • les gains de performance > coûts de maintenance.

3. Automatic Reclustering

Source : Automatic Clustering Service

✔ Qu'est‑ce que l'Automatic Reclustering ?

Un service Snowflake qui gère automatiquement et continuellement le reclustering des tables ayant un clustering key.

✔ Avantages

  • Zéro maintenance : Vous n'avez plus à surveiller manuellement l'état du clustering.
  • Snowflake reclustre uniquement si nécessaire.
  • Pas de warehouse à spécifier → effectué via compute serverless.

✔ Contrôle total

Pause / reprise :

ALTER TABLE t SUSPEND RECLUSTER;
ALTER TABLE t RESUME RECLUSTER;

Supprimer le clustering key : → Arrête toute activité de reclustering.

✔ Non‑blocking

Le reclustering n'interrompt pas les DML.

✔ Comment est‑il déclenché ?

Snowflake ne reclustre que si cela apporte un bénéfice concret → pas de compute inutile.

✔ Activateur implicite

Définir un clustering key suffit à activer Automatic Clustering.

⚠️ Exception : si le tableau est issu d'un CLONE, l'auto‑reclustering est désactivé par défaut.

5. Points clés à retenir pour SnowPro Core

✔ Micro-partitions

  • Automatiques, petites, colonaires, immuables.
  • Métadonnées → pruning.

✔ Clustering Keys

  • Optimisation pour très grandes tables.
  • Améliorent le pruning mais coûtent cher si DML fréquent.
  • À utiliser sélectivement.

✔ Automatic Reclustering

  • Gère le clustering en continu.
  • Ne bloque pas les DML.
  • Coûts en credits via serverless compute.

6. Mini‑FAQ typique des questions d'examen

❓ Faut-il définir un clustering key pour toutes les tables ?

→ Non. Seulement pour les tables volumineuses avec des patterns de filtrage stables.

❓ Automatic Clustering bloque‑t‑il les requêtes ?

→ Jamais.

❓ Le clustering améliore‑t‑il le JOIN ?

→ Indirectement : en améliorant le pruning des tables filtrées.

❓ Le reclustering commence‑t‑il immédiatement après un CLUSTER BY ?

→ Parfois non : Snowflake l'exécute uniquement si nécessaire.
