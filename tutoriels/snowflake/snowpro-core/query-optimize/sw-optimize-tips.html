Snowflake Performance Optimization

✅ 1. Vue d'ensemble des thèmes Performance Snowflake

La page Performance Optimization – Guides Overview regroupe l'ensemble des documents essentiels pour comprendre comment optimiser les performances dans Snowflake.

Snowflake regroupe plusieurs axes d'optimisation :

  • Analyse des exécutions passées
  • Optimisation des requêtes
  • Optimisation des warehouses
  • Optimisation du stockage
  • Analyse de charges (workloads)
  • Automatisation avec Snowflake Optima

✅ 2. Exploring Execution Times

Permet d'obtenir des informations sur les performances historiques des requêtes.

✔ Deux méthodes :

  • Via Snowsight (Query History, Query Profile)
  • Via SQL sur ACCOUNT_USAGE (ex. QUERY_HISTORY)

✔ Exemples d'usage :

  • Identifier les requêtes les plus lentes
  • Suivre l'évolution des performances dans le temps
  • Vérifier l'impact d'une optimisation (clustering, SO, warehouse size…)
Ce thème est très fréquent en SnowPro Core, car il valide votre capacité à diagnostiquer la performance.

✅ 3. Optimizing Query Performance

✔ Les options d'optimisation comprennent :

  • Réécriture du SQL
  • Utilisation de prédicats efficaces (SARGables)
  • Pruning grâce aux micropartitions
  • Matérialisation (materialized views)
  • Search Optimization (service optionnel)
✔ Points classiques dans l'examen :
  • Comment réduire les bytes scanned ? → via pruning, partitions logiques, filtrage efficace.
  • Quand utiliser SO ? → lorsque les recherches sont très sélectives mais que les données ne sont pas bien corrélées.

✅ 4. Optimizing Warehouses for Performance

✔ Concepts clés :

  • Taille du warehouse = parallélisme = vitesse potentielle
  • Multi‑cluster warehouse = améliore la concurrency
  • Query Acceleration Service (QAS) = accélération ciblée pour certaines requêtes
✔ À connaître pour SnowPro Core :
  • Quand augmenter la taille ? → tâches lourdes : scans massifs, large joins
  • Quand activer multi-cluster ? → file d'attente (queued), haute concurrence
  • QAS = utile pour charge irrégulière et requêtes bloquantes

✅ 5. Optimizing Storage for Performance

✔ Trois axes principaux :

  • Regrouper les données similaires
  • Structures optimisées (clustering keys éventuelles pour tables larges)
  • Choisir entre :
    • Automatic Clustering
    • Search Optimization Service
    • Materialized Views
✔ Ce qu'on attend de vous en SnowPro Core :
  • Comprendre quand utiliser chacune de ces fonctionnalités
  • Savoir que Snowflake optimise déjà le stockage automatiquement (micropartitions, colonnes, compression)

✅ 6. Analyzing Query Workloads with Performance Explorer

✔ Dans Snowsight :

Performance Explorer permet :

  • De visualiser les métriques SQL en temps réel
  • De suivre les tendances (latence, concurrency, bytes scanned, etc.)

✔ Ce que vous devez savoir :

  • Très utile pour corréler performance & workload
  • Permet d'identifier des pics d'activité ou des requêtes coûteuses
  • Peut remplacer l'utilisation d'ACCOUNT_USAGE pour des analyses plus visuelles

✅ 7. Snowflake Optima

Fonctionnalité d'optimisation automatisée.

✔ Ce que fait Optima :

  • Analyse continue des patterns de workload
  • Applique automatiquement les stratégies les plus efficaces
✔ Pourquoi c'est important pour SnowPro Core :
  • Snowflake met en avant l'idée "performance by default"
  • Optima réduit la nécessité de tuning manuel complexe
  • Vous devez connaître les bénéfices, mais pas les détails internes

✅ 8. Managing Cost in Snowflake

Inclus dans la page car performance et coûts sont liés.

✔ Concepts clés :

  • Optimisation warehouse = impact direct sur l'usage de crédits
  • Réduction des scans = moins de compute
  • Meilleur clustering = réduction des coûts de recherche optimisée
