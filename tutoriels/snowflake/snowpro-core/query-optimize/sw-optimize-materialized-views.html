Snowflake Materialized Views Performance

✅ 1. Qu'est‑ce qu'une vue matérialisée ?

Source : Working with Materialized Views [docs.snowflake.com]

Une vue matérialisée est un ensemble de données pré‑calculé à partir d'une requête SQL, stocké physiquement par Snowflake.

Elle se comporte comme une table optimisée pour des requêtes répétitives. [docs.snowflake.com]

✔ Points clés

  • Les données sont pré‑calculées puis stockées.
  • Les requêtes sur une MV sont plus rapides que celles sur la table source.
  • Particulièrement efficace pour agrégations, projections, sélections lourdes.
  • Les données sont toujours à jour (maintenance automatique). [docs.snowflake.com]

✅ 2. Quand créer une vue matérialisée ?

Snowflake recommande de créer une MV lorsque : [docs.snowflake.com]

✔ Situations optimales

  • Le résultat contient peu de lignes/colonnes vs la table de base.
  • Le résultat nécessite :
    • Analyse de données semi‑structurées,
    • Calculs d'agrégats coûteux.
  • La requête cible une external table (moins performante).
  • La table source ne change pas trop fréquemment.
❗ Risque important

Les MVs génèrent des coûts de maintenance → toujours évaluer si les gains de performance compensent les coûts. [docs.snowflake.com]

✅ 3. Avantages des vues matérialisées

Snowflake apporte des avantages significatifs : [docs.snowflake.com]

✔ Performance

  • Accélère les requêtes répétitives ou complexes.
  • Requêtes plus rapides que sur la table source.

✔ Maintenance automatique

  • Processus de mise à jour transparent après chaque DML (INSERT/UPDATE/DELETE) sur la table source.
  • Snowflake décide automatiquement de compléter ou combiner :
    • Parties à jour de la MV
    • Dernières données de la table source si nécessaire

✔ Données toujours synchronisées

Aucune opération manuelle nécessaire.

⚠ Coûts
  • La maintenance consomme des credits compute.
  • Nécessite Enterprise Edition. [docs.snowflake.com]

✅ 4. Limites importantes (SnowPro Core)

Certaines limitations sont dans la section détaillée mais non affichées dans l'extrait ; cependant la doc les signale dans la page (limitations des SELECT, etc.) via "Limitations on the select_statement". [docs.snowflake.com]

  • Certaines expressions SQL ne sont pas autorisées dans la requête de définition.
  • Les MVs ne supportent pas les JOIN complexes (selon la version).

✅ 5. Création d'une vue matérialisée – Syntaxe essentielle

Source : CREATE MATERIALIZED VIEW [docs.snowflake.com]

✔ Syntaxe générale

CREATE MATERIALIZED VIEW mv_name
AS
SELECT ...
FROM base_table;

✔ Points importants

La commande accepte :

  • SECURE (vue sécurisée)
  • CLUSTER BY (obligatoire si column_list fourni)
  • COPY GRANTS
  • Masquage (MASKING POLICY), Row Access Policy, etc.
  • AGGREGATION POLICY [docs.snowflake.com]

✅ 6. Maintenance & Actualisation

Snowflake maintient automatiquement les MVs : [docs.snowflake.com]

✔ Fonctionnement

Si la MV n'est pas complètement à jour au moment de la requête :

  • → Snowflake met à jour la MV
  • → Ou combine parts up-to-date + données de la base
✔ Impacts coûts

Maintenance = compute serverless ⇒ facturation à chaque mise à jour.

✅ 9. Bonnes pratiques SnowPro

✔ À FAIRE

  • Utiliser pour requêtes répétitives sur grosses tables.
  • Utiliser si les résultats sont petits ou complexes à calculer.
  • Évaluer volume de DML sur la table source.
  • Utiliser SYSTEM$ESTIMATE_QUERY_ACCELERATION ou Query Profile pour analyser les gains.

❗ À ÉVITER

  • MV sur tables avec haut taux de changements (maintenance très coûteuse).
  • MV pour petites tables (pas de gain).
  • MV sur queries peu ré-utilisées.
