Snowflake QAS Performance

1. Qu'est‑ce que le Query Acceleration Service ?

Source officielle : Using the Query Acceleration Service (QAS)

Le Query Acceleration Service (QAS) est une fonctionnalité Enterprise Edition (ou +) permettant d'accélérer certaines requêtes en offloadant une partie du traitement vers des ressources serverless supplémentaires.

✔ Objectif :

Accélérer les requêtes « outliers » – celles qui consomment anormalement plus de ressources que la majorité des requêtes d'un même warehouse.

✔ Comment ?

  • Le QAS ajoute dynamiquement du compute supplémentaire.
  • Il traite en parallèle des étapes coûteuses : scanning, filtering, traitements intensifs.

✔ Bénéfices

  • Réduit le temps mur (wall‑clock) des scans.
  • Améliore la stabilité et les performances globales du warehouse.
  • Limite l'impact négatif des requêtes lourdes sur les autres utilisateurs.

2. Cas d'usage typiques

Le QAS est particulièrement utile pour les workloads suivants :

  • Ad-hoc analytics (requêtes imprévisibles)
  • Requêtes avec volumes de données variables et imprévisibles
  • Requêtes avec gros scans + filtres sélectifs
Ces workloads génèrent souvent des situations où une seule requête bloque ou ralentit toutes les autres : QAS évite cela.

3. SQL commandes compatibles avec QAS

Le service peut accélérer les commandes :

  • SELECT
  • INSERT
  • CREATE TABLE AS SELECT (CTAS)
  • COPY INTO <table>
⚠️ Le QAS peut accélérer l'intégralité d'une requête, ou uniquement un sous‑ensemble (subqueries, clauses), selon l'éligibilité.

4. Comment activer le Query Acceleration Service ?

📌 Activer lors de la création du warehouse

CREATE WAREHOUSE my_wh
    WITH ENABLE_QUERY_ACCELERATION = true;

📌 Activer sur un warehouse existant

ALTER WAREHOUSE my_wh
    SET ENABLE_QUERY_ACCELERATION = true;

📌 Vérifier l'état du QAS

SHOW WAREHOUSES LIKE 'my_wh'
->> SELECT "name", "enable_query_acceleration", "query_acceleration_max_scale_factor"
FROM $1;

Résultat typique :

  • enable_query_acceleration = TRUE
  • query_acceleration_max_scale_factor = 8
Note importante : Le QAS dépend de la disponibilité du serveur → l'accélération peut varier.

5. Coûts associés

L'utilisation du QAS augmente le taux de consommation de crédits.

✔ Pourquoi ?

Parce que Snowflake mobilise des ressources serverless additionnelles, facturées en plus du warehouse.

✔ Comment mesurer le coût du QAS ?

→ Via QUERY_ATTRIBUTION_HISTORY (colonne credits_used_query_acceleration) dans ACCOUNT_USAGE.

6. Bonnes pratiques (SnowPro Core)

✔ QAS ≠ remplacer le tuning SQL

Il accélère la performance ponctuelle mais ne corrige pas :

  • des prédicats inefficaces,
  • un mauvais modèle de données,
  • des requêtes non optimisées.

✔ Préférer QAS lorsque :

  • Très peu de requêtes lourdes mais importantes
  • L'augmentation de taille du warehouse serait trop coûteuse
  • L'activité est très variable (bursty)

✔ Ne pas activer QAS si :

  • Le warehouse est déjà trop petit → mieux l'augmenter d'abord
  • La lenteur vient du réseau, de jointures non optimisées, ou du modèle de tables

8. Conclusion

Le Query Acceleration Service est un outil puissant dans Snowflake pour accélérer ponctuellement les requêtes gourmandes sans redimensionner un warehouse.

Cela permet une performance stable, une réduction des outliers, et une meilleure gestion des workloads imprévisibles.
