Snowflake Hybrid Tables Cloud

1. Définition & Objectif

Les Hybrid Tables sont un type de table Snowflake conçu pour des workloads transactionnels nécessitant :

  • Faible latence
  • Haut débit
  • Accès aléatoires en lecture/écriture
  • Contraintes d'intégrité (unique + référentielle)

Elles reposent sur un moteur row-based avec row locking, contrairement aux tables standard qui sont orientées colonnes.

Elles servent notamment pour des workloads Unistore, mêlant transactionnel + analytique.

Cas d'usage typiques

  • Gestion de métadonnées d'applications ou workflows massivement parallèles
  • Serving faible latence de données pré‑agrégées (API/UI)
  • Applications transactionnelles légères (états, paniers, sessions)

2. Architecture et fonctionnement

Les Hybrid Tables s'intègrent nativement dans l'architecture Snowflake existante :

  • Utilisent les mêmes services de cloud, warehouses et moteurs de requêtes
  • Permettent des transactions atomiques entre tables hybrides et standard
  • Supportent les fonctionnalités de gouvernance Snowflake

Stockage hybride (Hybrid Storage Engine)

  • Stockage primaire : Row Store
    • Optimisé pour les opérations transactionnelles
  • Stockage secondaire : Object Storage (copie asynchrone)
  • Caches en colonnes sur warehouse → meilleures performances analytiques.

Le Query Optimizer choisit automatiquement la meilleure source (row store, object storage, columnar cache).

3. Création de Hybrid Tables

Nécessite :

  • Entrepôt Snowflake en cours d'exécution (sinon erreur)

Méthodes de création

1️⃣ CREATE HYBRID TABLE

CREATE OR REPLACE HYBRID TABLE application_log (
    id NUMBER PRIMARY KEY AUTOINCREMENT,
    col1 VARCHAR(20),
    col2 VARCHAR(20) NOT NULL
);

2️⃣ CREATE HYBRID TABLE … AS SELECT (CTAS)

CREATE OR REPLACE HYBRID TABLE dept_employees (
    employee_id INT PRIMARY KEY,
    department_id VARCHAR(200)
)
AS SELECT employee_id, department_id FROM company_employees;

3️⃣ CREATE HYBRID TABLE … LIKE

Pour répliquer une structure existante.

4. Performance & Chargement de données

Stockage

  • Footprint plus important que les tables standards
  • Moins de compression que les tables colonnes

Bulk Loading optimisé

Effectif si la table est :

  • vide
  • ou créée via CTAS

Méthodes supportées :

  • CTAS
  • COPY INTO
  • INSERT INTO … SELECT

Vitesses usuelles : jusqu'à 1M lignes/minute (variable selon structure).

5. Contraintes supportées

Les Hybrid Tables appliquent réellement :

  • PRIMARY KEY
  • UNIQUE
  • FOREIGN KEY (avec enforcement)

Ce qui les rend adaptées au transactionnel, contrairement aux tables Snowflake standard.

6. Meilleures pratiques (Best Practices)

A. Drivers & Connectivité

Utiliser un driver compatible (exemples) :

  • Python Connector ≥ 3.1.0
  • JDBC ≥ 3.13.31
  • SnowSQL ≥ 1.2.28

Les versions antérieures peuvent ne pas accéder aux hybrid tables.

B. Connexions

  • Utiliser connection pooling et des connexions longues
  • Éviter les reconnections fréquentes (surcoût de latence)

C. Requêtage

  • Snowsight n'est pas représentatif des performances réelles
    • Latence plus élevée qu'avec drivers programmatiques

D. Bulk Loading

  • Préférer charger dans des tables fraîchement créées pour bénéficier du mode optimisé

E. Indexation

Même si Snowflake gère internement, le design des clés (PRIMARY/FOREIGN) impacte les performances.

F. Monitoring

Points clés :

  • Caching
  • Warm-up
  • Monitoring des quotas & throttling

7. Limitations importantes

  • Fonctionnalité disponible uniquement dans AWS & Azure
  • Non disponible en Chine
  • Stockage plus volumineux que les tables colonnes
  • Certaines fonctionnalités Snowflake restent non supportées ou limitées (à vérifier selon version)
