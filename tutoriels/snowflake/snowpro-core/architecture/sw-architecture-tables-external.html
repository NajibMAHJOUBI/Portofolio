Snowflake - External Tables

Niveau Débutant
Mis à jour: Février 2026 Durée: 10 min Difficulté: Intermédiaire
Snowflake Data Engineering Cloud

Objectifs du tutoriel

Les external tables permettent de requêter des données stockées hors de Snowflake (dans un external stage), comme si elles étaient stockées dans une table Snowflake — sans déplacer les fichiers.

1. Définition

Une external table est un objet Snowflake qui référence des fichiers stockés dans un external stage (S3, GCS, Azure Blob), tout en permettant de les requêter via SQL.

Snowflake ne stocke pas les données des external tables :

  • la donnée reste dans le storage externe
  • Snowflake stocke uniquement des métadonnées au niveau fichier (filename, version, propriétés).

2. Caractéristiques principales

✔ Read-only

Les external tables sont en lecture seule :

  • Aucun DML possible (INSERT, UPDATE, DELETE)
  • Elles servent uniquement à interroger et joindre les données.

✔ Formats supportés

Supporte tous les formats compatibles avec COPY INTO sauf XML.

✔ Performance

  • Les requêtes peuvent être plus lentes que sur des Snowflake tables natives.
  • Pour accélérer : créer une materialized view sur l'external table.
▶ Recommandation : Snowflake recommande, pour Parquet, de préférer Iceberg tables (plus performantes).

3. Sécurité & connectivité

L'external stage peut être configuré avec outbound private connectivity pour renforcer la sécurité (accès privé aux fichiers).

4. Comportement en cas d'erreur

Si Snowflake rencontre une erreur en scannant un fichier :

  • le fichier est ignoré
  • la requête continue avec les fichiers suivants
  • résultat partiel possible (si scan incomplet).

5. Schéma sur lecture (schema-on-read)

Lorsque Snowflake lit des external tables, il applique un schema-on-read, c'est-à-dire que :

  • Snowflake lit les fichiers tels quels
  • la structure n'a pas besoin d'être connue à l'avance

Toutes les external tables incluent automatiquement :

  • VALUE (colonne VARIANT représentant une ligne du fichier)
  • METADATA$FILENAME
  • METADATA$FILE_ROW_NUMBER
⚠ Attention : un SELECT * retourne toujours la colonne VALUE.

6. Virtual Columns

Si on connaît la structure des fichiers, on peut créer des colonnes virtuelles dans l'external table, via des expressions appliquées sur :

  • VALUE
  • METADATA$FILENAME
  • METADATA$FILE_ROW_NUMBER

Snowflake impose un type checking strict : les types des colonnes virtuelles doivent correspondre aux données dans les fichiers.

7. Quand utiliser les external tables ?

✔ Utilisations idéales

  • Interroger un data lake directement (S3/GCS/Azure Blob)
  • Joindre datasets externes sans ingestion préalable
  • Utiliser Snowflake comme moteur SQL sur des fichiers non chargés

✔ À éviter

Si vous avez besoin :

  • de DML (INSERT, UPDATE, DELETE)
  • de performance élevée → préférer Snowflake tables ou Iceberg tables
