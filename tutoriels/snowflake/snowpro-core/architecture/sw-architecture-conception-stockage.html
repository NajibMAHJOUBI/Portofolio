1. Comprendre le stockage Snowflake : Active, Time Travel, Fail-safe

Les "Storage Considerations" expliquent comment Snowflake gère le stockage des données et comment optimiser les coûts, notamment dans le cadre du Continuous Data Protection (CDP) : Time Travel + Fail-safe.

Snowflake facture le stockage quelle que soit la phase du cycle de vie des données :

  • Active : données actuelles.
  • Time Travel : anciennes versions conservées après un UPDATE / DELETE.
  • Fail-Safe : protection finale pour récupération gérée par Snowflake.

➡️ Toutes ces phases sont facturées, car Snowflake stocke les micro‑partitions correspondant à chaque état. [docs.snowflake.com]

Important :

  • Le stockage Time Travel + Fail-safe peut devenir significatif selon le volume de changements DML.
  • Les éléments supprimés restent stockés jusqu'à sortie du Fail-safe. [docs.snowflake.com]

2. Impact des opérations INSERT / COPY / Snowpipe sur le stockage

Lors des chargements (INSERT, COPY, Snowpipe), Snowflake peut effectuer une défragmentation des micro‑partitions :

  • → cela génère de nouvelles micro‑partitions
  • → et place les anciennes dans Time Travel / Fail-safe

⇒ d'où une augmentation temporaire du stockage facturé. [docs.snowflake.com]

3. Comment analyser et suivre le stockage

Snowflake met à disposition plusieurs moyens :

A. Niveau compte

(Account admin uniquement)

Via Snowsight :

Admin → Cost Management → Consumption

→ donne la consommation moyenne de stockage pour :

  • bases,
  • stages internes,
  • données en Fail-safe. [docs.snowflake.com]

B. Niveau table

Trois méthodes :

  • Snowsight → Catalog → Database Explorer → Tables
  • SHOW TABLES
  • TABLE_STORAGE_METRICS dans INFORMATION_SCHEMA ou ACCOUNT_USAGE [docs.snowflake.com]

Pourquoi TABLE_STORAGE_METRICS est le meilleur ?

Il fournit le détail en colonnes :

  • ACTIVE_BYTES
  • TIME_TRAVEL_BYTES
  • FAILSAFE_BYTES [docs.snowflake.com]

… ainsi que la distinction entre :

  • Owned storage
  • Referenced storage (ex : clones) [docs.snowflake.com]

4. Clonage et stockage

Lorsqu'une table est clonée :

  • Snowflake ne duplique pas les données (zero‑copy).
  • Le clone "référence" les micro‑partitions de la source → referenced storage.
  • Le stockage augmente uniquement en cas de modifications ultérieures. [docs.snowflake.com]

5. Stockage des fichiers mis en stage (staged file storage)

Pour supporter les chargements MASSIFS (COPY INTO, Snowpipe), Snowflake utilise des stages où sont stockés les fichiers temporaires avant ingestion. [docs.snowflake.com]

Ces stages :

  • font partie du stockage facturé,
  • doivent être surveillés et nettoyés régulièrement pour éviter les coûts inutiles.
