Snowflake - Apache Iceberg™ Tables

Niveau Intermédiaire
Mis à jour: Février 2026 Durée: 20 min Difficulté: Intermédiaire
Snowflake Apache Iceberg Cloud

1. Définition & Objectif

Les Iceberg Tables dans Snowflake combinent :

  • La performance et les sémantiques de requête des tables Snowflake
  • Avec un stockage externe dans votre propre cloud (S3, GCS, Azure)

Elles utilisent le format Apache Iceberg, qui offre :

  • ACID transactions
  • Évolution de schéma
  • Hidden partitioning
  • Table snapshots

Elles sont idéales pour :

  • Les data lakes existants
  • Les cas où les données doivent rester hors Snowflake

2. Architecture & Fonctionnement

Stockage

  • Données et metadata stockées dans un stockage cloud externe (S3, GCS, Azure) que vous gérez.
  • Pas de stockage Snowflake → pas de coût de stockage Snowflake.
  • Pas de Fail-safe pour Iceberg tables.

External Volume

Un external volume est un objet Snowflake permettant :

  • De connecter Snowflake au stockage externe
  • D'y stocker les IAM (permissions cloud)
  • De desservir une ou plusieurs Iceberg tables

Iceberg Catalog

Le catalog gère les pointeurs vers la metadata Iceberg.

Il doit permettre :

  • Stocker le pointeur de metadata
  • Assurer des opérations atomiques

Types possibles :

  • Snowflake Catalog (Snowflake‑managed)
  • External Catalog (AWS Glue, etc.)

3. Types d'Iceberg Tables dans Snowflake

1) Snowflake‑managed Iceberg tables

  • Snowflake sert de catalog
  • Vous fournissez :
    • un external volume
    • un répertoire base
  • Supportent le DML complet : INSERT, MERGE, UPDATE, DELETE, TRUNCATE
  • Supportent Snowpipe, COPY INTO…

2) Externally‑managed Iceberg tables

  • Le catalog externe (Glue, Nessie, etc.) est utilisé
  • Nécessite metadata refresh régulier
  • Prise en charge du DML limitée selon architecture

4. Création d'une Iceberg Table

Nécessite :

  • Un warehouse Snowflake actif

Exemple Snowflake‑managed

CREATE OR REPLACE ICEBERG TABLE my_iceberg_table (
    boolean_col boolean,
    int_col int,
    long_col long
)
PARTITION BY (int_col)
CATALOG = 'SNOWFLAKE'
EXTERNAL_VOLUME = 'my_ext_vol'
BASE_LOCATION = 'my/relative/path/from/extvol';

Variantes

CREATE ICEBERG TABLE … AS SELECT
CREATE ICEBERG TABLE … LIKE

External catalog

Nécessite :

  • External volume
  • Catalog integration
  • Refresh initial automatique

5. Requêtage & DML

Privileges nécessaires

  • USAGE sur database + schema
  • SELECT sur la table

DML supporté

Pour Snowflake‑managed tables :

  • INSERT
  • UPDATE
  • MERGE
  • DELETE
  • TRUNCATE

Attention aux orphan files

En cas de rollback, des fichiers Parquet peuvent rester dans le storage sans être référencés → orphan files.

Si mismatch sur métriques de stockage, contacter Snowflake Support.

6. Refresh & Metadata

Metadata & snapshots

  • Snowflake génère automatiquement la metadata dans /metadata pour Snowflake‑managed tables.

External catalog → Refresh obligatoire

  • Après opérations de maintenance Iceberg (snapshot expiration, compaction, etc.)
  • Utiliser ALTER ICEBERG TABLE … REFRESH

7. Optimisation & Best Practices

A. Gestion des External Volumes

  • Un seul volume peut héberger plusieurs tables
  • Mais créer plusieurs volumes permet d'isoler sécurité & organisation

B. Options recommandées pour Parquet (COPY/Snowpipe)

  • BINARY_AS_TEXT = FALSE
  • USE_LOGICAL_TYPE = TRUE
  • USE_VECTORIZED_SCANNER = TRUE
  • REPLACE_INVALID_CHARACTERS = TRUE

C. Refresh des tables externes

  • Faire des refresh fréquents pour maintenir les performances
  • Alignement avec compaction & expiration de snapshots

D. Statistiques complètes dans Parquet

Indispensables pour :

  • Optimiser les joins
  • Éviter join explosion

Statistiques nécessaires :

  • min/max
  • NDV (distinct values)
  • NULL counts

E. Taille de warehouse

Augmenter la taille du warehouse améliore :

  • Lecture des manifest files
  • Traitement des statistiques externes

8. Iceberg v3 (Preview) – Notions à connaître

  • Snowflake supporte le format Iceberg v3 en preview
  • Nouveaux types supportés : geography, geometry, nanosecond timestamps, variant
  • Peut choisir la version via :
    • ICEBERG_VERSION_DEFAULT paramètre
    • ICEBERG_VERSION = 3 dans CREATE ICEBERG TABLE
  • Attention : downgrade impossible
  • Tous les moteurs doivent supporter v3 avant migration
