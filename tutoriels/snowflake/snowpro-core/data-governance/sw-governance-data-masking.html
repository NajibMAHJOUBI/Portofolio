Niveau Intermédiaire

Snowflake Column-Level Security Data Masking

1. Column-Level Security – Introduction

La column-level security dans Snowflake permet de protéger des colonnes spécifiques contenant des données sensibles via des politiques de masquage (masking policies).

Elle fait partie des fonctionnalités de gouvernance Snowflake.

✔ Objectif

  • Masquer ou révéler dynamiquement la valeur d'une colonne selon l'identité du requérant.
  • Empêcher l'exposition de données sensibles comme : PII, PHI, PCI.

✔ Basé sur les Masking Policies

  • Une masking policy est un objet SQL appliqué à une colonne (table ou view).
  • Elle définit comment la colonne est masquée selon :
    • le rôle,
    • l'utilisateur,
    • le contexte de requête.

2. Dynamic Data Masking (DDM)

Le Dynamic Data Masking est le mécanisme principal de column-level security.

✔ Fonctionnement

Lorsqu'une requête accède à une colonne masquée, Snowflake :

  • Évalue la masking policy
  • Détermine la variante affichée (réelle, partielle, nulle…)

✔ Exemple de logique

  • Rôle autorisé → valeur réelle
  • Rôle non autorisé → NULL ou version masquée
  • Développeur → vue tronquée
  • Auditeur → masquage partiel

✔ Types de masques typiques

  • Masquage complet
  • Masquage partiel (ex: xxxx-xxxx-1234)
  • Tokenisation (avec ou sans externalisation)
  • Nullification

DDM constitue la fonctionnalité recommandée pour protéger les données sensibles sans dupliquer les tables.

3. External Tokenization

L'external tokenization permet d'utiliser des mécanismes de tokenisation hors Snowflake, via un fournisseur externe.

✔ Objectif

  • Tokeniser/dé‑tokeniser les valeurs en dehors de Snowflake.
  • Conserver les données sensibles en dehors du Data Cloud.
  • Respecter des politiques internes strictes ou des réglementations exigeant tokenisation externe.

✔ Fonctionnement général

  • Snowflake envoie la valeur à tokeniser à un service externe (appel via external functions).
  • Le service retourne un token.
  • Les tokens sont stockés dans Snowflake, pas les données sensibles.

✔ Avantages

  • Conformité renforcée
  • Gestion centralisée de la tokenisation
  • Intégration avec masking policies permettant :
    ➜ masquage → tokenisation externe → restitution contrôlée

4. Tag-Based Masking Policies

Les tag-based masking policies permettent d'automatiser l'application de politiques de masquage grâce aux tags.

✔ Principe

  1. Créer une masking policy
  2. Créer un tag
  3. Associer la masking policy au tag
  4. Appliquer le tag à une colonne
    → La masking policy s'applique automatiquement.

✔ Avantages majeurs

  • Centralisation : une politique peut être appliquée à des centaines d'objets via un tag unique.
  • Scalabilité : en ajoutant simplement un tag à une colonne, elle est immédiatement masquée.
  • Consistance : les colonnes portant le même tag appliquent la même gouvernance.
  • Couplage naturel avec la classification sensible :
    Une fois les colonnes classifiées, leurs tags sont utilisés pour déclencher des politiques de masquage.
Tag inheritance

Si un tag est défini sur une table, il est hérité par les colonnes, ce qui active automatiquement les masking policies correspondantes.

5. Synthèse comparative

Fonction Objectif Appliqué où ? Automatisable ?
Masking policies Masquer dynamiquement Colonne Oui (tag-based)
Dynamic Data Masking Masquage déterminé par contexte Colonne Oui
External Tokenization Tokeniser/enlever les données sensibles hors Snowflake Colonne / pipeline Oui (via external functions)
Tag-Based Masking Gouvernance centralisée en appliquant un tag Colonne / table Oui

6. Points clés SnowPro Core

✔ Object Tagging

  • Tags = objets clé–valeur
  • Différents objets peuvent portés le même tag
  • Inheritance & propagation

✔ Masking Policies

  • Objets SQL appliqués à une colonne
  • Dynamiques, dépendant du contexte utilisateur

✔ Dynamic Data Masking

  • Mécanisme natif de Snowflake
  • Permet un masquage conditionnel, non destructif

✔ External Tokenization

  • Tokenisation réalisée en dehors du Data Cloud
  • Idéal pour conformité stricte

✔ Tag-Based Masking Policies

  • Masquage automatisé basé sur tags
  • Parfait pour gouvernance à grande échelle

7. Résumé express (à mémoriser)

  • Column-level security repose sur masking policies.
  • DDM applique le masquage selon rôle, user, contexte.
  • External tokenization garde les données sensibles hors Snowflake.
  • Tag-based masking policies permettent une gouvernance scalable et automatisée.
  • Les tags héritent aux objets enfants et déclenchent automatiquement les politiques.
