1. Snowflake Alerts – Overview

Les alerts sont des objets Snowflake permettant d'exécuter automatiquement une action ou d'envoyer une notification lorsque des conditions sur les données sont remplies.

Elles s'utilisent pour surveiller :

  • des règles métier,
  • des erreurs,
  • des dérives de données,
  • des charges ETL,
  • des métriques d'usage.

✔ 1.1. Fonctionnement d'une Snowflake Alert

Une alerte se compose de trois éléments :

  • CONDITION : Une requête SQL renvoyant TRUE/FALSE ou retournant des lignes.
  • ACTION : Une instruction SQL ou un appel à procédure stockée (souvent une notification).
  • SCHEDULE : Une exécution périodique via l'ordonnanceur Snowflake.

✔ 1.2. Cas d'usage typiques

Selon la documentation :

  • détecter seuils de KPI dépassés,
  • détecter des anomalies dans les données,
  • activer une notification automatique,
  • déclencher une remédiation SQL.
✔ 1.3. Privilèges requis

Pour créer et exécuter une alerte :

  • EXECUTE ALERT au niveau du compte (ACCOUNTADMIN uniquement),
  • USAGE & CREATE ALERT sur le schéma cible,
  • USAGE sur le warehouse utilisé,
  • droits requis pour la procédure/action déclenchée.

(Information confirmée dans l'écosystème et nécessaire pour l'examen, cohérente avec la doc officielle sur les alertes.)

2. Snowflake Notifications – Overview

Snowflake propose un système complet de notifications internes pour envoyer des messages à :

  • une adresse e-mail,
  • une file Cloud provider (SNS / Event Grid / Pub/Sub),
  • un webhook (Slack, Teams, PagerDuty),
  • ou via SQL.

3. Email Notifications

Les notifications e-mail sont envoyées via la procédure système :

  • SYSTEM$SEND_EMAIL ou SYSTEM$SEND_SNOWFLAKE_NOTIFICATION.

Elles nécessitent :

  • Un utilisateur Snowflake avec une adresse e-mail vérifiée.
  • Une notification integration TYPE=EMAIL.
CREATE NOTIFICATION INTEGRATION my_email_int
    TYPE=EMAIL
    ENABLED=TRUE;

✔ Restrictions e-mails

  • Snowflake ne peut envoyer qu'aux utilisateurs du même compte Snowflake.
  • L'envoi se fait via AWS SES (détail important) et les messages peuvent être temporairement conservés 30 jours.

✔ ALLOWED_RECIPIENTS

Vous pouvez restreindre les destinataires :

CREATE NOTIFICATION INTEGRATION my_email_int
    TYPE=EMAIL
    ENABLED=TRUE
    ALLOWED_RECIPIENTS=('first.last@example.com');

4. Notifications vers Cloud Queues

Snowflake peut envoyer des messages vers :

  • Amazon SNS,
  • Azure Event Grid,
  • Google Cloud Pub/Sub.

Ces intégrations permettent :

  • monitoring Snowpipe,
  • erreurs de tasks,
  • intégration avec systèmes d'alertes externes.

5. Webhook Notifications

Snowflake supporte officiellement les webhooks pour :

  • Slack,
  • Microsoft Teams,
  • PagerDuty.

✔ 5.1. Prérequis : créer un secret

Les webhooks requièrent un secret contenant la clé d'intégration. Il doit être créé dans Snowflake via :

CREATE SECRET my_webhook_secret TYPE=GENERIC_STRING ... ;

✔ 5.2. Créer l'intégration

CREATE NOTIFICATION INTEGRATION my_slack_int
    TYPE=WEBHOOK ...
    SECRET=my_webhook_secret;

✔ 5.3. Envoyer une notification

On utilise : SYSTEM$SEND_SNOWFLAKE_NOTIFICATION avec les fonctions helper :

  • APPLICATION_JSON,
  • TEXT_PLAIN,
  • SANITIZE_WEBHOOK_CONTENT.

6. Historique des notifications

L'historique est consultable via :

INFORMATION_SCHEMA.NOTIFICATION_HISTORY

7. Synthèse : Alerts vs Notifications

Fonction Alerts Notifications
Déclenchement Basé sur une condition SQL + schedule Appelé via procédure ou lié à un événement (Snowpipe, Task)
Type Objet Snowflake Message envoyé via intégration
Cible Action SQL, notification Email, Cloud Queue, Webhook
Prérequis EXECUTE ALERT CREATE NOTIFICATION INTEGRATION
Usage Surveiller / automatiser Alerter / externaliser

8. Points clés SnowPro Core – À retenir absolument

✔ Snowflake Alerts

  • Objet SQL évaluant une condition et exécutant une action.
  • Déclenchée périodiquement (schedule).
  • Parfait pour surveiller qualité / anomalies / dérives.

✔ Notifications

  • Envois vers e-mail, SNS, Event Grid, Pub/Sub, slack/Teams/PagerDuty via webhooks.
  • Requiert une notification integration.
  • Historique disponible via NOTIFICATION_HISTORY.

✔ Distinction majeure

  • Alert = logique + condition + action
  • Notification = moyen d'envoi (email / webhook / cloud queue)
