1. Définition & Objectif de la Data Governance dans Snowflake

Source officielle :

Snowflake fournit un ensemble de fonctionnalités visant à assurer :

  • la gouvernance des données,
  • la sécurité,
  • la conformité réglementaire,
  • la traçabilité,
  • la transparence.

La gouvernance s'applique :

  • à l'accès aux données,
  • à la qualité des données,
  • à la classification des données sensibles,
  • aux politiques de sécurité,
  • à la visibilité sur les dépendances et usages.

2. Composants de la Data Governance dans Snowflake

✔ 2.1. Data Quality Monitoring & Data Metric Functions

Permet de surveiller l'état et l'intégrité des données à l'aide :

  • des system data metric functions,
  • et des user‑defined metric functions.

Cela permet de :

  • mesurer fraîcheur, doublons, nulls, anomalies, etc.
  • automatiser les contrôles qualité.

✔ 2.2. Column‑Level Security

Snowflake permet d'appliquer une masking policy sur une ou plusieurs colonnes.

→ Très utilisé pour protéger les données sensibles (ex : PII, PCI).

✔ 2.3. Row‑Level Security

Basée sur les Row Access Policies, permettant de filtrer dynamiquement les lignes visibles.

➜ Exemple d'usage : restreindre les données par région, par utilisateur, par équipe.

✔ 2.4. Object Tagging

Les tags sont utilisés pour :

  • suivre les données sensibles,
  • catégoriser les objets,
  • gérer conformité et audits.

✔ 2.5. Tag‑Based Masking Policies

Une fonctionnalité avancée où :

  • un tag porte une masking policy,
  • et cette politique s'applique automatiquement à tout objet tagué.

→ Simplifie et centralise la gouvernance des colonnes sensibles.

✔ 2.6. Sensitive Data Classification

Snowflake propose une classification automatique :

  • identification des données sensibles, personnelles ou confidentielles,
  • support conformité (GDPR, HIPAA…).

✔ 2.7. Access History

Snowflake fournit une vue ACCESS_HISTORY permettant d'auditer :

  • qui a consulté quelles données,
  • comment,
  • à quel moment.

→ Indispensable pour les audits et examens de sécurité.

✔ 2.8. Object Dependencies

La vue OBJECT_DEPENDENCIES permet d'auditer les dépendances :

  • vues → tables,
  • UDF → objets,
  • streaming / pipelines → tables.

➜ Utile pour l'analyse d'impacts d'une modification.

✔ 2.9. Governance Area in Snowsight

Snowflake fournit une interface dédiée dans Snowsight :

  • monitoring des tags,
  • monitoring des masking policies,
  • vues combinées Dashboard / Tagged Objects.

C'est particulièrement utile pour les équipes non techniques.

3. Domaines principaux de la gouvernance Snowflake

DomaineFonctionnalité Snowflake associée
Sécurité & accès RBAC, RLS, CLS, masking policies
Sensibilité des données Sensitive Data Classification, tagging
Audits & traçabilité ACCESS_HISTORY, OBJECT_DEPENDENCIES
Data Quality Data Metric Functions
Centralisation gouvernance Snowsight Governance Area

4. Pourquoi c'est important pour SnowPro Core ?

La certification SnowPro Core attend que tu :

  • ✔ comprennes les capacités de gouvernance intégrées
  • ✔ saches différencier RLS / CLS / Tagging / Masking
  • ✔ connaisses les vues d'audit (ACCESS_HISTORY, OBJECT_DEPENDENCIES)
  • ✔ identifies quand utiliser Tag‑Based Policy vs Column Policy
  • ✔ comprennes comment Snowflake facilite conformité & sécurité

5. Résumé express (à mémoriser)

  • Snowflake offre un portfolio complet de gouvernance native.
  • Les quatre piliers sont : sécurité, qualité, classification, audit.
  • Les masking policies peuvent être appliquées directement ou via tags.
  • La classification sensible identifie automatiquement les colonnes critiques.
  • Les vues ACCESS_HISTORY et OBJECT_DEPENDENCIES sont clés pour les audits.
  • L'interface Snowsight Governance centralise le monitoring.
