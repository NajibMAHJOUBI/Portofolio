✅ 1. Data Lineage dans Snowsight (UI)

Source :

La data lineage est une fonctionnalité Enterprise Edition permettant de visualiser comment les données circulent entre les objets Snowflake (tables, vues, stages, materialized views, etc.).

Elle permet de comprendre :

  • d'où viennent les données (upstream)
  • où elles vont (downstream)
  • comment elles sont transformées
  • quelles colonnes proviennent de quelles sources
  • quelles dépendances doivent être analysées en cas de changement

✔ 1.1. Ce que Snowflake capture comme lineage

Snowflake enregistre automatiquement deux types de relations :

  • Data movement (avec matérialisation) :
    • CTAS (CREATE TABLE AS SELECT)
    • INSERT, MERGE, COPY INTO, etc.
  • Object dependencies (sans copie de données) :
    • vues
    • materialized views
    • objets qui référencent d'autres objets

✔ 1.2. Avantages du Data Lineage

Selon la documentation, cela permet :

  • Impact analysis : comprendre les impacts de changement d'un objet
  • Monitoring & troubleshooting : analyser les flux de données et leurs origines
  • Compliance : suivre le mouvement des données sensibles
  • Travail avec tags & masking policies : propagation de sensibilité via lineage
  • Confiance dans les données : comprendre source → transformation → destination

✔ 1.3. Upstream / Downstream

  • Un objet upstream est la source (ex : table1).
  • Un objet downstream est la cible (ex : table2).
  • Snowsight permet d'explorer les relations pas à pas dans les deux directions.

✔ 1.4. Accès dans Snowsight

Pour utiliser le lineage dans l'UI :

  1. Ouvrir Snowsight
  2. Aller dans Catalog → Database Explorer
  3. Sélectionner un objet supporté (table/view/dynamic table…)
  4. Ouvrir l'onglet Lineage
  5. Options dans l'interface :
    • zoom +/-
    • explorer upstream/downstream
    • afficher détails des colonnes/tags

✅ 2. Access History – Vue d'Audit des Accès

Source :

L'Access History est une fonctionnalité Enterprise Edition permettant d'auditer :

  • qui a accédé à quelle donnée
  • quoi a été lu ou modifié
  • quand
  • comment (quelles colonnes utilisées directement / indirectement)

Elle est accessible via :

  • SNOWFLAKE.ACCOUNT_USAGE.ACCESS_HISTORY
  • SNOWFLAKE.ORGANIZATION_USAGE.ACCESS_HISTORY

✔ 2.1. Ce que contient chaque ligne d'Access History

Chaque ligne correspond à une requête SQL exécutée dans le compte.

Elle inclut :

  • 🔹 Colonnes source auxquelles un utilisateur a accédé
    • Directement
    • Indirectement (via une vue, une jointure…)
  • 🔹 Colonnes projetées dans le résultat
    • → liste dans direct_objects_accessed
  • 🔹 Colonnes utilisées mais non projetées
    • (ex : colonnes de WHERE, JOIN, FILTER)
    • → enregistrées dans base_objects_accessed
  • 🔹 Objets modifiés par la requête
    • → INSERT, UPDATE, MERGE, DELETE, COPY
    • → enregistrés dans objects_modified

✔ 2.2. Exemples documentés

Exemple 1 – Vue simple

CREATE VIEW v1(vc1, vc2) AS
SELECT c1, c2 FROM t WHERE t.c3 > 0;
  • C1 et C2 : colonnes sources directes (base_objects_accessed)
  • C3 : colonne utilisée pour filtrer (base_objects_accessed)
  • VC1 et VC2 : colonnes projetées (direct_objects_accessed)

Exemple 2 – Jointure

SELECT bt.c1, bt.c2, jt.c1
FROM bt, jt
WHERE bt.c3 = jt.c1;
  • → Access History enregistre :
    • colonnes de bt (C1, C2, C3)
    • colonnes de jt (C1)
  • → dans base_objects_accessed

✔ 2.3. Cas d'usage de l'Access History

Selon la doc, cette vue sert à :

  • audit de conformité (GDPR / HIPAA…)
  • identifier quelles données sont réellement utilisées
  • déterminer quelles colonnes sont les plus consultées
  • sécuriser l'usage (détection d'accès anormaux)
  • analyses d'impact et optimisation des pipelines
✔ 2.4. Précisions importantes
  • Disponible uniquement en Enterprise Edition ou plus
  • Retention : 365 jours
  • Certaines requêtes ne créent pas d'entrée dans Access History selon leur structure

✅ 3. Relation entre Lineage et Access History

✔ Lineage = graphique des flux & dépendances

  • Montre la circulation des données entre objets (ETL, vues, etc.)
  • Utilisée pour l'analyse d'impact et la gouvernance

✔ Access History = audit détaillé des accès au niveau utilisateur/colonne

  • Qui a lu quoi ?
  • Quelles colonnes ont été projetées, filtrées, joinées ?
  • Quel objet a été modifié ?

Les deux ensemble permettent une traçabilité complète des données Snowflake.

✅ 4. Points clés SnowPro Core – à retenir absolument

🎯 Data Lineage (Snowsight)

  • Affiche upstream/downstream
  • Montre data movement + object dependencies
  • Inclut lineage au niveau colonne
  • Utilisé pour impact analysis, troubleshooting, compliance
  • Accessible dans Snowsight → Catalog → Lineage

🎯 Access History

  • Table d'audit des accès (lecture, écriture)
  • Fourni par ACCOUNT_USAGE / ORGANIZATION_USAGE
  • Identifie colonnes utilisées, projetées, filtrées
  • Utilisé pour conformité, sécurité, analyse d'usage
