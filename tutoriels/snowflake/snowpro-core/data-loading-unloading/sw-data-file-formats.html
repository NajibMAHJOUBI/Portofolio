1. Les formats de fichiers supportés par Snowflake

Snowflake accepte différents formats structurés et semi‑structurés destinés au chargement des données via COPY INTO ou Snowpipe.

✔ 1.1 Formats structurés

Snowflake supporte les formats délimités suivants :

  • CSV / TSV / autres délimités
    Tout délimiteur single‑byte est accepté. Le délimiteur par défaut est la virgule.

✔ 1.2 Formats semi‑structurés

Snowflake prend en charge nativement :

  • JSON
  • Avro
  • ORC
  • Parquet
  • XML
Notes importantes :
  • Snowflake gère automatiquement les fichiers Avro/ORC/Parquet compressés.
  • Snowflake supporte uniquement les fichiers Parquet générés avec Parquet writer v1, pas v2.
  • Chaque « top-level object » JSON/Avro/ORC/Parquet devient une ligne lors du chargement.
  • Pour XML : chaque « top-level element » devient une ligne.

✔ 1.3 Semi‑structured data → colonnes VARIANT

Snowflake autorise le chargement direct dans des colonnes VARIANT sans schéma explicite.

2. File compression (préparation des données)

Snowflake recommande la compression des fichiers lors de gros chargements.

  • La méthode de compression est déclarée via l'option COMPRESSION du file format.
  • Snowflake détecte automatiquement codec & format lors du chargement de fichiers compressés.

3. CREATE FILE FORMAT : Définition et syntaxe

La commande CREATE FILE FORMAT permet de définir un objet décrivant la structure d'un fichier.

🧩 Syntaxe générale :

CREATE [ OR REPLACE ] [ TEMP | TEMPORARY | VOLATILE ]
FILE FORMAT [ IF NOT EXISTS ] <name>
    [ TYPE = { CSV | JSON | AVRO | ORC | PARQUET | XML | CUSTOM } [ formatTypeOptions ] ]
    [ COMMENT = '<string_literal>' ];

4. Options de format par type

Snowflake propose des options distinctes selon le type de fichier.

✔ 4.1 TYPE = CSV — Principales options

Exemples d'options supportées :

  • COMPRESSION = AUTO, GZIP, BZ2, BROTLI…
  • FIELD_DELIMITER
  • RECORD_DELIMITER
  • SKIP_HEADER
  • MULTI_LINE
  • FIELD_OPTIONALLY_ENCLOSED_BY
  • NULL_IF
  • ERROR_ON_COLUMN_COUNT_MISMATCH
  • REPLACE_INVALID_CHARACTERS
  • SKIP_BYTE_ORDER_MARK

Exemple :

CREATE FILE FORMAT my_csv_fmt
    TYPE = 'CSV'
    FIELD_DELIMITER = ','
    SKIP_HEADER = 1
    FIELD_OPTIONALLY_ENCLOSED_BY = '"';

✔ 4.2 TYPE = JSON — Options principales

  • COMPRESSION
  • STRIP_OUTER_ARRAY
  • IGNORE_UTF8_ERRORS
  • ALLOW_DUPLICATE
  • STRIP_NULL_VALUES
  • MULTI_LINE
  • NULL_IF

✔ 4.3 TYPE = PARQUET — Options principales

  • COMPRESSION = AUTO, LZO, SNAPPY, NONE
  • SNAPPY_COMPRESSION
  • USE_LOGICAL_TYPE
  • USE_VECTORIZED_SCANNER
  • BINARY_AS_TEXT

✔ 4.4 TYPE = AVRO, ORC, XML

Options plus limitées, avec notamment :

  • NULL_IF
  • TRIM_SPACE
  • REPLACE_INVALID_CHARACTERS

5. COMMENT utiliser un FILE FORMAT ?

Un fichier de format Snowflake peut être utilisé dans les commandes COPY INTO :

Exemple :

COPY INTO my_table
FROM @mystage/datafile.json
FILE_FORMAT = (FORMAT_NAME = 'my_json_fmt');

Cette structure est conforme aux usages documentés. (La documentation renvoie vers COPY INTO pour détailler l'usage.)

6. Points essentiels pour l'examen SnowPro Core

✔ Connaître les formats supportés :

CSV, TSV, JSON, Avro, ORC, Parquet (writer v1), XML.

✔ Comprendre que LECTURE & chargement diffèrent selon le type

(ex. top-level object par ligne).

✔ Maîtriser la syntaxe CREATE FILE FORMAT

et les options principales selon le type.

✔ Savoir que la compression doit être déclarée dans COMPRESSION

mais peut être détectée automatiquement.

✔ Savoir que les semi-structured data vont souvent dans une colonne VARIANT
