Snowflake Data Unload Export

1. Overview of Data Unloading

Source : Snowflake Documentation

✔ Principe général

Snowflake permet l'export (unload) de données vers des fichiers plats (CSV, TSV, JSON…) de façon similaire au chargement, mais en sens inverse.

Le mécanisme principal repose sur :

  • COPY INTO : écrit les données de la table vers un internal ou external stage.
  • GET : télécharge les fichiers depuis le stage (ou via interfaces cloud : S3, Azure, GCS).

✔ Unloading via SELECT

Au lieu d'exporter une table complète, Snowflake permet :

  • d'utiliser une requête SELECT dans COPY INTO <location>
  • d'inclure des JOIN, des filtres, etc.
    → Le résultat est exporté sous forme de fichiers.

✔ Unloading en un ou plusieurs fichiers

Option COPY importante :

  • SINGLE = TRUE → un fichier unique
  • SINGLE = FALSE (défaut) → plusieurs fichiers générés en parallèle
  • Fichiers nommés automatiquement avec préfixe (ex: data_...).
  • MAX_FILE_SIZE permet de limiter la taille maximum par fichier.

✔ Partitionnement lors de l'unload

Copy option : PARTITION BY

  • Permet de diviser les lignes en plusieurs fichiers organisés par répertoires, utile pour les data lakes.
  • Très efficace pour ingestion en aval par des outils tiers.

2. Data Unloading Considerations

Source : Snowflake Documentation

🎯 Objectif
Éviter les erreurs courantes dans les fichiers exportés, en particulier sur les chaînes vides, les NULLs et le comportement des formats de fichier.

✔ Empty strings vs NULL values

Distinction importante (surtout dans les formats CSV)

  • NULL → deux délimiteurs successifs (ex: ,,)
  • Empty string → généralement '' (chaîne vide entre quotes)

Snowflake fournit plusieurs options pour contrôler cela :

FIELD_OPTIONALLY_ENCLOSED_BY

  • Permet d'envelopper les valeurs chaines dans un caractère (', ").
  • Recommandé pour distinguer NULL et empty string.
  • Peut être NONE (défaut).

EMPTY_FIELD_AS_NULL

  • TRUE (défaut) → empty string devient NULL
  • FALSE → empty string reste une chaîne vide
⚠ interdit d'utiliser EMPTY_FIELD_AS_NULL=TRUE avec certains comportements ; cela peut rendre NULL et empty string indistinguables.

NULL_IF

  • Indique la représentation textuelle qui doit être interprétée comme NULL.
  • Important lorsque FIELD_OPTIONALLY_ENCLOSED_BY = NONE et EMPTY_FIELD_AS_NULL = FALSE.
✔ Bonnes pratiques recommandées :
  • Préféré : utiliser FIELD_OPTIONALLY_ENCLOSED_BY pour entourer les chaînes.
  • Si pas d'enclosure :
    • mettre EMPTY_FIELD_AS_NULL = FALSE
    • définir NULL_IF pour différencier NULL et chaînes vides

3. Preparing to Unload Data

Source : Snowflake Documentation (via Data Unloading Overview + Unload processes)

Snowflake fournit des instructions précises pour préparer l'unload, notamment :

✔ Étapes du processus d'unload

  1. COPY INTO @stage/path vers un internal named stage, un user stage, ou un external stage (S3, Azure, GCS)
  2. GET @stage/path pour récupérer les fichiers localement si besoin

✔ Préparation du stage

Un stage peut être :

  • Internal Stage → plus flexible, géré par Snowflake
  • External Stage → pointe vers S3 / Azure / GCS via credentials

Exemple interne :

CREATE OR REPLACE STAGE my_unload_stage
    FILE_FORMAT = my_csv_unload_format;

✔ Unloading vers un internal stage

COPY INTO @mystage/unload/
FROM mytable;
  • Le préfixe unload/ organise les fichiers dans un sous-dossier.
  • Pas besoin de préciser de FILE_FORMAT si défini au niveau du stage.

✔ Téléchargement local via Snowsql

GET @mystage file://local/path/

4. Points clés à maîtriser pour SnowPro Core

COPY INTO

  • Peut utiliser une table ou une requête SELECT
  • Peut partitionner les sorties (PARTITION BY)
  • Peut gérer SINGLE=TRUE pour un fichier unique
  • Utilise MAX_FILE_SIZE

Gestion des formats (CSV surtout)

  • Distinction NULL vs empty string
  • Options : FIELD_OPTIONALLY_ENCLOSED_BY, EMPTY_FIELD_AS_NULL, NULL_IF

Stages

  • Internal stage
  • External stage (S3 / Azure / GCS)
  • GET pour récupérer les fichiers

Performance & organisation

  • Partitionnement pour data lakes
  • Nommage automatique des fichiers en parallèle
