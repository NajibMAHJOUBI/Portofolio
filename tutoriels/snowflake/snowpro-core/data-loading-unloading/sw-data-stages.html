Snowflake - Stages, Directory Tables & Unstructured Data

Niveau Intermédiaire
Mis à jour: Février 2026 Durée: 25 min Difficulté: Intermédiaire
Snowflake Stages Unstructured Data

1. External Stages (stages externes)

Un external stage référence un stockage cloud externe (S3, GCS, Azure) et sert de point d'accès aux fichiers utilisés pour le chargement Snowflake.

Points essentiels :
  • Snowflake supporte Amazon S3, Google Cloud Storage, Azure Blob/ADLS.
  • Les données dans les classes archival (ex. S3 Glacier, Azure Archive) ne sont pas accessibles.
  • Un external stage est un objet de base de données stockant : URL du bucket, Credentials ou Storage Integration, File format éventuel.
  • Création via CREATE STAGE (avec paramètres spécifiques selon le cloud).
  • Possibilité d'associer un directory table (métadonnées des fichiers).

2. Internal Stages (stages internes)

Snowflake maintient automatiquement plusieurs types de stages internes :

User stage (@~)

Dédié à chaque utilisateur, accessible uniquement par celui-ci ; ne peut pas être modifié ou supprimé.

Table stage (@%table_name)

Lié à une table Snowflake, pour charger des fichiers uniquement dans cette table. Ne peut pas être supprimé. Le propriétaire de la table doit disposer de OWNERSHIP pour manipuler ses fichiers.

Named internal stage

Objet explicite créé via CREATE STAGE. Peut servir à charger plusieurs tables, est partageable entre utilisateurs.

Chaque stage interne est stocké au sein de Snowflake (storage internal Snowflake).

3. Directory Tables (dirtables)

Un directory table est une couche ajoutée à un stage pour cataloguer les fichiers.

Principes :
  • Ce n'est pas un objet indépendant : c'est une couche liée au stage.
  • Fonctionne comme une « external table » (métadonnées : taille, last_modified, file_url...).
  • Peut être activé lors de CREATE STAGE DIRECTORY = (ENABLE=TRUE).
  • Utilisations :
    • Lister tous les fichiers d'un stage
    • Construire des pipelines de traitement de fichiers
    • Joindre fichiers + métadonnées
  • Rafraîchissement nécessaire :
    • Automatique via events cloud
    • Manuel via ALTER STAGE … REFRESH (peut être coûteux)
  • Requêtage via : SELECT * FROM DIRECTORY(@stage_name);

4. Unstructured Data & Server‑side Encryption

Snowflake prend en charge l'accès sécurisé aux fichiers non structurés (images, vidéos, PDF, audio).

Points clés :
  • Supporté dans internal et external stages.
  • Types d'URL pour accéder aux fichiers :
    • Scoped URL (accès temporaire sécurisé, recommandé)
    • File URL (permanent, nécessite privilèges sur le stage)
    • Pre-signed URL (pour applications externes, avec expiration configurable)
  • Server-side encryption :
    • Pour éviter corruption lors de GET → vérifier ENCRYPTION='SNOWFLAKE_SSE' sur le stage.

5. Organizing Data by Path

Lorsque les fichiers sont organisés dans des sous‑répertoires au sein d'un stage, ceci permet :

  • d'améliorer la lisibilité et le partitionnement logique,
  • d'utiliser PATTERN dans COPY INTO,
  • d'optimiser les refresh de directory tables via SUBPATH.

L'organisation par chemins est une bonne pratique mentionnée dans les considérations de staging.

6. CREATE STAGE — Points clés

La commande CREATE STAGE crée un stage interne ou externe.

Internal stage (extrait simplifié)

CREATE STAGE my_int_stage
    ENCRYPTION = (TYPE='SNOWFLAKE_SSE')
    DIRECTORY = (ENABLE=TRUE)
    FILE_FORMAT = (TYPE=CSV);

External stage (exemple S3)

CREATE STAGE my_ext_stage
    URL='s3://bucket/path/'
    STORAGE_INTEGRATION = my_int
    DIRECTORY = (ENABLE=TRUE);
Points importants :
  • FILE_FORMAT peut être défini directement dans le stage.
  • DIRECTORY table peut être activée.
  • Encrypted external stages peuvent utiliser AWS_SSE_S3, AWS_SSE_KMS, ou NONE.

7. PUT — Upload de fichiers dans un stage interne

PUT permet d'envoyer des fichiers locaux → internal stages.

Caractéristiques :
  • Upload possible uniquement vers internal stages (user, table, named).
  • Fichiers automatiquement encryptés AES‑128 ou 256 lors de l'upload.
PUT file:///local/path/file.csv @my_int_stage AUTO_COMPRESS=TRUE;

8. GET — Télécharger des fichiers depuis un internal stage

GET permet de rapatrier des fichiers locaux depuis un internal stage.

GET @my_int_stage file:///local/download/;

9. LIST — Lister les fichiers d'un stage

Commande fondamentale pour tout stage (interne ou externe).

LIST @my_stage;

Permet de visualiser : nom du fichier, taille, date de modification.

Ces sorties peuvent être utilisées :

  • via le pipe operator ->>
  • via TABLE(RESULT_SCAN(LAST_QUERY_ID()))
