Snowflake COPY INTO Data Loading

✅ 1. COPY INTO — Chargement en table

La commande COPY INTO <table> charge des fichiers vers une table Snowflake existante.

✔ Sources de fichiers autorisées

  • Internal stages : user (@~), table (@%table), named stage (@mystage)
  • External stages : S3, GCS, Azure
  • External location directement (s3://, gcs://, azure://)
⚠️ Limite : fichiers dans archival storage classes (S3 Glacier, Azure Archive) non accessibles.

✔ Syntaxe (simplifiée)

COPY INTO mytable
FROM @mystage/path/
FILE_FORMAT = (FORMAT_NAME='myformat')
PATTERN='.*.csv'
ON_ERROR='CONTINUE';

✔ Options essentielles

  • FILES = ('f1', 'f2') : charger fichiers spécifiques.
  • PATTERN (regex) : filtrer les fichiers.
  • FILE_FORMAT : FORMAT_NAME ou TYPE = CSV/JSON/AVRO/ORC/PARQUET/XML.
  • VALIDATION_MODE :
    • RETURN_ERRORS
    • RETURN_ALL_ERRORS
    • RETURN__ROWS
    Permet de tester et valider avant chargement réel.
  • Transformations : COPY peut s'appuyer sur un SELECT pour transformer les colonnes en entrée.
Bonnes pratiques :
  • Préparer un file format séparé.
  • Utiliser PATTERN pour limiter les fichiers.
  • Utiliser VALIDATION_MODE pour valider avant ingestion.
  • Suivre l'historique de loads via LOAD_HISTORY et Snowsight.

✅ 2. COPY INTO — Déchargement/export

La commande COPY INTO <location> exporte des données d'une table ou requête vers :

  • internal stage
  • external stage
  • external location (S3, GCS, Azure)

✔ Syntaxe (simplifiée)

COPY INTO @mystage/export/
FROM mytable
FILE_FORMAT = (TYPE = CSV COMPRESSION='GZIP');

✔ Points clés

  • Export vers fichiers parallélisés par défaut.
  • SINGLE=TRUE permet un fichier unique (sinon Snowflake produit plusieurs fichiers).
  • Supporte seulement CSV, JSON, PARQUET pour FILE_FORMAT en déchargement.
  • Option PARTITION BY pour partitionner l'export.
  • Résultats téléchargeables via GET si export vers internal stage.

✅ 3. Chargement depuis un système de fichiers local

Documentation Snowflake : Bulk loading from a local file system.

Chargement local se fait en 2 étapes :

  1. PUT → uploader fichier(s) local(aux) vers internal stage.
  2. COPY INTO <table> → charger depuis le stage vers la table.

✔ Étape 1 — PUT

Permet d'envoyer un fichier local à un stage interne :

PUT file:///data/data.csv @mystage/path/;

Supporte user stage (@~), table stage (@%table), named stage (@mystage).

Fichiers uploadés sont automatiquement encryptés.

✔ Étape 2 — COPY INTO

Comme décrit dans la section 1.

✔ Listing des fichiers uploadés

LIST @~;
LIST @%mytable;
LIST @mystage;

✅ 4. Chargement via l'interface Web (Snowsight)

Snowflake permet de charger des données directement via l'UI (Snowsight).

✔ Formats supportés

  • Structurés : CSV, TSV
  • Semi‑structurés : JSON, Avro, ORC, Parquet, XML

✔ Sources d'import possibles

  • Local machine
  • Stages internes ou externes
  • Cloud storage non encore déclaré comme external stage (Classic Console)
Limitations :
  • Jusqu'à 250 fichiers par upload
  • Taille max 250 MB par fichier

Pour plus volumineux → utiliser PUT + COPY INTO.

✔ Fonctionnement

  • Snowsight peut créer automatiquement une table à partir d'un fichier (sauf XML & Iceberg).
  • Les chargements UI exécutent une transaction explicite.
  • Nécessite privilèges :
    • DB: USAGE
    • SCHÉMA: CREATE TABLE
    • STAGE: USAGE
    • TABLE : OWNERSHIP (si chargement dans table existante)

✔ Étapes

  1. Snowsight → Create → Table → From file
  2. Sélection du ou des fichiers (drag & drop ou depuis stage)
  3. Aperçu des données + mapping colonnes
  4. Création table + chargement
