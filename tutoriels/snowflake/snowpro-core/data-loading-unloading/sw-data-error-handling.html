✅ 1. COPY INTO — COPY_OPTIONS

Source : Snowflake Documentation

La commande COPY INTO <table> permet de charger des fichiers depuis un stage interne/externe vers une table Snowflake. Les COPY_OPTIONS permettent de contrôler finement le comportement du chargement.

⭐ COPY_OPTIONS les plus importants à connaître

🔹 1. SIZE_LIMIT

Limite la taille totale des données chargées.

→ Utile pour restreindre un chargement massif involontaire.

🔹 2. PURGE

PURGE = TRUE supprime les fichiers source du stage après un chargement réussi.

→ Pratique pour éviter la relecture des fichiers.

🔹 3. FORCE

FORCE = TRUE recharge les fichiers même s'ils ont déjà été chargés.

→ À utiliser lors de modifications dans les données sources.

🔹 4. TRUNCATECOLUMNS

TRUE = tronque silencieusement les valeurs trop longues.

⚠️ Risque de perte de données. Attention en examen !

🔹 5. ENFORCE_LENGTH

TRUE = Snowflake génère une erreur si la valeur dépasse la longueur déclarée.

→ Plus strict que TRUNCATECOLUMNS.

🔹 6. MATCH_BY_COLUMN_NAME

Gère comment les colonnes du fichier se mappent aux colonnes de la table.

Inclut : COLUMN MATCH CRITERIA, LOAD CRITERIA, gestion des colonnes non correspondantes, limitations

🔹 7. INCLUDE_METADATA

Inclut des colonnes système décrivant le fichier source (ex : nom du fichier).

→ Utile pour traçabilité.

✅ 2. COPY INTO – VALIDATION_MODE (rappel)

(Paramètre du COPY INTO)

VALIDATION_MODE = RETURN_ERRORS | RETURN_ALL_ERRORS | RETURN_n_ROWS

Permet de vérifier les problèmes avant un chargement réel.

Très utile pour les examens SnowPro.

✅ 3. Fonction de table VALIDATE

Source officielle Snowflake Documentation

La fonction VALIDATE permet d'analyser les erreurs d'un chargement COPY INTO déjà exécuté.

🎯 Objectif
Obtenir toutes les erreurs associées à un chargement COPY INTO donné, et non seulement la première.

🔧 Syntaxe

SELECT *
FROM TABLE(VALIDATE(
    <table_name>,
    JOB_ID => '<query_id>' | '_last'
));

📌 Paramètres importants

  • table_name : Nom complet de la table cible du COPY.
  • JOB_ID : Un query_id provenant de l'historique des requêtes Snowflake, ou _last pour le dernier COPY du même user / même session.

ℹ Notes d'utilisation essentielles

  • Ne retourne rien si le COPY utilisait ON_ERROR = ABORT_STATEMENT (par défaut).
  • Échec si :
    • Le COPY incluait un SELECT transformant les données
    • L'utilisateur n'a pas les droits sur la table
    • Les métadonnées du COPY ont expiré
    • Le query_id appartient à un autre utilisateur et l'accès n'est pas autorisé
  • Nouveaux fichiers ajoutés au stage après l'exécution → ignorés
  • Fichiers supprimés après coup → signalés comme manquants

📚 Exemples

👉 Valider le dernier COPY exécuté

SELECT * FROM TABLE(VALIDATE(t1, JOB_ID => '_last'));

👉 Valider un COPY spécifique

SELECT *
FROM TABLE(VALIDATE(t1, JOB_ID => '5415fa1e-59c9-4dda-b652-533de02fdcf1'));

✅ 4. Points clés à retenir pour l'examen SnowPro Core

✔ COPY_OPTIONS

  • Comprendre PURGE, FORCE, TRUNCATECOLUMNS, ENFORCE_LENGTH, MATCH_BY_COLUMN_NAME
  • Savoir quand FORCER le reload et gérer les colonnes dynamiques.

✔ VALIDATION_MODE vs VALIDATE()

  • VALIDATION_MODE : préchargement.
  • VALIDATE() : post‑chargement, analyse d'un job déjà exécuté.

✔ VALIDATE

  • Très utile pour comprendre les erreurs de format de fichier.
  • Ne fonctionne pas lorsque ON_ERROR = ABORT_STATEMENT (retour vide).
  • Identifier les fichiers manquants / ignorés.
