Snowflake Data Loading COPY INTO

🎯 Objectif

Comprendre les différentes méthodes de chargement de données dans Snowflake, les concepts clés (stages, COPY INTO, Snowpipe, formats…), et les bonnes pratiques essentielles pour le passage de l'examen.

1. Vue d'ensemble du Data Loading dans Snowflake

Snowflake propose plusieurs façons de charger des données, avec des outils, tâches, et approches différentes selon les besoins (batch, temps réel, semi-structuré, via interface ou via API).

Les principales rubriques couvertes par l'overview sont :

  • Options de chargement
  • Fonctionnalités COPY INTO
  • Tutoriels étape‑par‑étape
  • Considérations & bonnes pratiques
  • Snowpipe & Snowpipe Streaming
  • Transformation à l'ingestion
  • Querying staged files

2. Les Stages — Point central du chargement

Toutes les méthodes de chargement passent par un stage, qui sert de zone d'atterrissage des fichiers. Deux types : external ou internal.

✔ 2.1 Internal Stages

Snowflake met à disposition :

  • User stage : stage individuel par utilisateur
  • Table stage : un stage implicite lié à chaque table
  • Named internal stage : objet explicite créé dans un schéma

✔ 2.2 External Stages

Utilisent un stockage cloud externe :

  • AWS S3
  • Google Cloud Storage
  • Azure Blob Storage
❗ Limite importante : les stockages d'archive type S3 Glacier ou Azure Archive ne sont pas supportés pour un chargement direct.
❗ Attention à la facturation : du data transfer peut être facturé si le stockage externe est dans une autre région.

3. Méthodes de chargement des données

Snowflake supporte plusieurs modes de data ingestion :

✔ 3.1 Bulk Loading — COPY INTO

C'est la méthode standard et la plus utilisée pour ingérer des volumes importants.

COPY INTO supporte :

  • fichiers situés dans internal ou external stages
  • transformations légères
  • file formats variés (CSV, JSON, Parquet, etc.)

✔ 3.2 Snowpipe — Chargement continu

Pour le chargement quasi temps réel, Snowpipe :

  • surveille l'arrivée des fichiers,
  • charge automatiquement les données,
  • retourne un statut d'ingestion,
  • facture selon l'utilisation de compute serverless.

✔ 3.3 Snowpipe Streaming

Solution pour ingestion streaming haute performance, intégrée à Snowflake.

✔ 3.4 Snowsight — Chargement manuel pour petits volumes

Permet d'uploader des fichiers locaux via l'interface web.

✔ 3.5 Connecteurs / Intégrations

Snowflake propose de multiples connecteurs pour charger des données depuis :

  • Google Cloud
  • Azure
  • Salesforce
  • API & outils ETL (Fivetran, Informatica…)

4. Préparation et transformation des données

✔ 4.1 File Formats

Les files formats décrivent le mode de lecture des fichiers :

  • CSV
  • JSON
  • Parquet
  • AVRO
  • etc.

✔ 4.2 Transformations pendant le chargement

Le COPY INTO peut effectuer des transformations simples :

  • parsing
  • colonnes dérivées
  • gestion d'erreurs

5. Querying staged files

Snowflake permet de lire les fichiers directement dans les stages avant ingestion :

  • utile pour pré-validation
  • via des commandes SQL (SELECT FROM @stage …)

Deux thématiques associées :

  • Query data in staged files
  • Query metadata for staged files

6. Data Loading Considerations — Points-clés pour l'examen

La documentation signale plusieurs bonnes pratiques essentielles :

✔ Préparer correctement les fichiers

  • assurer cohérence du format
  • éviter les erreurs dans les en‑têtes, séparateurs

✔ Optimiser la taille des fichiers

  • fichiers trop petits = surcharge
  • fichiers trop gros = latence accrue

✔ Gérer les permissions des stages

OWNERSHIP nécessaire pour table stage

✔ Utiliser les row timestamps

Pour mesurer précisément la latence d'ingestion.

✔ Comprendre la facturation liée au chargement

  • compute (COPY, Snowpipe)
  • data transfer si stockage distant
