✅ 1. Data File Compression

Source : Preparing to load data — Snowflake Documentation

🎯 Objectif
Optimiser la vitesse de chargement, les coûts de stockage et les performances du COPY en exploitant la compression des fichiers.

📌 Points essentiels à retenir

  • ✔ Snowflake recommande de compresser les fichiers pour les chargements volumineux
  • ✔ Snowflake détecte automatiquement :
    • Le format du fichier compressé
    • Le codec de compression utilisé
  • ✔ Déclaration de la compression via l'option COMPRESSION :
    • Peut être définie :
      • Dans le COPY INTO <table>
      • Ou dans un named file format ou named stage utilisé dans le COPY
  • ✔ Compatibilité et formats pris en charge (avec compression automatique) :
    Avro, ORC, Parquet → Snowflake gère automatiquement la détection et le traitement des fichiers compressés

✅ 2. File Sizing Best Practices & Limitations

Source : Preparing your data files — Snowflake Documentation

🎯 Objectif
Optimiser le parallélisme, les performances et éviter les erreurs ou interruptions lors du chargement.

⭐ Recommandations générales de taille des fichiers

  • ✔ Taille recommandée des fichiers : 100–250 MB (compressés)
    → Permet de maximiser le parallélisme et l'efficacité du warehouse.
  • ✔ Pourquoi ?
    • Le nombre d'opérations en parallèle est limité par le nombre de fichiers disponibles
    • Plus de fichiers → Plus de parallélisme → Temps de chargement plus court

❌ À éviter

❌ Fichiers très volumineux (> 100 GB)
  • Peu recommandé
  • Si nécessaire, vérifier attentivement ON_ERROR
  • Risque : abandon du chargement si durée > 24 heures (aucune partie du fichier n'est committée)

🔧 Stratégies pour optimiser les fichiers

  • ✔ Agréger les petits fichiers
    → Réduit le surcoût de traitement par fichier
  • ✔ Fractionner les gros fichiers
    → Meilleure répartition de la charge entre les clusters Snowflake
  • ✔ Fractionner par lignes, pas par octets
    → Évite que des enregistrements soient coupés entre deux fichiers
  • ✔ Outils recommandés pour le splitting
    • Sous Linux/macOS : split
    • Exemple : split -l 100000 pagecounts-20151201.csv pages
    • Sous Windows → Utiliser des utilitaires tiers (pas d'outil natif)
⚠ Limites particulières : Objets > 16 MB

Snowflake recommande de réduire les objets dépassant 16 MB avant chargement.

Cette fonctionnalité nécessite le bundle 2024_08 activé (activé par défaut).

✅ 3. Points critiques pour l'examen SnowPro Core

🔹 Compression

  • Comprendre que Snowflake détecte automatiquement la compression
  • Comprendre comment paramétrer COMPRESSION dans un file format ou dans COPY INTO

🔹 Taille des fichiers

  • Retenir la règle d'or 100–250 MB
  • Savoir éviter les fichiers trop gros (>100 GB)
  • Importance du parallélisme dépendant du nombre de fichiers
  • Comprendre les risques d'interruption après 24h

🔹 Manipulation

  • Savoir quand agréger / fractionner
  • Savoir utiliser split
  • Savoir gérer les limites des objets > 16 MB
