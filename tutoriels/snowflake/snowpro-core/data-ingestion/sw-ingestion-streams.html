✅ 1. Introduction aux Streams Snowflake (CDC)

Source : Introduction to streams

✔ Définition

Un stream est un objet Snowflake qui enregistre les modifications DML (INSERT, UPDATE, DELETE) effectuées sur un objet source (table, vue, table externe, table Iceberg, table dynamique…). Il fournit une Change Data Capture (CDC) interne.

✔ Objectif

Fournir une "change table" permettant d'identifier ce qui a changé entre deux versions transactionnelles d'un objet.

✔ Fonctionnement général

  • Lors de la création d'un stream, Snowflake capture un offset initial : un instantané logique du contenu de la table.
  • Ensuite, Snowflake enregistre tous les changements intervenus après cet offset.
  • Les données restituées incluent des métadonnées sur chaque événement de changement (old/new values, type de changement).
✔ Important : les streams ne stockent pas de données

Un stream ne contient pas les lignes : il stocke uniquement l'offset et s'appuie sur l'historique de versioning du tableau.

Quand un stream est créé, Snowflake ajoute des colonnes cachées au tableau pour suivre les modifications.

✔ Types d'objets pouvant avoir un stream

  • Tables standard (y compris partagées)
  • Vues (avec change tracking activé)
  • Tables externes
  • Tables dynamiques
  • Tables Iceberg (avec limitations)

✅ 2. Comprendre les offsets et la consommation

Source : CDC usage details

✔ Offset (position temporelle du stream)

  • Le stream retourne les modifications depuis le dernier offset consommé.
  • L'offset n'est avancé que lorsqu'une requête DML consomme les données du stream :
    • INSERT
    • UPDATE
    • DELETE
    • MERGE
    • CTAS

✔ Consommation vs simple lecture

  • Un SELECT n'avance pas l'offset : on peut inspecter les données sans les consommer.
  • Une opération DML consomme la modification → ces changements ne seront plus renvoyés lors de la prochaine requête.

✅ 3. Contenu d'un Stream : structure CDC

Source : Introduction to streams

Chaque ligne de CDC contient :

  • Les colonnes de la table d'origine
  • Des méta-informations sur le changement :
    • Type (INSERT/UPDATE/DELETE)
    • Valeurs avant / après
    • Métadonnées transactionnelles
⚠️ Les streams utilisent le schéma courant de la table mais peuvent échouer si des modifications du schéma sont incompatibles avec des données supprimées (Time Travel).

✅ 4. Commande SQL : CREATE STREAM & options

Source : SQL CREATE STREAM reference

✔ Syntaxe générale (table)

CREATE [ OR REPLACE ] STREAM [ IF NOT EXISTS ] <name>
    ON TABLE <table_name>
    [ APPEND_ONLY = TRUE | FALSE ]
    [ SHOW_INITIAL_ROWS = TRUE | FALSE ]
    [ COMMENT = '<text>' ];

✔ Options importantes

  • APPEND_ONLY = TRUE : suit uniquement les INSERT (utile pour éviter updates/deletes).
  • SHOW_INITIAL_ROWS = TRUE : renvoie les lignes existantes de la table lors de la création (sinon stream vide).
  • Modes temporels : AT / BEFORE TIMESTAMP, OFFSET, STATEMENT → permettre de créer un stream sur un état passé.

✔ Variants disponibles

  • Sur une table externe (option INSERT_ONLY)
  • Sur une vue
  • Sur une table Iceberg
  • Sur une dynamic table
  • Sur une directory table (ON STAGE)

✔ Clone

CREATE STREAM <name> CLONE <source_stream>;

→ Reprend le même offset que l'original.

✅ 5. Commandes associées aux streams

Source : SQL Reference Streams commands

✔ SHOW STREAMS

Liste les streams du schéma / compte.

SHOW STREAMS;

✔ DESCRIBE STREAM

Affiche la définition du stream, son offset, ses options.

DESCRIBE STREAM my_stream;

✔ ALTER STREAM

Pour modifier certaines propriétés.

✔ DROP STREAM

Supprime un stream (ne supprime pas la table source).

✅ 6. Principes de bonne compréhension – SnowPro Core

🔹 1. Un stream = un "bookmark" CDC

→ Enregistre à partir de un point dans le temps ; n'est pas un stockage de données.

🔹 2. Consommation unique des données

→ Une fois consommées via DML, les données disparaissent du stream.

🔹 3. Un stream par use case

→ Pour que chaque pipeline lise indépendamment les changements.

🔹 4. Interaction avec Tasks

Les tasks peuvent automatiser le traitement des changements (e.g. MERGE sur une table cible).

🔹 5. Hidden metadata columns

→ Ajoutées à la table source dès la création du premier stream.

✅ 7. Exemples simples

✔ Création d'un stream :

CREATE STREAM my_stream ON TABLE my_table;

✔ Consommation via MERGE :

MERGE INTO target t
USING (SELECT * FROM my_stream) s
ON t.id = s.id
WHEN MATCHED THEN UPDATE SET ...
WHEN NOT MATCHED THEN INSERT (...);
