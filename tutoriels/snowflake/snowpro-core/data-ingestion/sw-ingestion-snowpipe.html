1. Snowpipe – Introduction (Continuous File-Based Ingestion)

Source : Snowflake Documentation

✔ Définition

Snowpipe est le service Snowflake de chargement continu des données dès que des fichiers apparaissent dans un stage. Il ingère les données en micro-batchs, garantissant une disponibilité rapide sans lancer manuellement un COPY.

✔ Principe de fonctionnement

Snowpipe repose sur un objet PIPE, qui contient l'instruction COPY INTO <table> définissant :

  • La source (stage)
  • La table cible

✔ Détection des fichiers

Snowpipe peut être déclenché par :

  • Cloud Messaging (événementiel)
    • Utilise S3/SNS/SQS, Azure Event Grid, GCP Pub/Sub
    • Snowpipe lit les événements et charge automatiquement les fichiers
  • Snowpipe REST API
    • Le client appelle une API Snowflake et fournit la liste des fichiers

✔ Support Cloud

Snowpipe supporte :

  • S3
  • GCS
  • Azure Blob & ADLS Gen2

2. Snowpipe – Gestion & Administration

Source : Snowflake Documentation

✔ Suppression des fichiers source

  • Snowpipe ne supporte pas PURGE.
  • Il ne supprime pas automatiquement les fichiers du stage.
  • Il faut utiliser REMOVE, ou configurer la politique de cycle de vie du cloud.

✔ Chargement de données historiques

  • Snowpipe via événements ne charge que les fichiers des 7 derniers jours (avec ALTER PIPE … REFRESH).
  • Pour des fichiers plus anciens :
    • Charger manuellement via COPY INTO <table>
    • Reconfigurer Snowpipe pour l'ingestion automatique
    • Utiliser ALTER PIPE … REFRESH pour éviter les doublons

✔ Recréation de pipes (modification)

Étapes recommandées :

  1. Pause du pipe (ALTER PIPE … SET PIPE_EXECUTION_PAUSED = TRUE)
  2. Vérifier via SYSTEM$PIPE_STATUS
  3. Recréer le pipe (CREATE OR REPLACE PIPE)
  4. Vérifier la configuration cloud (SNS/SQS, Event Grid…)
  5. Reprendre le pipe

3. Commandes SQL : PIPE (CREATE / ALTER / SHOW / DESC)

Sources : Snowflake Documentation

✔ CREATE PIPE

Exemple générique :

CREATE OR REPLACE PIPE mypipe
AUTO_INGEST = TRUE
AS COPY INTO mytable
FROM @mystage/path
FILE_FORMAT = (TYPE = 'CSV');

Points clés :

  • AUTO_INGEST = TRUE active les notifications pour ingestion automatique
  • copy_statement est l'instruction COPY INTO utilisée par Snowpipe
  • Supporte deux types de sources :
    • Fichiers en stage
    • Source de streaming (DATA_SOURCE(TYPE => 'STREAMING'))
⚠ Recommandations : Ne pas utiliser CURRENT_DATE, CURRENT_TIMESTAMP, etc. dans un COPY Snowpipe

✔ DESCRIBE PIPE

Permet de consulter :

  • Définition COPY
  • Canal de notification
  • Propriétaire
  • Type de pipe (manuel ou auto-généré par Snowpipe Streaming HP)

✔ SHOW PIPES

Liste tous les pipes accessibles, avec filtre possible via LIKE.

4. Snowpipe Streaming – Overview

Sources : Snowflake Documentation

✔ Principe

Snowpipe Streaming permet l'ingestion ligne par ligne en quasi temps réel, sans utiliser de stage fichier → flux direct dans Snowflake.

✔ Avantages

  • Latence extrêmement faible
  • Pas de fichiers compressés intermédiaires
  • Pipelines simplifiés
  • Serverless et auto‑scalable

✔ Deux architectures

1. Snowpipe Streaming – Architecture Hautes Performances

  • Utilise le snowpipe‑streaming SDK
  • Prix basé sur le débit (GB non compressé)
  • S'appuie sur un objet PIPE, contre lequel sont ouverts les "channels"
  • Ingestion via REST API
  • Validation de schéma côté serveur

2. Snowpipe Streaming – Architecture Classique

  • Utilise le snowflake-ingest SDK
  • Pas d'objet PIPE dédié (chaîne opératoire différente)
  • Fonctionne avec Java 8+ et nécessite JCE
  • Peut ingérer dans des tables standards et Iceberg
  • Gestion d'erreurs configurable :
    • CONTINUE
    • SKIP_BATCH
    • ABORT (défaut)

5. Snowpipe vs Snowpipe Streaming – Points clés pour examen

✔ Snowpipe (fichiers)

  • Fichiers dans un stage
  • Détection par notifications cloud
  • Latence en minutes
  • Appending only (pas d'UPSERT)
  • Nécessite CREATE PIPE

✔ Snowpipe Streaming (événements / lignes)

  • Données streamées directement (pas de stage fichier)
  • Ingestion quasi-immédiate
  • Utilise un PIPE (HP) ou un channel (classique)
  • Basé sur SDK (Java/Python)
