1. Qu'est‑ce qu'une Dynamic Table ?

Source : Documentation Snowflake sur les Dynamic Tables

✔ Définition

Une Dynamic Table est une table gérée automatiquement par Snowflake, alimentée par une requête SQL déclarative.

Elle :

  • se met à jour automatiquement selon un délai de fraîcheur (TARGET_LAG),
  • reflète les modifications des objets sources (tables, Iceberg, etc.) sans planification manuelle,
  • simplifie le pipeline ELT sans Streams ni Tasks.

✔ Fonctionnement

  • Lors de la création, la requête passée dans AS <query> définit le contenu de la Dynamic Table.
  • Snowflake détecte les changements dans les objets sources et applique un rafraîchissement automatique.
✔ Comparaison rapide :
  • Vs Vue : la Dynamic Table matérialise les données automatiquement.
  • Vs Materialized View : supporte des transformations complexes (JOIN, UNION…).

2. TARGET_LAG – Fraîcheur de données

Source : Snowflake Dynamic Tables overview

✔ Rôle

TARGET_LAG fixe l'écart maximal autorisé entre la Dynamic Table et les données sources.

Ex. : TARGET_LAG = '5 minutes' → la table a au plus 5 min de retard.

✔ Impact

  • Contrôle la fréquence de rafraîchissement.
  • Impacte le coût compute : plus la fréquence est élevée, plus l'usage est important.

3. Refresh : fonctionnement, modes et initialisation

Sources : Dynamic tables refresh

✔ Initialisation

Lors de la création d'une Dynamic Table :

  • INITIALIZE = ON_CREATE → rafraîchissement initial immédiat. (par défaut)
  • INITIALIZE = ON_SCHEDULE → initialisation selon le target lag.

✔ Modes de Refresh

Une Dynamic Table peut être rafraîchie selon différents modes :

  • INCREMENTAL : ne traite que les données modifiées (optimisé performance).
  • FULL : recalcul complet.
  • AUTO : Snowflake choisit automatiquement (recommandé en développement).

✔ Rafraîchissement manuel

Commande SQL :

ALTER DYNAMIC TABLE my_dynamic_table REFRESH;
⚠ À utiliser avec parcimonie : trop de refresh manuel peut perturber les rafraîchissements planifiés.

✔ Rafraîchissement via TASK

Pour un contrôle total :

CREATE TASK my_dt_refresh
    WAREHOUSE = my_wh
    SCHEDULE = 'USING CRON 0 0 * * * UTC'
AS ALTER DYNAMIC TABLE my_dynamic_table REFRESH;

4. Prérequis techniques & bonnes pratiques

Source : Create dynamic tables

✔ Change Tracking obligatoire

Pour qu'une Dynamic Table fonctionne en mode incrémental :

  • Le change tracking doit être activé sur toutes les tables sources,
  • Avec un Time Travel non nul,
  • Snowflake tente de l'activer automatiquement (sauf en FULL refresh mode).

✔ Objets sources supportés

  • Tables Snowflake
  • Tables Iceberg Snowflake-managed
  • Tables Iceberg externes

✔ Conseils d'architecture

  • Découper les Dynamic Tables complexes en plusieurs étapes.
  • Optimiser les requêtes pour tirer avantage du refresh incrémental.

5. Commandes SQL pour Dynamic Tables (CREATE / ALTER / DESCRIBE)

Source : CREATE DYNAMIC TABLE

✔ CREATE DYNAMIC TABLE

Exemple complet :

CREATE OR REPLACE DYNAMIC TABLE my_dt (
    col1 STRING,
    col2 NUMBER
)
TARGET_LAG = '20 minutes'
WAREHOUSE = my_wh
REFRESH_MODE = AUTO
INITIALIZE = ON_CREATE
AS
SELECT col1, col2 FROM staging_table;

Paramètres importants :

  • TARGET_LAG = '<interval>' | DOWNSTREAM
  • WAREHOUSE = <name>
  • REFRESH_MODE = AUTO | FULL | INCREMENTAL
  • INITIALIZE = ON_CREATE | ON_SCHEDULE
  • IMMUTABLE WHERE (<expr>) → empêcher la mise à jour de certaines lignes
  • CLUSTER BY (...)

✔ ALTER DYNAMIC TABLE

Source : ALTER DYNAMIC TABLE

Permet de modifier :

  • TARGET_LAG
  • WAREHOUSE
  • INITIALIZATION_WAREHOUSE
  • Politiques (masking, row access, tags…)
  • Commentaire
  • Suspension / reprise

Refresh manuel :

ALTER DYNAMIC TABLE my_dt REFRESH;

✔ DESCRIBE DYNAMIC TABLE

Source : DESC DYNAMIC TABLE

Utilisation :

DESC DYNAMIC TABLE my_dynamic_table;

Montre : Colonnes, Définitions, Métadonnées (exige privilège MONITOR).

6. Points clés à retenir pour l'examen SnowPro Core

🔹 Dynamic Tables = pipeline ELT déclaratif

→ Snowflake orchestre automatiquement.

🔹 TARGET_LAG contrôle la fraîcheur

→ Plus il est petit, plus la table se rafraîchit souvent (coût compute ↑).

🔹 Change tracking obligatoire en mode incrémental

→ Active automatiquement sauf en FULL refresh mode.

🔹 Trois modes de refresh : INCREMENTAL / FULL / AUTO

→ AUTO recommandé seulement en développement.

🔹 Rafraîchissement manuel possible mais à limiter

→ Risque de perturber le planificateur automatique.

🔹 Commandes essentielles :

  • CREATE DYNAMIC TABLE
  • ALTER DYNAMIC TABLE
  • DESCRIBE DYNAMIC TABLE
  • SHOW DYNAMIC TABLES
