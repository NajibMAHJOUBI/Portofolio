Snowflake Query Profile Performance

✅ 1. Accéder au Query Profile

Dans Snowsight, le Query Profile est accessible depuis :

  • Les résultats d'une requête exécutée dans un worksheet
  • La page Query History, en sélectionnant une requête
  • Les pages "Grouped Queries" ou "Individual Queries"

Il permet d'examiner en détail l'exécution d'une requête Snowflake, notamment les étapes, les scans, les agrégations, les transferts de données, et les performances associées.

✅ 2. Ce que montre le Query Profile

Le Query Profile permet :

  • D'explorer chaque étape d'une requête exécutée, à travers un graphe visuel de l'exécution (operators / nodes, liens de données).
  • D'obtenir des informations détaillées par étape :
    • Rows processed
    • Data scanned
    • Time spent
    • Pruning, filtering, join methods
    (détails présentés dans le profil visuel)
  • Comprendre le plan d'exécution réel produit par Snowflake : Snowflake génère automatiquement un plan d'exécution (DAG d'opérateurs), qui peut différer de l'ordre logique du SQL.
  • Diagnostiquer les problèmes de performance :
    • Étapes lentes
    • Surconsommation de compute
    • Goulots d'étranglement de tri, jointure ou agrégation

✅ 3. Pourquoi utiliser Query Profile

✔ Identifier les opérations lourdes

Le Query Profile permet de savoir quelle étape coûte le plus en temps ou en ressources.

✔ Comprendre pourquoi une requête ne renvoie pas les résultats attendus

Le plan peut révéler des filtres inattendus, un mauvais ordre de jointure ou un mauvais choix d'indexation logique.

✔ Identifier les raisons d'une exécution longue ou bloquée

Chaque node du plan montre où la requête passe le plus de temps.

✔ Aide au support / debugging

Le Query ID peut être partagé avec Snowflake Support pour faciliter le diagnostic.

✅ 4. Navigation dans le Query Profile

✔ Accès aux étapes ("nodes")

Les étapes du plan (table scan, join, aggregate, sort, etc.) sont affichées sous forme de graphe.

✔ Inspecter chaque étape

Un clic sur un node montre :

  • Le temps d'exécution
  • Les lignes lues / écrites
  • Les données scannées
  • Le volume retourné à l'étape suivante

✔ Parcours chronologique

Représentation visuelle du flow de données entre les étapes (links).

✅ 5. Accès et permissions nécessaires

  • ✔ Vous pouvez toujours voir vos propres requêtes — L'historique est accessible nativement pour vos exécutions.
  • ✔ Voir les requêtes d'autres utilisateurs dépend de votre rôle :
    • ACCOUNTADMIN : accès complet
    • Rôle avec privilège MONITOR ou OPERATE sur un warehouse → voir les requêtes des utilisateurs de ce warehouse
    • GOVERNANCE_VIEWER : accès aux grouped queries, mais pas aux individual queries

✅ 7. Ce qu'il faut retenir pour SnowPro Core

  • Le Query Profile est l'outil clé pour analyser les performances d'une requête.
  • Il montre les étapes de traitement (plan d'exécution), les métriques de performance, et les flux de données.
  • Il est disponible depuis Query History, Query Results, ou Query ID via l'URL.
  • Les permissions varient selon les rôles Snowflake.
  • Indispensable pour diagnostiquer lenteurs, surconsommation, ou erreurs dans un pipeline SQL.
