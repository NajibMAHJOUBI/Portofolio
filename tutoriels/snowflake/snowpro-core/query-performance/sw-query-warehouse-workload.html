Snowflake - Warehouse Load & Performance

Niveau Intermédiaire
Mis à jour: Février 2026 Durée: 20 min Difficulté: Intermédiaire
Snowflake Performance Cost Management

1. ACCOUNT_USAGE.WAREHOUSE_LOAD_HISTORY

La vue WAREHOUSE_LOAD_HISTORY permet d'analyser la charge d'un warehouse Snowflake au fil du temps. Elle est essentielle pour comprendre la concurrence, l'attente des requêtes et optimiser la taille / multi-cluster d'un warehouse.

✔ Ce qu'elle mesure

  • Le niveau de charge (load) d'un warehouse au cours du temps.
  • Le nombre de requêtes en exécution parallèles.
  • Le nombre de requêtes mises en file d'attente (queued).
  • Permet de repérer si un warehouse est sous-provisionné ou sur-provisionné.

✔ À quoi ça sert dans SnowPro Core

  • Comprendre pourquoi certaines requêtes sont en queue.
  • Identifier les périodes d'activité intense → ajuster la taille du warehouse ou activer le multi‑cluster.
  • Diagnostiquer les problèmes de latence liés à la concurrence.
✔ Lien direct avec Snowsight

Snowflake recommande l'usage des vues Account Usage pour analyser plus finement l'activité qu'en Snowsight, ce dernier permettant une visualisation mais pas une analyse SQL avancée.

2. ACCOUNT_USAGE.WAREHOUSE_METERING_HISTORY

La vue WAREHOUSE_METERING_HISTORY mesure la consommation de crédits d'un warehouse.

✔ Ce que fournit cette vue

  • La consommation totale de crédits par warehouse.
  • Ventilation des crédits par période (typiquement par heure).
  • Distinction entre consommation en mode compute actif, autoscaling ou warehouse suspendu.

✔ Comment elle complète QUERY_ATTRIBUTION_HISTORY

  • La vue QUERY_ATTRIBUTION_HISTORY attribue la consommation à chaque requête.
  • La vue WAREHOUSE_METERING_HISTORY, elle, donne la consommation globale du warehouse – y compris l'inactivité.

✔ À quoi ça sert en SnowPro

  • Contrôle des coûts Snowflake (facturation au compute).
  • Compréhension de l'impact d'un scaling automatique.
  • Vérification de la consommation liée à une charge anormale.

3. Exploring Query Performance (User Guide)

Source : Exploring execution times

Cette page explique comment diagnostiquer les performances de requêtes via Snowsight, les vues ACCOUNT_USAGE et le Query Profile.

3.1 Snowsight – Analyse graphique des performances

✔ Dans Snowsight, via Monitoring → Query History

  • Trier les requêtes par durée.
  • Filtrer par user, warehouse, status.

✔ Visualiser la charge d'un warehouse

  • Snowsight → Compute → Warehouses → onglet Activity
  • Vous y voyez : Charge du warehouse, Concurrency, Requêtes en queue

3.2 Query Profile – Analyse détaillée des étapes

(accès via Query History → query_id → Query Profile)

  • Visualiser les nœuds les plus coûteux ("Most Expensive Nodes").
  • Analyser le temps passé dans chaque catégorie (scan, filter, join…).

Snowflake fournit également une fonction SQL : GET_QUERY_OPERATOR_STATS() pour extraire les stats du Query Profile.

3.3 Analyse programmatique (SQL)

Snowflake recommande d'interroger les vues Account Usage pour créer vos propres tableaux de bord :

  • QUERY_HISTORY → analyse fine des temps d'exécution
  • WAREHOUSE_LOAD_HISTORY → analyse de la concurrence
  • WAREHOUSE_METERING_HISTORY → analyse des crédits
  • TASK_HISTORY → analyse des transformations (si applicable)
NB : Seuls les rôles ayant accès à la base SNOWFLAKE peuvent interroger ACCOUNT_USAGE.

4. Relations entre les trois vues dans un contexte performance

BesoinVueCe qu'elle apporte
Pourquoi mes requêtes sont lentes ? QUERY_HISTORY Durée + statut + bytes scanned
Pourquoi mes requêtes entrent en queue ? WAREHOUSE_LOAD_HISTORY Charge et saturation du warehouse
Pourquoi mes coûts explosent-ils ? WAREHOUSE_METERING_HISTORY Crédit consommé par warehouse
Quelles étapes d'une requête posent problème ? Query Profile Analyse des nodes coûteux
Comment le coût est attribué à une requête ? QUERY_ATTRIBUTION_HISTORY Crédit par requête, exclut idle time

5. Résumé

Warehouse Load

  • Indique si un warehouse est sous-dimensionné.
  • Les requêtes en queue = surcharge → augmenter taille ou activer multi-cluster.

Warehouse Metering

  • Permet de suivre les coûts compute.
  • Indique l'impact du scaling et de la consommation réelle vs idle.

Performance Analysis

  • Snowsight est idéal pour inspection visualisée.
  • ACCOUNT_USAGE est indispensable pour audit et analyse avancée.
  • Query Profile reste l'outil ultime pour diagnostiquer étape par étape.

Rétention des données

  • ACCOUNT_USAGE : 365 jours pour Query History.
