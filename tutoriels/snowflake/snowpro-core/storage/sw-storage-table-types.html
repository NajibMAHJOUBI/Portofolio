Table Types (Temp/Transient, External, Iceberg, Dynamic)

Ces quatre types de tables sont essentiels pour comprendre comment Snowflake gère le stockage, la persistance, l'intégration avec des data lakes et la mise à jour automatique des vues matérialisées modernes (Dynamic Tables).

1. Temporary Tables & Transient Tables

✔ Temporary Tables (TEMP)

  • Existent uniquement pour la durée de la session.
  • Automatiquement supprimées à la fin de la session.
  • Stockage dans Snowflake avec Time Travel = 0 jours (pas de Fail-safe).
  • Très utilisées pour transformations intermédiaires et processing temporaire.

✔ Transient Tables

  • Persistantes entre sessions, contrairement aux temporary.
  • Time Travel limité (0 ou 1 jour), et pas de Fail-safe.
  • Coût de stockage inférieur car sans fail-safe.
  • Utilisées pour staging longue durée ou tables intermédiaires non critiques.
Ce que l'examen SnowPro Core teste :
Type Durée Time Travel Fail-safe Usage
Temporary session 0 jour ❌ transformations temporaires
Transient persistant limité ❌ staging, tables non critiques

2. External Tables

✔ Définition

Une external table permet de requêter des données stockées hors de Snowflake, par exemple dans :

  • AWS S3
  • Azure Blob
  • Google Cloud Storage

Les données restent dans le data lake, Snowflake ne stocke que des métadonnées.

✔ Fonctionnement

  • Snowflake construit des metadata files pour décrire la structure.
  • Les données en elles-mêmes sont lues directement depuis le cloud storage.
  • Supporte les formats semi-structurés (JSON, Parquet, Avro, ORC…).

✔ Avantages

  • Aucun coût de stockage Snowflake pour les données.
  • Intégration naturelle avec les architectures data lakehouse.
  • Idéal pour data sharing ou ingestion progressive.
Limites
  • Pas de DML (INSERT/UPDATE/DELETE).
  • Latence dépendant du stockage cloud.

3. Iceberg Tables

✔ Définition

Snowflake permet de créer des Iceberg Tables : ce sont des tables compatibles Apache Iceberg, stockées dans des data lakes, mais consultables et manipulables depuis Snowflake comme des tables Snowflake.

✔ Caractéristiques

  • Basées sur le format Iceberg table (manifests, snapshots, metadata).
  • Les données restent dans le data lake, mais Snowflake lit/écrit via son moteur.
  • Peut fonctionner dans deux modes :
    • External Iceberg Tables : stockage dans votre data lake.
    • Managed Iceberg Tables : stockage géré par Snowflake.
  • Supporte les opérations DML (contrairement aux External Tables).

✔ Avantages

  • Interopérabilité totale avec l'écosystème Iceberg.
  • Time Travel via mécanisme Iceberg.
  • Performance optimisée par Snowflake pour les opérations analytiques.
  • Gouvernance centralisée.

4. Dynamic Tables (nouvelle génération de transformations)

✔ Définition

Une dynamic table est un objet Snowflake qui maintient automatiquement le résultat d'une requête SQL en fonction d'un target lag.

→ à mi‑chemin entre une materialized view et un pipeline ELT automatisé.

✔ Fonctionnement

Vous définissez une table dynamique avec :

CREATE DYNAMIC TABLE target
TARGET_LAG = '1 minute'
AS SELECT ...
  • Snowflake rafraîchit automatiquement la table pour qu'elle reflète les données sources avec un retard maximal (target lag).
  • Calcul géré par compute serverless.

✔ Avantages

  • Rafraîchissement automatique et incrémental.
  • Pas besoin de gérer des pipelines ETL/ELT externes.
  • Supporte transformations complexes, y compris multi‑tables.
  • Permet de créer des architectures ELT déclaratives.

✔ Cas d'usage

  • Tables dérivées constamment mises à jour.
  • Tables d'agrégations, cleansing, enrichissement.
  • Pipelines de transformation "low‑maintenance".

Résumé

TypeOù sont les données ?DML possible ?ParticularitésUsage typique

Points clés

  • Temporary = durée session ; Transient = persistant mais sans Fail-safe.
  • External tables = lecture de données dans un data lake, pas de DML.
  • Iceberg tables = tables compatibles Iceberg entièrement modifiables.
  • Dynamic tables = rafraîchissement automatique basé sur Target Lag.
  • Snowflake privilégie automatisation, immuabilité, micro‑partitions et metadata-driven optimization.
