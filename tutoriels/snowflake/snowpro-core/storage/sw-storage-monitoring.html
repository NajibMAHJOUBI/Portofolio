🧊 Data Storage, Monitoring & CDP Costs

Ces notions sont essentielles pour la certification SnowPro Core, car elles touchent aux coûts de stockage, à la compréhension des mécanismes Time Travel / Fail-safe, ainsi qu'aux outils de suivi dans Snowsight et via les vues ACCOUNT_USAGE.

✅ 1. Monitoring Data Storage (Surveillance du stockage)

La documentation décrit plusieurs niveaux de visibilité : [docs.snowflake.com]

🔹 1.1. Monitoring au niveau Account (ACCOUNTADMIN)

Dans Snowsight :

  • Admin → Cost management → Consumption
  • Affiche :
    • le total du stockage moyen pour l'account,
    • le stockage des bases de données,
    • des stages,
    • du Fail-safe. [docs.snowflake.com]
  • Permet d'obtenir une vue globale de l'empreinte de stockage.

🔹 1.2. Monitoring au niveau table

Méthodes possibles : [docs.snowflake.com]

  • Snowsight → Catalog → Database Explorer → Table
  • SHOW TABLES (SQL)
  • TABLE_STORAGE_METRICS (Information Schema / Account Usage)

TABLE_STORAGE_METRICS est la vue la plus détaillée :

  • ACTIVE_BYTES : données actives
  • TIME_TRAVEL_BYTES : données historiques (Time Travel)
  • FAILSAFE_BYTES : données en Fail-safe [docs.snowflake.com]

Elle distingue aussi :

  • owned storage
  • referenced storage (cas des clones)

🔹 1.3. Monitoring des fichiers en stage

Snowflake stocke les fichiers en stage pour l'ingestion. Leur stockage contribue aux coûts de stockage. [docs.snowflake.com]

✅ 2. Exploring Data Storage Cost (Comprendre et explorer les coûts)

La page dédiée permet de comprendre comment naviguer dans les coûts depuis Snowsight. [docs.snowflake.com]

🔹 2.1. Accès au tableau de bord Storage Cost

Snowsight :

  • Admin → Cost management → Consumption → Storage [docs.snowflake.com]
  • Filtrage possible :
    • par tag (attribution analytique des coûts)
    • par Type (Database / Fail-safe / Stage)
    • par Object (par base, schéma, table) [docs.snowflake.com]

🔹 2.2. Storage Types considérés dans la facturation

Le Total Storage Cost comprend :

  • fichiers en stage
  • stockage des tables (actif + Time Travel)
  • stockage Fail-safe [docs.snowflake.com]

🔹 2.3. Visualisation par table

Dans Snowsight, chaque table affiche :

  • → la taille active (Active Bytes) [docs.snowflake.com]
Attention :

Cette taille peut différer du stockage physique réel pour :

  • tables clonées
  • tables avec lignes supprimées

✅ 3. CDP Storage Costs (Time Travel & Fail-safe)

La documentation détaille les mécanismes de Continuous Data Protection (CDP), incluant Time Travel et Fail-safe. [docs.snowflake.com]

🔹 3.1. Ce qui génère des coûts

Seront facturés :

  • données actives,
  • données Time Travel,
  • Fail-safe,
  • clones qui référencent des données supprimées. [docs.snowflake.com]

Snowflake compresse automatiquement les données et applique la facturation sur la taille compressée. [docs.snowflake.com]

🔹 3.2. Time Travel & Fail-safe — Facturation

  • Facturation par jour pour chaque segment conservé. [docs.snowflake.com]
  • Snowflake ne stocke pas toute la table :
    • Snowflake minimise la quantité de stockage pour les données historiques en conservant seulement les informations nécessaires à restaurer les lignes modifiées. [docs.snowflake.com]
  • Les copies complètes ne sont créées que pour :
    • DROP TABLE,
    • TRUNCATE
      (→ coûte plus cher). [docs.snowflake.com]

🔹 3.3. Particularités pour les Temporary / Transient tables

  • Time Travel : 0 à 1 jour max
  • Fail-safe : aucun Fail-safe [docs.snowflake.com]
  • → Ces tables sont moins coûteuses.

🎯 4. Points clés à retenir pour SnowPro Core

✔ Monitoring

  • Utiliser TABLE_STORAGE_METRICS pour voir Active / Time Travel / Fail-safe. [docs.snowflake.com]
  • Snowsight → Cost Management → Consumption → Storage. [docs.snowflake.com]

✔ Cost categories

  • Storage = fichiers en stage + bases de données + Time Travel + Fail-safe. [docs.snowflake.com]

✔ CDP cost behavior

  • Tout ce qui transite par Time Travel et Fail-safe reste facturé jusqu'à sortie du Fail-safe. [docs.snowflake.com]
  • Micro-partitions supprimées via INSERT/COPY/SNOWPIPE contribuent immédiatement à TIME_TRAVEL_BYTES et FAILSAFE_BYTES. [docs.snowflake.com]

✔ Optimization insights

  • Clones n'augmentent pas le stockage tant qu'ils ne modifient pas les données.
  • Temporary & Transient tables = pas de Fail-safe → moins coûteux. [docs.snowflake.com]

🧠 Résumé final (super‑synthèse)

  • Snowflake facture tout stockage, qu'il soit actif, Time Travel ou Fail‑safe.
  • L'outil principal de suivi est TABLE_STORAGE_METRICS (granularité par micro-partition).
  • Snowsight permet d'explorer, filtrer, analyser et attribuer les coûts (tags).
  • CDP augmente le stockage : comprendre ses implications est crucial.
  • Temporary/Transient tables réduisent fortement les coûts CDP.
