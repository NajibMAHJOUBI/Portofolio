🧊 Views, Materialized Views & Secure Views

Les vues sont un thème central dans SnowPro Core, car elles sont utilisées pour la sécurité, la performance et l'organisation logique des données.

✅ 1. What is a View ? (Vue non matérialisée)

Selon la documentation :

Une vue permet d'accéder au résultat d'une requête comme s'il s'agissait d'une table. [docs.snowflake.com]

✔ Caractéristiques essentielles

  • Une vue est une définition SQL nommée, créée avec CREATE VIEW.
  • Elle ne stocke pas de données : les résultats sont recalculés à chaque exécution. [docs.snowflake.com]
  • Peut être utilisée partout où une table peut l'être (JOIN, sous‑requêtes...). [docs.snowflake.com]
  • Utilités :
    • masquer des colonnes sensibles ;
    • simplifier l'accès à des tables complexes ;
    • fournir une vision logique adaptée à différents rôles.

✔ Types de vues dans Snowflake

Snowflake distingue :

  • Views (non matérialisées) : calculées à la demande.
  • Materialized Views : stockent physiquement les résultats. [docs.snowflake.com]

✅ 2. Materialized Views (Vues matérialisées)

Selon la documentation :

Une materialized view est un jeu de données pré‑calculé, stocké pour une utilisation ultérieure. [docs.snowflake.com]

✔ Fonctionnement

  • Les résultats de la requête sont stockés physiquement.
  • Les requêtes sont beaucoup plus rapides, car Snowflake lit directement les données matérialisées. [docs.snowflake.com]

✔ Avantages

  • Boost massif des performances pour requêtes répétitives ou complexes.
    Exemples : agrégations lourdes, analyse de semi‑structuré, requêtes fréquentes. [docs.snowflake.com]
  • Maintenance automatique :
    • Un service en arrière‑plan met à jour la materialized view après les changements dans la table source. [docs.snowflake.com]
Limitations (SnowPro Core aime tester ces points)
  • Consomme du compute pour la maintenance. [docs.snowflake.com]
  • Consomme du stockage.
  • Doit être basée sur une seule table (pas de JOIN), avec restrictions supplémentaires sur la requête.

✔ Idéal pour :

  • Tables stables, peu modifiées.
  • Résultats petits en volume par rapport à la table source.
  • Workloads fortement répétitifs.

✅ 3. Secure Views (Vues sécurisées)

Selon la documentation :

Les secure views empêchent toute exposition indirecte des données sous‑jacentes et masquent la définition de la vue. [docs.snowflake.com]

✔ Pourquoi les utiliser ?

  • Les vues non sécurisées peuvent parfois permettre d'inférer des données sensibles via des optimisations internes ou des comportements d'erreur. [docs.snowflake.com]
  • Les secure views désactivent ces optimisations afin d'empêcher :
    • accès indirect aux données source,
    • déduction par l'utilisateur (ex : division‑by‑zero trick),
    • exposition de la définition SQL de la vue. [docs.snowflake.com]

✔ Fonctionnement

  • Créées via : CREATE SECURE VIEW …
  • Le texte de la vue n'est visible que pour les rôles autorisés (propriétaires). [docs.snowflake.com]
  • Possible aussi avec des materialized views : CREATE SECURE MATERIALIZED VIEW …
Inconvénients
  • L'exécution peut être plus lente, car Snowflake ne peut pas appliquer certaines optimisations. [docs.snowflake.com]

✔ Scénarios typiques

  • Masquer des colonnes sensibles (PII, données financières).
  • Fournir un accès sécurisé aux consumers dans un partage de données.
  • Appliquer du row‑level filtering sans exposer la logique.

🎯 5. Points clés à mémoriser pour SnowPro Core

  • Une vue = requête enregistrée, aucun stockage. [docs.snowflake.com]
  • Une materialized view = résultats pré‑calculés, consommant compute & storage. [docs.snowflake.com]
  • Snowflake maintient automatiquement les materialized views. [docs.snowflake.com]
  • Secure views = protection contre exposition indirecte des données et masquage du SQL. [docs.snowflake.com]
  • Secure views = utile pour sécurité, PII, data sharing.
  • Materialized Views ne supportent pas les JOIN (limitation importante).
  • Secure views désactivent certaines optimisations, donc performance < standard views.
