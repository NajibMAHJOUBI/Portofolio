Snowflake Clustering Micro-Partitions

🧊 Data Clustering, Clustering Keys & Automatic Reclustering

Ces trois concepts sont essentiels pour comprendre les mécanismes d'optimisation des performances dans Snowflake. Ils sont fréquemment abordés dans la certification SnowPro Core, car ils conditionnent l'efficacité du pruning des micro-partitions et les stratégies de conception de tables.

✅ 1. What is Data Clustering ?

La documentation explique que Snowflake organise physiquement les données en micro‑partitions, contenant des plages de valeurs pour chaque colonne.

Le clustering désigne la manière dont les valeurs d'un ou plusieurs attributs sont distribuées dans ces micro‑partitions.

✔ Objectif principal

Améliorer l'efficacité du micro‑partition pruning :

Snowflake utilise les métadonnées (min/max) des micro‑partitions pour ignorer celles qui ne contiennent pas les données pertinentes pour une requête.

✔ Clustering naturel

Sans clustering key, Snowflake utilise l'ordre d'insertion des données pour organiser les micro‑partitions.

→ On parle de natural clustering.

Pourquoi le clustering est important ?

Un bon clustering :

  • réduit le nombre de micro-partitions scannées,
  • accélère les requêtes filtrées,
  • réduit les coûts (moins de data scanned),
  • favorise une meilleure sélectivité.

✅ 2. Clustering Keys

Une clustering key permet d'optimiser explicitement l'organisation des données dans les micro‑partitions selon une ou plusieurs colonnes.

✔ Cas d'usage typiques

  • Très grandes tables multi‑To
  • Tables sur lesquelles les requêtes filtrent le plus souvent sur les mêmes colonnes
  • Tables dont les données ne sont plus naturellement triées (forts volumes de DML)

✔ Fonctionnement

Quand un clustering key est défini :

  • Snowflake organise les micro‑partitions de manière à regrouper les données ayant des valeurs proches selon la clé.
  • La clé peut être un ensemble de colonnes ou une expression.

✔ Avantages

  • Amélioration significative du pruning
  • Réduction des temps de requête
  • Amélioration de la performance pour les clauses WHERE, JOIN, GROUP BY, etc.
Inconvénients / Risques
  • Reclustering coûteux pour les tables avec beaucoup de DML
  • Beaucoup de petites micro‑partitions si clé inadaptée
  • Maintenance automatique potentiellement coûteuse

✅ 3. Automatic Reclustering

Snowflake propose un service serverless, facturé à part, qui réorganise automatiquement les micro‑partitions pour maintenir le clustering selon la clé définie.

La documentation précise :

Automatic reclustering is a Snowflake serverless feature that continuously maintains clustering of large tables.

✔ Quand intervient le reclustering ?

Lorsqu'un grand nombre de micro‑partitions devient sous‑optimisé, par exemple après :

  • INSERT/DELETE/UPDATE massifs
  • FLATTEN ou manipulation sur semi-structuré
  • ingestion désordonnée

✔ Rôle du reclustering

  • Reconstituer des micro‑partitions plus homogènes
  • Réduire le chevauchement des plages de valeurs
  • Améliorer le pruning futur
Points importants pour l'examen
  • C'est un processus automatique, facturé via credits serverless.
  • Il s'exécute en arrière-plan, sans immobiliser les tables.
  • Il dépend de la clustering key définie.
  • Le reclustering n'est pas nécessaire tant que : la table est petite, le taux de pruning reste bon, les requêtes restent rapides.

🎯 5. Points clés SnowPro Core à mémoriser

  • ✔ Micro-partition pruning est le moteur principal de performance → Clustering améliore directement le pruning.
  • ✔ Clustering keys à utiliser uniquement pour très grandes tables → Sinon, coût et maintenance superflus.
  • ✔ Le reclustering est serverless et facturé séparément → Consommation visible dans les crédits Snowflake.
  • ✔ Snowflake supporte les clés de clustering composées → Mais plus la clé est complexe, plus le reclustering peut être coûteux.
  • ✔ Clustering ≠ partitionnement statique → Clustering est automatique, granulaire et continu (avec reclustering).

🧠 Résumé final (10 secondes)

  • Le clustering organise les micro‑partitions pour optimiser le pruning.
  • Les clustering keys permettent d'orienter cette organisation.
  • Automatic reclustering maintient cette optimisation dans le temps.

➡ Résultat : moins de micro-partitions scannées, requêtes plus rapides, coûts réduits.
