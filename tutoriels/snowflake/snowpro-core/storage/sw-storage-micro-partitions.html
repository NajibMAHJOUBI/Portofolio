Snowflake Micro-Partitions Performance

Micro‑Partitions et leur Impact

Les micro‑partitions sont un concept fondamental de Snowflake. Elles influencent directement les performances des requêtes, la compression, le pruning, le clustering et les bonnes pratiques de design de tables.

1. Qu'est-ce que les Micro‑Partitions ?

✔ Caractéristiques essentielles

Taille :

Chaque micro‑partition contient 50 à 500 MB de données non compressées (stockage réel plus petit car compressé).

Structure colonne (columnar)

Les lignes du tableau sont réorganisées par colonne dans chaque micro‑partition.
➜ Permet de ne scanner que les colonnes utiles.

Création automatique

Pas besoin de définir des partitions manuellement.
Snowflake partitionne transparently selon l'ordre d'ingestion.

Métadonnées riches stockées par micro‑partition :

  • Plage de valeurs (min/max) par colonne
  • Nombre de valeurs distinctes
  • Autres statistiques (pour optimisation et query processing)

Nombre élevé

Un tableau peut contenir des millions de micro‑partitions.

Immuabilité

Une micro‑partition est immuable :
→ toute mise à jour crée de nouvelles micro‑partitions.

2. Avantages des Micro‑Partitions

✔ Automatisation complète

Contrairement au partitionnement statique traditionnel,
➜ pas de définition, pas de maintenance.

✔ Granularité fine (50–500 MB)

  • ➜ Permet un pruning très efficace
  • ➜ Réduit les lectures inutiles
  • ➜ Accélère fortement les requêtes filtrées.

✔ Métadonnées = moteur de performance

Snowflake utilise min/max par colonne → accélère la détection des partitions pertinentes.

✔ Prévention du skew

Les micro‑partitions peuvent chevaucher leurs plages de valeurs, ce qui limite le risque de partitions disproportionnées (problème courant des partitions statiques).
➜ meilleur équilibrage des opérations.

✔ Stockage colonne + compression

  • chaque colonne est stockée séparément
  • compression optimisée
    ➜ moins de données lues, meilleure performance.

3. Impact des Micro‑Partitions

La section Impact des Micro‑Partitions décrit comment elles influencent performance, pruning, clustering et coût.

✔ 1. Query Pruning (impact majeur)

Grâce aux métadonnées (ranges min/max), Snowflake peut ignorer complètement les micro‑partitions qui ne contiennent pas de données pertinentes.

  • ➜ réduction importante du volume scanné
  • ➜ impact direct sur la performance.

Exemple implicite :
Une requête filtrée sur WHERE date BETWEEN '2025-01-01' AND '2025-01-31' lit uniquement les micro‑partitions dont la plage de dates intersecte cet intervalle.

✔ 2. DML Efficiency (INSERT/DELETE/MERGE)

Comme les micro‑partitions sont immuables, les opérations DML créent de nouvelles micro‑partitions.

  • → Cela peut fragmenter physiquement les données.
  • → Le clustering automatique peut réorganiser les micro‑partitions.

✔ 3. Influence du chargement (Load Order Impact)

Snowflake note que les partitions sont créées selon l'ordre d'insertion.

  • ➜ Un chargement désordonné peut nuire au pruning.
  • ➜ Un chargement trié peut améliorer naturellement le clustering.

✔ 4. Foundation of Clustering

Le clustering (naturel ou avec clustering key) repose entièrement sur les micro‑partitions.

  • Sans clustering key → "natural clustering" basé sur l'ordre d'insertion.
  • Avec clustering key → Snowflake réorganise les micro‑partitions pour optimiser prune.
    ➜ Moins de partitions scannées, donc meilleures performances.

✔ 5. Scalability

De très grandes tables (multi‑To) restent performantes grâce à :

  • micro‑partitions petites, nombreuses, indépendantes
  • parallélisme du MPP Snowflake
  • métadonnées micro‑partitionnées pour les accès sélectifs

4. Points clés

ConceptÀ maîtriser absolument
Taille 50–500 MB non compressés par micro‑partition.
AutomatisationCréées automatiquement → pas de partitionnement manuel.
Métadonnéesmin/max, NDV, statistiques utilisées pour pruning.

ClusteringDépend directement de la distribution des données dans les micro‑partitions.

Résumé

Les micro‑partitions sont de petits blocs de stockage (50–500 MB), créés automatiquement, contenant des métadonnées détaillées permettant à Snowflake de pratiquer un pruning extrêmement efficace. Elles rendent les requêtes plus rapides, améliorent la compression, évitent le skew, et constituent le socle du clustering.
