Niveau Intermédiaire

Snowflake Data Sharing Shares

✅ 1. Principes généraux — Secure Data Sharing

Secure Data Sharing lets you share selected objects… with other Snowflake accounts.
No actual data is copied or transferred… all sharing uses Snowflake's services layer and metadata store.

✔ Caractéristiques clés :

  • Zero‑copy : pas de duplication physique, partage via pointeurs métadonnées.
  • Temps réel : les consommateurs voient les mises à jour immédiatement.
  • Lecture seule côté consumer : All shared database objects are read‑only.
  • Coûts :
    • Provider : paie le stockage.
    • Consumer : paie uniquement le compute pour requêter les données.
    Shared data does not take up any storage in a consumer account… only compute charges apply.

✅ 2. Qu'est‑ce qu'un Share ? (What Is a Share)

Shares are named Snowflake objects that encapsulate all information required to share a database.

✔ Un share contient :

  • Les objets à partager :
    • Tables
    • Views (regular, secure, materialized)
    • External tables
    • Iceberg tables
    • Dynamic tables
    • Functions (UDFs, secure et non‑secure)
    • Semantic views
    • Cortex Search services
    You can share the following Snowflake objects…
  • La liste des consommateurs autorisés (Snowflake accounts ou reader accounts).

✔ Comment fonctionne un share ?

  1. Le provider crée un SHARE et lui ajoute des objets.
  2. Il ajoute un ou plusieurs consumer accounts au SHARE.
  3. Le consumer crée une database en lecture seule depuis le SHARE. On the consumer side, a read‑only database is created from the share.
✔ Points importants SnowPro :
  • Un share ne contient pas de données : uniquement des références.
  • Un share ne peut provenir que d'un seul compte Snowflake.
  • Un share peut contenir des objets provenant de plusieurs bases du même compte provider. Provider can share data from multiple databases as long as these databases belong to the same account.

✅ 3. Rôles : Provider & Consumer

✔ Provider (fournisseur)

  • Crée le SHARE.
  • Ajoute objets + comptes cibles.
  • Contrôle totalement l'accès (RBAC + suppression d'accès).
  • Peut partager avec :
    • Comptes Snowflake
    • Reader accounts (pour consommateurs sans Snowflake)

✔ Consumer (consommateur)

  • Reçoit un share → crée une database consommée.
  • Peut consulter les données en lecture seule.
  • Peut rejoindre plusieurs providers.
Any full Snowflake account can both provide and consume imported data.

✅ 4. Options pour partager des données (Options for Sharing)

There are many ways to share data… including listings and direct shares.

✔ OPTION 1 — Listings (Snowflake Marketplace ou private listings)

Listings let you share data with people in any Snowflake region, across clouds.
  • Fonctionne cross‑cloud et cross‑region.
  • Fournit des métadonnées enrichies (titre, description, exemples d'usage).
  • Permet de :
    • Facturer l'accès
    • Publier publiquement
    • Voir les métriques d'usage consumers
    Optionally charge for data… offer publicly… get consumer usage metrics.
  • Types de listings : Public (Snowflake Marketplace) ou Private (partage ciblé).

✔ OPTION 2 — Direct Share

Use a direct share to share data with one or more accounts in the same Snowflake region.
  • Fonctionne uniquement dans la même région.
  • Pas cross‑cloud.
  • Pas de possibilité de monétiser.
  • Pas de métadonnées Marketplace.
  • Share → Consumer DB (lecture seule).
  • You don't need to copy or move data shared with a direct share.

✔ OPTION 3 — Reader Accounts

You can share with people who don't have Snowflake accounts by using Reader Accounts.
  • Utilisé lorsque le consumer n'a pas son propre compte Snowflake.
  • Le provider crée et gère le compte reader.
  • Le provider paie le compute utilisé par le reader.
  • Reader → accès lecture seule via une shared database.

✅ 6. Objets partageables

You can share… databases, tables, views, secure views, external tables, Iceberg tables, dynamic tables, UDFs, semantic views, Cortex search services, models…

✅ 7. Points clés SnowPro à connaître absolument

✔ Data Sharing = zero‑copy, pas de duplication.

✔ Les données partagées sont toujours en lecture seule côté consumer.

✔ Share = objet Snowflake contenant les références + permissions.

✔ Direct Share = même région, Listings = cross‑cloud / Marketplace.

✔ Reader Account = pour utilisateurs sans Snowflake, compute payé par provider.

✔ Provider contrôle totalement l'accès au share.

✔ Consumer crée une database depuis le share.
