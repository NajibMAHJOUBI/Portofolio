1. Définition et objectifs d'une Clean Room

Data clean rooms are configurable, isolated Snowflake environments where collaborators can import data, specify what queries can be run, and configure data protection settings such as differential privacy.

Elles permettent d'obtenir des insights tout en protégeant les données sous-jacentes.

✔ Points clés :

  • Environnement isolé, contrôlé par le provider.
  • Collaboration multi‑parties sans partage des données en clair.
  • Contrôle strict des analyses autorisées (templates).
  • Application automatique de techniques de protection :
    • Differential privacy
    • Colonnes joignables, projetables (définies par le provider).
  • Aucune fonctionnalité de monétisation.
    Clean rooms don't support monetization.

2. Accès et modèle de collaboration

Deux rôles principaux, similaires au modèle Provider/Consumer de Secure Sharing :

Provider

Creates a clean room, adds data, configures allowed analyses, and shares the clean room with consumers.

Consumer

Installs the clean room, adds datasets, and performs analyses including joining provider data with their own data.
Informations essentielles :
  • Accès uniquement sur invitation.
    Access is by invitation only.
  • Un compte peut être provider dans une clean room et consumer dans une autre.
  • Possibilité d'inclure des collaborateurs non-Snowflake via des "managed accounts".

3. Installation de l'environnement Clean Room

The environment is installed once per Snowflake account by someone with ACCOUNTADMIN privileges.

L'administrateur configure :

  • Quels utilisateurs peuvent créer et utiliser les clean rooms.
  • Quels comptes peuvent être invités à collaborer.
  • Quels jeux de données peuvent être importés dans les clean rooms.
  • Quels services tiers peuvent exporter les résultats.
À retenir pour l'examen :
  • L'installation se fait une seule fois par compte.
  • Nécessite ACCOUNTADMIN.
  • Sans installation préalable → aucun utilisateur ne peut utiliser la fonctionnalité.

4. Structure et configuration d'une Clean Room

Dans chaque clean room, le provider peut :

✔ Importer des datasets autorisés

Specify what data a clean room creator can import.

✔ Définir les règles de protection

  • Colonnes joignables
  • Colonnes projetables
  • Paramètres de confidentialité différentielle

✔ Définir les requêtes autorisées

La collaboration se fait via des analysis templates, préconfigurés par le provider.

The collaborator who is sharing their data can define what analyses are available to the others.

✔ Contrôler tout accès et usage

Les consumers ne peuvent pas exécuter de SQL libre sur les données brutes.

5. Fonctionnement analytique dans une clean room

All analyses are conducted within the secure environment; collaborators receive only aggregated results.

✔ Important :

  • Aucun accès aux données brutes.
  • Les résultats sont agrégés, soumis aux contraintes du provider.
  • Peut inclure du JOIN entre données provider et consumer.
    Consumer can join their own data with provider data.

✔ Facturation :

  • Provider : paie les processus internes nécessaires.
  • Consumer : paie pour le compute utilisé lors de ses analyses.
    Provider billed for background processes; consumer billed standard compute/data usage.

6. Portée et régionalisation

By default, you can share clean rooms only with accounts in the same web hosting region.

L'administrateur peut toutefois étendre le partage à d'autres régions Snowflake.

7. Interface utilisateur (UI) et API

Collaborators can use either the Clean Rooms UI (business-friendly) or the API (developer-focused).

✔ UI Clean Rooms

  • Accessible aux profils non techniques.
  • Exécution d'analyses basées sur des templates.

✔ API Clean Rooms

  • Permet l'automatisation et les intégrations.
  • Nécessite un rôle API spécifique (ex. SAMOOHA_APP_ROLE).
