Snowflake - Direct Share & Getting Started

Niveau Intermédiaire
Mis à jour: Février 2026 Durée: 20 min Difficulté: Intermédiaire
Snowflake Data Sharing Direct Share

✅ 1. Principes fondamentaux du Secure Data Sharing

Ce que dit la documentation officielle :
  • Snowflake permet le partage sans copie, entièrement basé sur la couche de services et le métastore : aucune donnée n'est physiquement copiée vers le compte consumer. [docs.snowflake.com]
  • Tous les objets partagés sont en lecture seule pour les consumers. [docs.snowflake.com]
  • Les consumers ne paient que pour leur compute, jamais pour le stockage associé aux données partagées. [docs.snowflake.com]

✅ 2. Direct Share — Fonctionnement et caractéristiques

Source : Snowflake Sharing Overview → section direct share [sql.info]

Un direct share permet de partager des données avec un ou plusieurs comptes dans la même région Snowflake. [sql.info]

⭐ Caractéristiques clés d'un Direct Share

  • Même région : pas de partage cross‑region ou cross‑cloud.
    Direct share = “one or more accounts in your region” [sql.info]
  • Zero-copy, identique aux autres types de sharing.
  • Pas de monétisation possible (contrairement aux listings Marketplace).
    Direct share → “Optionally charge? No / Public? No / Metrics? No” [sql.info]
  • Pas de metadata enrichie (contrairement aux listings Marketplace).
  • Processus simple : Provider crée un share → l'associe à des comptes Snowflake de la même région.

⭐ Quand utiliser un direct share ?

  • Collaboration interne dans une même région Snowflake.
  • Partage bilatéral simple, rapide et sans besoins cross‑région / marketplace.

✅ 3. Data Sharing – Getting Started (data-sharing-gs)

Source : [docs.snowflake.com]

3.1. Ajouter des objets à un share

La documentation explique que deux méthodes existent :

Option 1 — Accorder des database roles à un share

Segment the securable objects… by creating multiple database roles … grant each database role to the share. [docs.snowflake.com]

Permet une segmentation fine de l'accès côté consumer.

Option 2 — Accorder des privilèges directement au share

Grant privileges on specific objects directly to a share… allows including data from multiple databases in a share. [docs.snowflake.com]

Méthode classique via GRANT … TO SHARE.

3.2. Cas où utiliser chaque option

✔ Option 1 (Database Roles → Share)

Utile lorsque :

  • Vous voulez segmenter les droits dans un même share.
  • Le consumer doit gérer des permissions détaillées via les database roles partagés.
Limites : Impossible pour des objets provenant de plusieurs databases, car REFERENCE_USAGE n'est pas compatible avec les database roles.
You cannot use this option if sharing data from multiple databases. [docs.snowflake.com]

✔ Option 2 (GRANT direct)

Utile pour :

  • Partager des objets provenant de plusieurs databases d'un même compte.
  • Faire du sharing simple et direct.

3.3. Fonctionnement côté consumer

  • Après création d'une database à partir d'un share, les consumers peuvent accorder le privilège IMPORTED PRIVILEGES à des rôles locaux. [docs.snowflake.com]
  • Cela donne accès en lecture à tous les objets partagés.
  • Sans database roles, ce modèle est tout ou rien pour un share unique.
    This all-or-nothing approach requires multiple shares to grant subsets of objects. [docs.snowflake.com]

✅ 4. Behavior important du partage Snowflake

  • ✔ Partage instantané
    Dès qu'un provider ajoute un consumer à un share, ce dernier y a accès immédiatement. [docs.snowflake.com]
  • ✔ Mises à jour visibles en temps réel
    New and modified rows are available immediately to consumers… [docs.snowflake.com]
  • ✔ Les objets recréés ne sont pas automatiquement re‑partagés
    A new object created or recreated … is not automatically available. [docs.snowflake.com]

✅ 5. Workflow SQL simplifié (provider → consumer)

Provider

CREATE SHARE my_share;

GRANT USAGE ON DATABASE mydb TO SHARE my_share;
GRANT USAGE ON SCHEMA mydb.public TO SHARE my_share;
GRANT SELECT ON TABLE mydb.public.sales TO SHARE my_share;

ALTER SHARE my_share ADD ACCOUNT = '<consumer_account>';

Consumer

CREATE DATABASE shared_sales
FROM SHARE provider_account.my_share;

Ensuite, consumer peut :

GRANT IMPORTED PRIVILEGES ON DATABASE shared_sales TO ROLE analyst;

✅ 6. Points clés SnowPro Core à retenir

🔹 Direct Share

  • Même région uniquement. ✔
  • Zero‑copy. ✔
  • Pas de cross‑cloud / cross‑region. ✔
  • Pas de monétisation ni de usage metrics. ✔

🔹 Data Sharing Getting Started

  • Deux méthodes : database roles OU GRANT direct.
  • Database roles = segmentation fine mais pas multi‑database.
  • GRANT direct = le plus flexible.
  • Consumer crée database depuis share + utilise IMPORTED PRIVILEGES.

🔹 Généralités

  • Tout est en lecture seule côté consumer.
  • Mises à jour visibles immédiatement.
  • Objets recréés → doivent être ré‑ajoutés au share.
